# 真实业务评测集使用说明

## 已建立的内容

版本：`bsagent-real-2026-11-01-v1`。从本机 Langfuse 的 269 条 `bs-agent.run` 根观察中筛选 50 条业务样本。排除探针执行段，合并重复问题的运行，保留财务取数、计算、反推、公告、Skill、开放式分析、工具失败和空结果等场景。这里的“真实”指真实业务执行记录，不代表每个问题都已被证实来自自然生产流量。

| Dataset | 数量 | 用途 |
| --- | ---: | --- |
| `bsagent-real-development-v1` | 48 | 定位问题、调整提示词与上下文、验证修复 |
| `bsagent-real-holdout-v1` | 2 | 独立会话的保留检查，不参与示例选择或提示词调整 |

近期样本绝大多数属于同一个会话。按会话和近似问题族连通分组后，只留下 2 条独立保留样本，没有为了凑 80/20 比例拆开同一会话。这 2 条不足以估计整体泛化能力；新独立会话需要继续补入。

## 样本字段与证据边界

- `input.question`：用户原问，不能用 Router 改写的 goal 替代。
- `input.as_of_utc`／`timezone`：原请求时间。评测“今天、最新、近一年”时依此解释，不能默默换成评测当日。
- `input.initial_context`：实际记录的 Router 输入与必要对话上下文。
- `input.synthesis_turns`：按真实父子关系识别的合成模型输入，保留多次合成时各次实际输入。没有凭提示词里出现“合成器”一词猜测调用归属。
- `input.tool_observations`：实际工具调用输入、输出与时间。HTTP 成功、工具成功、空结果、权限失败和业务完成须分别判断。
- `expected_output`：逐项验收标准，包含 `must_include`、`must_not` 和题设可独立复算的 `numeric_checks`。验收要点描述业务语义，不要求回答逐字复述；涉及取证和执行路径的条件，需要结合轨迹检查，不能要求出现在对外正文。
- `metadata.baseline_output`：历史回答，只供比较，**不能作为参考正确答案，也不能放入被测模型的输入**。
- `metadata.source_trace_id`／`source_observation_id`：原始根观察关联；Dataset item 也设置了对应原生来源关联。
- `metadata.review_status=agent_curated_pending_domain_review`、`human_reviewed=false`：本批由 AI 逐项整理需求标准，未冒充人工业务金标。外部财务事实没有从历史回答反向复制为精确真值。

6 项数值标准仅来自题设计算：季度营收环比、给定利润同比倍率推算、增速区间中值倍率、给定股数与价格的解禁市值、假设年化利润、给定相邻季度利润的环比。其余外部数值须对照实际来源或经业务复核后补充。

## 哪些样本可直接评什么

50 条均有原问、历史回答与独立整理的需求标准，可用于需求覆盖和行为验收。但只有 **26 条**保存了可直接用于固定输入合成回放的完整输入。

- 18 条的合成输入在历史内容采集时已被截断。
- 6 条没有可用的合成输入记录，其中包含直接回答路径，也包含合成调用存在但未记录输入的情况。
- 26 条 trace 的某些记录存在截断，这个数字与上述两类并非相加关系。部分工具记录被截断，但最终合成输入完整，仍可评估“回答是否忠于模型实际看到的材料”。

固定输入实验仅选择 `metadata.synthesis_replay_ready=true`。判断历史回答忠实度还应要求 `metadata.baseline_groundedness_ready=true`。其他样本必须跳过这类评分，不能把日志缺失记作模型错误，也不能凭标题和链接补想象中的证据。

`full_chain_replay_ready=false`：这些 trace 没有保存完整原始 checkpoint、所有执行绑定和工具契约。它们支持链路分析，不能声称已经支持确定性的全链路重放。重新执行真实工具属于另一个实验，必须区分数据源变化；不重放真实写操作。

## 数据位置与重复执行

业务快照、逐条标准、导入文件和完整性报告在已被 Git 忽略的 `data/evaluation/2026-11-01/`，不将原始业务正文批量提交到仓库。脚本使用现有 `.env.local` 读取凭证，不打印密钥，仅允许当前本机 Langfuse。

```bash
# 按 labels.json 引用的 trace 重新导出；含游标分页检查。
.venv/bin/python scripts/real_eval_dataset.py fetch

# 离线构建，检查来源、标准、内容摘要与会话／问题族分组。
.venv/bin/python scripts/real_eval_dataset.py build

# 幂等导入，并回读核对每项输入、标准、元数据和来源关联。
.venv/bin/python scripts/real_eval_dataset.py publish
```

稳定 ID 防止重复导入。远端同 ID 内容不同会停止，不能静默覆盖他人修改或人工标注；更新标准应发布新版本。回读只允许 JSON 浮点往返的末位误差，整数、布尔、字段、文本、列表顺序与来源关联严格检查。SHA-256 用于本地样本与快照完整性记录，不用浮点尾差伪造内容完全逐字一致的结论。

`labels.json` 是逐项整理后的选择与验收标准；`items.json` 是导入产物；`selection-audit.json` 记录全部候选的入选或排除理由；`review.md` 是逐项阅读清单；`build-report.json` 和 `publish-report.json` 记录实际结果。保留集内容只用于发布前验证，不能用来挑选 few-shot 示例。

## 后续评测方式

固定输入对照时，从符合条件样本选择最后一次合成输入，替换待测系统提示词，保留实际业务上下文。`expected_output` 交给评审器，不交给生成模型；`baseline_output` 不交给生成模型或充当 Judge 的标准答案。

分别记录需求满足、事实支持、推演正确、引用支持和表达质量。开放式分析不要求凑齐固定指标，不要求三方 MCP 数据普遍经过第二来源交叉验证。Skill 明确要求的业务字段与直接决定结论的关键输入，按各样本验收标准处理。

这一批未执行新的模型评审、未产生虚构质量分、未改动生产提示词。下一轮应先由业务人员核对高风险数值和少量正反例，再校准 Judge，随后运行新旧版本对照。
