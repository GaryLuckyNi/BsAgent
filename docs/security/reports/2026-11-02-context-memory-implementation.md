# 摘要与长期记忆凭证边界验收记录

日期：2026-11-02。范围：独立安全模块与摘要/长期记忆公共设施；业务 Agent 节点、外部 RAG 工程未修改。未提交、部署、迁移或批量删除历史记录。

## 发现与根因

隔离模型和内存 Store 中复现以下传播路径：摘要源消息/旧摘要原文直接进入首轮模型请求；无效模型输出在 repair 请求中原样回传；合法摘要 schema 中的嵌套 JSON 凭证漏过旧文本校验；显式偏好中的 Cookie/PEM/内联 JSON 可以进入候选，历史候选经审批后可以补写 Store，旧 Store 项也可以召回。它们不是新的用户身份凭证问题，而是内容在不同生命周期入口没有使用同一安全检查。

这些证据只证明本地实际函数调用及存储边界的行为，没有向真实模型发送样本，也不代表已发生生产泄露。

## 本批实现

- 新增 `security/context_content.py`，复用共享 `ToolContentPolicy` 凭证底线。生成有界安全副本，不修改原始消息；检查器故障与内容拒绝使用不同固定错误，异常链不携带原始凭证。
- 摘要的源消息、旧摘要和 repair 输入先保护再发送；已有私有推理/栈等受限输出在 JSON 解码后统一判断，不回传原文。超限、重复键或深层输出扣留，再按原契约最多修复一次。输出仍做严格 schema、凭证和 token 校验。
- 新摘要激活与历史 active 链读取都检查内容。已知不安全摘要进入既有失效/重建流程；检查器故障不会被误认为摘要损坏，也不会因此清空有效 active 指针。原始历史及摘要行保留。
- 显式偏好候选、候选持久化、后台 Store 补写与召回统一检查。审批不关闭凭证底线；旧不安全项不召回、不再补写，记录 `failed / memory_content_rejected` 并排除自动反复重试。修复内容并通过仓库正常更新后，既有机制会重置同步状态。检查器故障仍走可重试失败，正常 Store 恢复可补写。
- 共享底线补齐长裸 `sk-` 形式、已有 AWS access ID 形式，以及已有检测器能识别的 URL 编码凭证参数残留。无法精确清理的凭证字符串整字段隐藏。裸 `sk-` 至少 20 个后缀字符，避免把 SK-Hynix、SK-Innovation、sk-learn 等当作凭证；短凭证继续依靠字段/认证头/赋值等上下文识别，不声称裸字符串都能可靠分类。
- 内容策略语义版本升级为 `tool-content-v2`，摘要请求版本为 `context-summary-v2`。业务分类仍未定义，不把手机号、金额或公开公司名自动判为不可披露；无来源映射的历史文本也不盲目套用某个工具的业务字段规则。

本批没有新增记忆写入授权；已有审批和用户命名空间保持原契约，摘要或记忆文字不能改变宿主权限目录、任务权限上限或工具审批。

## 明确保留的下一步

1. 通用 LLM 输入、原生工具绑定、历史 checkpoint/TaskResult 重放及流式出口尚未统一接入；摘要失败后的原始历史降级路径也不能由本批局部保护推定安全。原有历史数据未完成全面清理。
2. 记忆/摘要中的业务来源分类、用途控制、任意编码/改写秘密、多轮指令洗白、真实模型误报/漏报与行为红队仍待验收。标记“不可信数据”不等于模型不会被诱导。
3. 后台记忆/压缩服务的完整服务身份、撤权时效及生产 PostgreSQL 并发/迁移继续以总 TODO 为准。
