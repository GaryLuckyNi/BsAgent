# 统一工具内容策略：业务脱敏与提示注入防护

2026-11-10补充：用户已批准普通正文改为增量检查后发布；新安全片段可实时持久化订阅，旧记录继续完整重放检查。当前行为、优化、测试和限制见[增量发布验收](reports/2026-11-10-security-stream-implementation.md)。下文全文缓冲/未封口暂缓描述为此前批次记录，不再代表新运行的全部正文行为。

日期：2026-11-02。状态：统一机制首批已实施并通过本地关联回归及独立复核；后续出口、业务规则和真实模型评估仍待验收。适用于所有工具的成功结果、失败结果与异常；RAG 只是一个测试样本。

## 1. 可以统一什么

统一的是安全模块、策略执行流程、公共接入点和审计契约；业务敏感性不能由通用引擎凭空推断。业务规则由受信配置/输出 schema 提供，Agent 与业务节点不直接依赖安全模块。

实施前，redact_sensitive_data 已支持凭证字段名及 writeOnly/x-sensitive schema 标记，但成功返回、失败归一化、观测出口及 ToolMessage 的 artifact/content 入口分散。首批已通过公共工具网关和消息组装接入同一策略，具体覆盖和限制见第 7 节；这仍不等于业务脱敏已完成。

## 2. 一个公共机制，两类独立策略

| 策略 | 目的 | 依赖 |
| --- | --- | --- |
| 通用秘密保护 | 防止凭证、私钥、认证头等进入不允许的出口 | 确定性字段/schema/文本规则；不声称识别全部未知秘密 |
| 业务数据策略 | 决定客户、个人、账户、订单、财务和内部资料允许如何展示/传输 | 业务分类、字段路径、工具/用途、租户/角色和接收方 |
| 内容信任与注入防护 | 防止外部资料被提升为系统指令、用户授权或执行权限 | 宿主来源与信任标记、角色隔离、风险信号、受信权限和数据出口控制 |

脱敏不能替代注入防护。恶意指令可以完全不含敏感数据；业务敏感数据也可能出现在正常任务里。不能用删关键词、统一星号或“包 JSON”宣称防住注入。

## 3. 统一内容策略契约

```text
输入：原始工具结果/异常 + 受信执行身份/任务 + 工具执行绑定 + 输出 schema
      + 接收方(model/user/trace/log/receipt/memory) + 用途 + 受信策略版本
输出：面向该接收方的内容视图 + allow/redact/withhold/deny + 命中规则/字段路径
      + 来源/信任级别 + 风险标记 + 最小审计摘要
```

业务规则通过字段路径和数据类别配置，例如“customer.phone → model 只保留后四位”。同一数据给授权用户界面、外部模型、普通日志的规则可以不同。不存在业务规则时，只能说明通用保护已覆盖，不能推定该数据已完成业务脱敏或允许外发。

工具返回自报 role、trusted、permission、policy_override 等字段不能改变宿主策略。工具提供的敏感注解可以进一步收紧保护，不能授予披露权限。

优先使用结构化 schema/字段策略，保留正常业务事实与类型。文本中的实体识别可辅助判断风险，不替代业务规则；低置信度必须明确记录，不能悄悄删除全部有效内容或自动放行受限数据。

## 4. 公共接入位置

1. ToolExecutionGateway 接收工具结果/异常后统一处理，覆盖 local、MCP、RAG、搜索等执行绑定；先确认原始执行与返回契约，生成分出口视图。
2. 公共工具消息组装与模型调用适配层统一携带来源和“不可信资料”属性；正文、error、details、artifact 都不能绕过处理。不得把外部内容提升为 System/Human 指令。
3. 日志、Trace、checkpoint、回执、记忆与压缩入口使用同一策略语义，各自选择合适视图；原始内容不默认另存一份形成旁路。
4. 工具派发和数据外发前继续执行当前权限、任务上限、审批/参数指纹与用途规则。不能只依赖模型识别注入。

脱敏视图不能改写“工具是否已经执行”、真实副作用状态或审批参数指纹。回执需保留受控的必要对账字段与摘要；若确有保留原文需求，另行定义受限存储、访问与保留期，不通过普通 trace 保存原文。

## 5. 注入防护的实际边界

外部证据可以影响事实判断，不能改变任务目标、角色、策略或授权。检测到伪造系统消息、提取秘密、修改权限、外传内容等风险时，按受信策略隔离/拒绝/复核，不能仅删除明显措辞后默认安全。

仅有工具权限也不充分：模型可能把内部资料塞进一个本来已允许的 web_search 参数。必须补数据类别与出口用途规则，并使用受信来源/任务信息限制后续外发。提示词约束和风险检测是辅助措施，不承诺消除所有模型诱导。

本契约只覆盖工具内容；用户输入、工具描述/文档、OCR、RAG 正文、记忆和压缩的其他入口需要逐项接入验收，不能由单一工具包装推定全量覆盖。

## 6. 验收要求与实施顺序

- 先明确首批业务数据类别、字段路径及各接收方允许规则；使用合成数据，不能要求用户提供真实个人/客户数据。
- 成功、失败、异常采用同组 canary 与注入样本；逐出口核对模型消息、用户响应、持久化和观测结果，正常业务数据对照保持有效。
- 覆盖 role/授权伪造、间接外传、嵌套结构、引用/编码、超长内容，以及处理后进入记忆/压缩/恢复的洗白路径。
- 分别报告敏感内容保护、注入风险识别、模型受诱导行为及实际受限操作是否发生。白盒规则测试不等于真实模型已防住注入。
- 现阶段先形成统一机制与业务规则契约，再替换分散出口；不继续把单个 RAG 错误正文的固定文案当作完整安全方案。


## 7. 首批实现与使用

独立内核位于 `backend/app/security/tool_content.py`，公共适配位于 `tool_content_adapter.py`、`ToolExecutionGateway` 和 `native_calls`。业务 Agent 节点无需增加安全调用。网关覆盖通过它执行的任意工具，不以 RAG 工具名作为内容处理条件；直接绕过网关的私有调用不因此自动受控。

已接入的内容范围：成功结果、归一化失败的 error/details、异常的固定安全信息、工具回执、网关结果观测、工具消息的正文与 artifact。先验证原始结果契约和 schema，再生成受限视图，避免掩码导致原始契约被误判。失败原始 payload 只保留类型诊断，不以 raw_result 另存原文。

当前运行时的 model/user/memory/receipt/trace/log 共用工作流结果，因此工作流采用所有这些出口规则的保守限制；任何一个出口要求隐藏的字段，在共享结果中都会隐藏。纯内核支持分别投影，但运行时尚不支持“模型看明文、Trace 隐藏明文”之类的独立视图。不能通过再次投影恢复已删除的值。已有历史 checkpoint、旧 TaskResult 字符串及其他应用日志仍需逐路径接入，不能推定已清理。

配置来自受信 Settings/环境，不接受普通工具、模型或请求正文覆写：

- `BS_AGENT_TOOL_CONTENT_RULES`：JSON 规则数组，默认 `[]`。规则包含稳定 ID、工具名模式、字段路径（支持 `*` 与数组索引）、出口、redact/mask/drop、可选租户范围和受信 scope 例外。凭证底线不会被 scope 例外关闭。
- `BS_AGENT_TOOL_CONTENT_INJECTION_ACTION`：2026-11-09起公共工具运行配置默认 `withhold`，扣留命中有限注入信号的内容；受信部署配置可以显式选择 `flag` 仅标记，普通请求或工具结果不能覆写。纯策略构造器默认仍为 `flag`，供模型凭证副本等不同用途的受信调用方使用；OCR与记忆/摘要入口显式选择 `withhold`。两者都不能证明模型不会受诱导，也不替代工具授权、审批和后续数据外发用途约束。现有部署若显式设置为`flag`，需调整配置才能采用扣留行为。

下面仅为合成手机号字段的配置示例，不代表生产业务分类：

```json
[{"rule_id":"customer-phone","tools":["crm.*"],"path":["customer","phone"],"sinks":["model","trace","receipt"],"action":"mask","keep_last":4}]
```

未配置业务规则时，普通客户名、手机号、金额等不会被自动识别为业务敏感数据；元数据 `business_rules_configured=false` 明示该状态。通用底线处理已知凭证字段/schema 标记、认证信息、Cookie、常见 PEM 私钥及正文中的嵌套/内联 JSON 凭证。JSON 字符串递归解码后清理；明确的 JSON 容器无法解析时替换该正文，不退回未经处理的原文。未知秘密、任意编码、自然语言个人信息等不属于完整覆盖承诺。

处理预算默认包括 20,000 个节点、32 层、单字符串 64,000 字符、总文本及 JSON 解码工作预算 1,000,000 字符；循环、非 JSON 对象、非有限数及超限结果扣留。规则配置无效在启动/工具派发前拒绝；执行之后处理故障只扣留内容，保留真实 status/execution_state，不能把成功写入伪装为未执行。同一已完成写调用的重试仍由原有副作用机制阻止。缓存搜索重用前按当前策略重新投影；历史明文存储清理仍待专项处理。

宿主附加策略版本、实际工具来源、执行绑定、不可信工具资料标记、处置与命中信息，不保留原始正文审计副本。工具自报 trusted/role/policy_override 不产生授权；消息保持 ToolMessage 角色。标记和模式检测只是辅助，数据被诱导塞入已允许的搜索参数、摘要洗白、OCR 及工具描述注入等仍列为 TODO。

本轮证据见 [首批验收记录](reports/2026-11-02-tool-content-implementation.md)：877 项关联测试通过，其中 64 项为统一内容策略专项；这不等于全量安全验收完成。

## 8. 第二批：工具外发前凭证拦截

用户已确认：目前没有业务数据分类，先完成通用凭证拦截并保留业务规则接口。本批按该范围实施，不默认将公司名、手机号、财务金额、全部 RAG 内容判定为不可外发。

“业务数据外发规则”表示某类数据允许交给哪个服务、用于什么目的。例如公开财报里的公司名可以用于联网搜索，内部未发布经营数据是否能发送给外部模型则需业务定义。当前接口只是受信工具/字段路径的拒绝能力，不是自动识别业务分类、追踪任意资料来源或用途授权的完整系统。

新增 `security/tool_outbound.py`：复用独立内容内核的凭证底线；若数据需要清理或无法在预算内检查，拒绝外发而非把参数改成星号后执行。已有认证头由适配器从受信配置注入，检查对象是业务 payload，不能以此禁止服务正常鉴权。

- `ToolCallRequest` 校验阻止已知凭证形成合法请求；公共网关再次检查原始参数、输入模型处理后的实际参数，以及受信工具契约声明的外发上下文。model_copy/construct 等绕过 DTO 校验不能绕过网关检查。
- 第一段检查位于网关观测及回执预留之前；可用性检查/回执预留后再次刷新权限，并以最新 scopes 和策略复核后才派发。授权例外在此期间撤销会拒绝，已预留回执结算为 denied/not_started。安全层不改写调用参数或审批指纹。
- `outbound_context_fields` 在注册快照中冻结，由受信工具适配器声明，不能由模型参数或工具返回降低检查。默认 Search API 只使用 original_question，旧搜索协议使用完整 research_context；按实际协议投影，避免因仅留在本地的研究目标误拒正常查询。未知搜索适配器保守声明完整上下文。
- 两个现有搜索客户端在最终 payload 观测/HTTP 外发前再做凭证检查；旧协议每个续轮同样检查，防止把服务端返回的凭证回传模型。首轮已执行、续轮被拦时不声称整次调用未执行，保留真实不确定状态。

业务接口为 `BS_AGENT_TOOL_OUTBOUND_RULES`，默认 `[]`。规则包含 rule_id、tools、path（支持 * 和数组索引）、可选 tenant_ids 和 except_scopes，命中字段即拒绝；额外字段、空路径、重复 ID 等配置错误拒绝启动。租户上下文缺失时保守应用相关规则；scope 例外只影响业务字段规则，不能关闭凭证底线。该配置只来自受管 Settings，不接受普通业务请求修改。

下面是字段拒绝接口示例，不是已启用的业务规则：

```json
[{"rule_id":"customer-phone-export","tools":["crm.export"],"path":["customer","phone"],"except_scopes":["customer:export"]}]
```

此例限制 crm.export 的 customer.phone 字段，不能识别复制进 web_search.query 的手机号，也不能防住任意编码或改写的业务资料外传。业务来源分类、用途控制、其他模型客户端实际输入、历史 checkpoint、旧请求对象及全局日志继续保留 TODO。绕过公共网关的任意私有工具调用不自动获得检查；搜索客户端的最终检查只证明这两个客户端的 payload 边界。

第二批本地证据见 [工具外发凭证验收记录](reports/2026-11-02-tool-outbound-implementation.md)：964 项关联测试通过，其中专项 32 项，独立复核通过；未部署。

## 9. 第三批：摘要与长期记忆

公共 `context_content` 适配复用同一凭证底线，接入摘要源/旧摘要/修复输入与输出、摘要激活和历史 active 验证、长期偏好候选/持久化/后台补写/召回。安全副本不改原文；已有审批不绕过凭证底线，检查器故障不视作内容损坏。受限后台候选保留固定失败原因，内容修复后按既有更新机制重新排队；故障失败仍可重试。

共享内容语义与摘要请求版本更新为 v2。编码后的已知 URL 凭证参数通过已有补充检测收紧处理，不能精确清理时隐藏整个字符串；裸 sk- 使用较长形状限制，普通公开公司名和技术词保持不变。该机制不声称识别任意未知秘密。

[本批验收记录](reports/2026-11-02-context-memory-implementation.md)：1167 项通过、6 项跳过，其中新专项 25 项。通用模型输入、历史 checkpoint/TaskResult、原始历史降级、来源/用途和真实多轮注入仍待逐项接入，不能由本批推定全覆盖。

## 10. 第四批：通用模型输入与旧历史副本

普通 factory 的能力分支/重试、当前 DeepSeek 公开 completion/同步异步流式/callback、原生工具绑定及 native_calls 已接入独立模型输入适配。旧历史、嵌套 TaskResult 和 ToolMessage 在进入这些入口时生成安全副本；不修改 checkpoint 控制字段、审批指纹或执行状态。角色与调用 ID 保留，需要改写身份时直接拒绝。

模板 schema 按契约检查，字段名不当作业务数据键替换；对象级 default/const/enum/examples 中的凭证也不能外发。模型整组预算包括协议字段、无效调用 error 和 artifact，不能拆成多条消息来重置总量。无来源的历史文本只执行凭证底线，不声称完整恢复业务分类。

共享内核改为在 JSON 解码后的叶子与非 JSON 片段上清理，保留有效语法与重复保护幂等性；内容语义升级 v3。证据见 [本批验收记录](reports/2026-11-02-model-input-implementation.md)：1311 项通过、6 项跳过，专项35项。输出流、错误正文、上游链路/全局日志及真实多轮注入继续待验收。

## 11. 第五批：模型结果与受管观测出口

按用户确认采用完整接收、检查后发布，正文/推理跨片段合并后检查。普通 completion、原生模型与已接入 SDK 输出回调都在发布前保护；逐 token/text/custom 输出回调禁用，结束回调接收完整安全副本。失败流不发布半段，重试前半段不混入最终答案；宿主阶段事件仍可继续，模型生成的目标、计划和答案延后。

统一固定模型传输错误，不携带响应正文及原异常链。受管日志先保护再截断，格式故障与写入故障不走原文 stderr 转储；Trace 内存/持久化和 OTLP/Langfuse 导出复用观测安全副本。OTLP 的 event/status/resource/scope/link/TraceState 也纳入检查，保留调用身份；Langfuse 无法 mask 的危险字段整 span 扣留，受管作用域以固定错误状态保留观测。

本批[证据与限制](reports/2026-11-03-model-output-implementation.md)：关联1695 passed、6 skipped，专项58项、独立复核92项（集合有重叠）。当前正常模型和工具参数、公开事实及原始对象保持；已知凭证执行参数拒绝而不改写后执行。业务类别仍未定义，独立 handler/exporter、metrics label、隐藏客户端、Vision/OCR、模型输出之后业务拼接、其他 provider 异常链及真实模型抗注入仍待验收，不等于全局数据出口与提示注入已完成。

## 12. 第六批：图片资产及 OCR/Vision 文本

图片公共边界复用共享凭证底线：客户端返回、协调器截断、持久化、旧行/缓存复制、API 和模型上下文均生成安全副本。原始 ORM 行及对象历史不被读取流程改写；缓存格式坏可重算，检查器故障不得用 fallback 绕过。上下文由宿主标记为不可信图片资料，不能产生用户授权。

图片资产默认只允许 owner 读取/删除，显式 `asset:read:any` 与 `asset:delete:any` 分别允许同租户对应操作，HTTP 与服务语义一致。后台任务在对象和 provider 调用前复核持久化绑定、有效期及当前 `asset:write`，不能从队列继承权限或跨用户换 analysis/session。

OCR 检查识别凭证或有限注入信号时，保留安全部分结果并跳过后续原像素 Vision 请求；本地 PrivateAttr 标记不接受 HTTP 覆写。OCR 本身此前已收到像素，未知秘密或未识别文字仍可能存在；租户允许时的原有 OCR 失败降级也仍可使用。这不构成所有图片外发前的数据分类或真实抗注入验收。

## 13. 第七批：公共正文、来源链接与浏览器

`security/public_output.py` 在公共适配点生成安全副本，覆盖引用链接插入、来源收集与补齐、最终回答、公开进度和会话历史 DTO。正文/元数据完整检查后截断；搜索摘要去除 HTML/Markdown、实体解码后再次检查。来源集合共用检查预算，超限扣留；来源编号、调用 ID、角色和真实执行状态保持。正文保护故障采用固定扣留文本，不能用展示失败改写已发生的副作用。

可点击来源只接受有效公开 HTTP(S) URL，拒绝 userinfo、已知凭证、控制字符、已知本地/私网数值地址及本地域名；不把敏感 URL 改成星号后继续使用。IDNA 后再去除尾点，覆盖 Unicode 点号；有限解码预算耗尽时拒绝。共享凭证内核语义由 v3 升至 **v4**，普通正文和工具出入站也拒绝 URL 查询/hash 中的 `auth/key/signature/cookie/passwd` 及已知参数赋值形式。仅 URL 上下文采用这些附加名字，普通业务 JSON 的 `key/auth` 不自动成为敏感字段；版本明确标识共享规则变化，旧缓存/摘要仍通过各自读取适配重新检查。

前端 URL 检查用于旧消息防御，服务端仍执行内容策略。Markdown 原始 HTML 不渲染，图片改为替代文字与安全地址的主动打开链接，favicon 改为本地 SVG；组件白名单不接受可触发其它网络请求的透传属性。真实隔离浏览器有本地请求记录器正向对照，网络和 DOM 证据见 [本批记录](reports/2026-11-04-public-output-implementation.md)。普通外链仍由用户主动打开；不证明目标服务的 DNS、重定向或业务数据用途安全。

两个搜索 provider 的 HTTP/超时/无效 JSON/过深 JSON 使用固定错误、保留状态和重试语义，在捕获块外抛出，原始请求、响应正文和异常链不随公共错误传播。历史数据库原文、旧持久化 SSE 任意跨帧重建、私有 handler/client、业务分类、整体网络预算和真实多轮注入继续 TODO。

## 14. 第八批：持久化协议与未封口历史

`security/protocol_replay.py` 在公共订阅出口复用共享凭证规则。正文按 `run_started` 阶段完整拼接检查，再按原片段长度分配安全文本，保留消息 ID 和 SSE 序号；恢复客户端会拼接不同消息 ID，所以 ID 变化不能切开检查上下文。中间 cursor 也从头读取检查前文，不把数据库里的旧安全标记当作当前策略证明。

生产者未退出时暂缓正文。正文之后的进度/来源可无 SSE id 预览，不能推进重连游标；封口后按原顺序正式发送，避免断线后跳过正文。前端只接受无序号 progress/answer_sources，忽略同类无序号正文/终态，保留正式事件去重语义。封口增加正文等待时间，任务进度仍可展示；取消/失败后的完整部分正文也经检查后重放。

活跃状态与历史列表从同一 SQL 快照读取完整正文、消息/运行状态和 producer_done，避免“旧部分正文＋新封口标志”竞争。搜索/会话查询排除未封口 assistant，会话 title/preview 完整检查后再截断。安全副本不更新原消息、事件或运行状态。

预检按200条读取，最多20,000事件和2,000,000正文字符；单字符串仍受公共规则上限约束。超限/格式坏/检查器故障扣留正文，正式终态不变；数据库故障不降级返回原文。这些是读取与检查预算，不是完整任务或网络字节预算。当前协议 [验收记录](reports/2026-11-04-protocol-replay-implementation.md) 不覆盖历史原文清理、所有自定义协议/隐藏客户端、持续权限撤销、未知业务秘密和真实部署。

## 15. 第九批：公共流的持续读取授权

`security/stream_authorization.py` 处理身份/资源边界，内容投影仍由前述模块负责。固定原请求主体、初始所需权限和资源绑定，在推进源之前及发布帧之前重新查当前目录与资源；目录/资源查询结束后再查期限，避免查询期间JWT到期仍输出正文。JWT模式的期限来自验签后的数值exp，经Principal和目录映射保留，不能从任务状态或业务payload重建。

持久化GET要求agent:read，POST首次/恢复/幂等输出要求agent:invoke，不能用无请求期限的后台委派主体替换。普通SSE、AG-UI新任务及审批恢复同样接入；后者在决策前及输出期间维护原run/requester资源约束和当前approval:decide，不扩大已有跨用户审批能力。

授权拒绝/到期/检查器故障采用固定无序号流错误，不生成持久化run_status，不以读取失败回滚结果或重跑工具。durable生产者独立运行；旧同步生成器仍遵循既有关闭收尾契约。前端GET和首次POST真实SDK均停止授权错误的自动恢复；SDK保留的name标记、HTTP分类和本地停止标志共同避免把硬拒绝当普通断线，新凭证与普通网络恢复有正常对照。

证据与限制见 [验收记录](reports/2026-11-06-stream-authorization-implementation.md)。此处检查目录当前授权及已验证期限，不替代企业IdP/JTI主动撤销通知、全任务/网络预算、独立安全决策审计、业务字段用途规则或真实部署验收。
