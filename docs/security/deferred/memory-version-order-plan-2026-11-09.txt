# 记忆意图与版本顺序实施计划

**目标：** 修复旧失败补偿覆盖较新偏好、以及新请求沿用旧候选终态的问题；迟到远端写入不能使受管读取回退。

**架构：** 新候选ID绑定受信request_id；相同请求/内容重试稳定，新请求独立审批。新增数据库递增的记忆版本记录及候选当前版本指针，保存主体、类型/键、候选ID和精确正文摘要、已通过本地审批/凭证检查的资格。审批状态改变不重排意图；非终态有效内容变更形成新版本。版本先后以数据库分配序号为准，不用各进程时钟或审批完成时间排序。

Store改用版本专属不可变键。同步时仅当前且未被更高合格版本取代的候选可写；即使旧远端put在连接/锁失效后迟到，也只写旧键。读取从可信DB挑选每键最新合格当前版本，按该版本键get，核对namespace、key、完整值及摘要，外部等待后再复核版本；错误/缺失不退回旧版本。不能只依赖SQL锁包住远端put承诺跨系统顺序。

**技术栈：** SQLAlchemy、SQLite/PG递增主键、LangGraph BaseStore、现有安全执行绑定、临时数据库和HTTPX禁网测试。
