# 思考模式验证与研究过程展示

## 结论

DeepSeek 思考模式的响应包含两个独立字段：`reasoning_content` 是提供方原始推理，`content` 是最终回答。BsAgent 会完整解析二者，但产品界面只展示基于真实计划、工具活动和分析结果生成的“研究过程”，不会公开或持久化原始推理。

参考：[DeepSeek 思考模式文档](https://api-docs.deepseek.com/zh-cn/guides/thinking_mode)。

## 三条数据通道

1. **后端诊断通道**：`reasoning_content` 被累积到 `LlmCompletionResult.reasoning_content`，供客户端单元测试和后端问题定位使用。
2. **研究过程通道**：LangGraph 节点发布结构化 `progress` 事件，事件类型为 `status`、`goal`、`plan` 或 `activity`；旧 `summary` 仅保留读取兼容。
3. **最终答案通道**：只有 synthesizer 的 `content` 通过 `answer_delta` 流式发送到答案区。

服务端不会把 `reasoning_content` 转换为 `reasoning_delta` 或 `thinking_delta`。AG-UI 对旧 `thinking_delta` 的解析仍保留兼容，但新请求不会产生这类事件。

## 研究过程事件

- `status` 表示“正在理解问题”“正在制定研究计划”等当前状态，只更新折叠区标题。
- `goal` 随 Intent Router 实际生成的顶层 `goal` 字段增量显示，标记为进行中；完整校验后使用同一 ID 覆盖为已确定目标，不额外生成展示文案。
- `plan` 随 Planner 的 `tasks[].task_goal` 生成而更新编号列表，修订读取 `plan.tasks`；只投影公开目标，其他参数与控制字段不公开。草稿不参与执行，完整校验后的计划覆盖同一事件。Planner 输出协议不再包含 `public_summary`；旧检查点读取时忽略该字段，不修改持久计划及其恢复签名。规划完成不等于子任务已经完成。
- `activity` 表示真实的工具或 Skill 执行。开始和结束事件使用同一个 ID，前端原位更新为成功或失败；不从结果正文截取“研究发现”公开。独立 analysis agent 已从当前运行链路停用，保留历史事件读取兼容。
- 旧 `summary` 事件仍可从历史消息读取，新执行不再产生此类事件。

公开目标保留完整清洗后的文本，不再套用短活动标签的 200 字限制。结构化字段的展示按小批次更新，不公开工具或协议标识，不从工具结果或推理正文生成展示摘要，也不公开原始 JSON。

目标或计划生成失败时，同一 ID 的草稿被失败状态覆盖，避免把未通过校验的计划留作已完成内容。完整结果仍经过原有协议校验后才参与执行。

## 持久化

流式执行期间，API 收集 `goal`、`plan`、`activity`，并兼容旧 `summary`，按事件 ID 合并状态，最多保存 32 项。研究目标和计划不再二次按 500/3000 字截断，活动和旧摘要继续保留 500 字上限。完成后写入 assistant message 的 `metadata.research_process`，中断等待确认时也保存，恢复完成时沿用。前端加载历史消息时恢复该字段。已保存的旧截断文本不会凭空恢复，需要原始目标或计划才能补回。

本次优化减少 Planner 专门生成的展示字段，不减少必要分析或业务模型调用次数；结果截取原本也没有额外模型调用。性能收益应通过输出 token 与实测耗时评估，不能把字符量差异直接换算成提速比例。

原始 reasoning 不写入公开 SSE、AG-UI 自定义事件、TraceBuffer 或会话 metadata。

## 自动化验证

回归测试覆盖：

- reasoning 与 content 分包或同包时的解析；
- 流式 completion 对完整 reasoning 的后端聚合；
- 公共 handler 忽略 reasoning，只发送最终答案 token；
- 目标/任务字段直接展示、结果正文不公开、内部标识清洗及真实失败状态；
- 研究过程事件的稳定排序、原位更新和 metadata 恢复；
- 研究折叠区的用户控制、计时结束和最终答案独立渲染。

研究进展折叠入口显示“研究进展 · 思考用时 N 秒”，秒数四舍五入为整数，不显示小数。计时边界统一在后端公开事件发送层：首个非空 `custom.progress` 事件开始发出时启动，首个非空答案正文 `messages` 事件开始发出时停止。这里的“思考事件”指公开的研究进展，不是原始模型 reasoning。请求受理到首个研究进展之前的等待、正文开始后的输出、向前端传输和 React 更新不计入时长。

计时由后台生产者集中计算，不读取模型开始生成正文的内部时间。首个实际公开正文经过原有校验后，生产者把包含 `elapsed_ms` 的 `answer_started` 标记和正文写入同一协议日志事务；前端只展示这个测量值。后续正文、完成事件和重复标记不延长时间，断线重放使用已保存的同一值。恢复执行沿用本轮最早的公开研究进展记录，已经开始过正文的恢复不重新计时。

没有公开研究进展或没有可靠服务端计时标记时，不显示秒数，前端不再按提交时间、首段接收时间或组件挂载时长推算。最终消息 metadata 尚未保存此计时字段；历史消息没有可靠记录时只展示“研究进展”。该指标是研究过程的公开事件阶段耗时，不是模型的纯 thinking 时间。
