# 评审矛盾修复与校准复测

## 结果

原先“评语指出600万元合计错误、结构化评分却给通过”的问题已修复。对原v2记录单独发起的一次修复请求，返回需求、事实与推演失败，明确正确合计为650万元；没有修改待评答案或手工翻分。

同时补齐新评审流程中的自动修复：结构、逐字引文、评分／问题一致性共用“首次生成＋最多一次修复”的总预算。第二次仍无效则拒收，不计回答质量零分。有效首次结果不重试，历史矛盾修复另限一次请求。

最终v4在同一14条基础校准题上全部符合预设判据，其中12条首次成功、2条经过一次协议修复。原矛盾记录的单独修复也通过，`candidate_experiment_gate=true`。这是开发回归检查的通过，不是线上准确率或模型回答质量已经提升的证明。

v3已修复合计题，但又在“年化利润已算出、缺市值无法得到PE”的题目上，将需求覆盖判为完全通过。该结果保留，没有为分数重跑同一版。

因此另建v4，通用地把“如实解释为什么缺结果”和“已提供所求结果”分开。模型逐项返回 `requirement_checks`，引用原问及答案，并标记 `answered`、`missing` 或 `incorrect`。只要声明有核心结果缺失或错误，就不能同时给需求完全通过。缺口诚实性在事实、推理维度单独判断，不因缺数据机械扣事实或推理分。

这不是针对某家公司或财务值补规则。两个新版本的题目、待评答案和预设判据不变，改动限于评审协议与完成状态表达。v4针对已知校准缺陷开发，所以这14题已是开发回归集；不能把其表现当作盲测泛化改善。

## 修复机制

离线 `judge_one` 增加可选校验钩子。JSON及逐字引文校验后执行一致性校验；若失败，将校验信息与上次输出作为 `protocol_repair` 数据提交一次。实际问题、材料和待评答案保持原样；不传校准题的预期评分或正确答案。

模型自行返回整个修复后的评审JSON，代码只验证，不代替模型改分。原始失败输出、修复输出、错误码／错误类型、次数、用量及来源关联均保留。历史修复传入的是已验证评审的快照，明确标记不是最初原始响应文本；不会伪造不存在的原始日志。

`requirement_checks` 的问题引文须在原问中，答案引文须在待评答案中；完全遗漏允许空答案引文。没有检查数组或检查与评分冲突会触发同一预算内的修复。代码能够检查模型已列出的状态与评分一致，**不能独立证明模型已列全所有子问、或语义判断完全正确**，仍需真实样本复核。

v3与v4中，合计题和成本敏感性题均在一次自动修复后得到一致的错误判定。v4的PE题首次正确标为需求部分完成，其余事实与推理维度通过，未将必要缺口误判为虚构。
