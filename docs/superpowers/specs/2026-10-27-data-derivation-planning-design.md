# 数据推演按变量角色规划设计

## 目标与原因

用户指出，当前计划会先取得待求结果，再把它用于推算别的量，混淆“推演输入”和“直接核对结果”。此前只强调直接证据、goal 与缺口一致，未让 Planner 明确建立公式与变量角色。

本次按用户建议采用通用推演流程：待求量 → 公式或定义 → 必要输入 → 缺失输入取证 → 推演结果与直接披露值核对。不针对公司、年份、数值或某个财务公式设置分支。

## 分工

- Router 忠实保留用户要求的计算、反推和核验，不替 Planner 指定算法，也不把推演任务改成单纯查询。
- Planner 根据指标定义确定待求量、公式或关系、自变量及适用条件。已给定或已核实输入复用，只取缺失项。公式未知或不适用时先核实定义，不编造公式。
- 任务目标与完成条件保留简短公式、变量含义和取证用途，供执行器和合成器使用，不输出完整内部思维链，也不创建仅为思考公式的任务。
- 对允许真实数据取证的推演请求，取得或复用待求量的直接披露记录，用于核对推演结果。该值不是推演输入；不能先用它反推缺失输入，再称为独立核验。
- 同源资料可以作口径与算术核对，但不能宣称为独立来源的证明。目标值未披露时如实记录，不能假定其存在或无限增加搜索。
- 不固定任务数：一次调用可提供输入与核对值时合并；来源/输入范围不同才拆分，只有真实参数依赖才串行。候选只覆盖核对值时不能被用于主要输入取证。
- 简单算术仍由最终合成完成；有后续消费者的中间计算和固定 Skill 沿用既有规则。用户仅查询、纯假设计算、禁止外取、直接证据充分时不机械追加推演或核验。

## 实现范围

只调整 `intent/classifiers.py` 和 `graph/planning/planner.py` 的 prompt；Planner 首次规划与反馈共用推演规则。任务 schema、工具门禁、模型与 thinking 配置不变。此前工作区改动保留，不提交、推送或部署。

## 验证

先保存当前提示下的 Router → Planner 对照，再修改提示。原问题重复三次，并覆盖其他反推、正向计算、已给输入复用、纯条件计算与普通查询。

检查取得的到底是不是公式必要输入，直接结果是否只用于核对，公式和变量是否正确，任务候选能否覆盖整个取证目标。不以提及关键词或固定任务数代替完整计划阅读。实验只调用模型，不执行取证工具，不证明实际业务数据可得或最终答案已修复。
