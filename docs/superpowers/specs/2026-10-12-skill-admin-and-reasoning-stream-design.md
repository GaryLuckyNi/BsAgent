# Skill 管理与原始思考流展示设计

## 目标

本次变更包含三个相互独立但可共同验证的界面行为：

1. Summary tooltip 保持紧凑，只用于快速预览；
2. Skill 名称允许在编辑时修改，新增和重命名均在前后端拦截重名；
3. 对话页面按真实到达顺序展示模型的 `reasoning_content`、工具执行事件和最终回答，消除请求发出后的无反馈空档。

## Summary tooltip

表格单元格继续单行截断。tooltip 固定最大宽度约 `420px`，最多展示 6 行，超出部分以省略号截断，不在 tooltip 内滚动。用户需要查看或修改全文时进入编辑弹窗。

## Skill 重命名和重名校验

编辑弹窗中的 Name 输入框恢复可编辑。前端提交前对名称执行首尾空白清理，并用当前列表做一次精确重名预检：

- 新增时，目标名称已存在则阻止提交并提示；
- 编辑时，目标名称与当前记录不同且已存在则阻止提交并提示；
- 名称未变化时允许正常保存其他字段。

管理 API 的 `SkillUpdate` 增加可选 `name`。后端以 URL 中的旧名称定位记录，在同一事务内检查目标名称并更新主键；目标名称已存在时返回 HTTP 409。数据库唯一约束仍是最终防线，捕获并发写入产生的唯一键冲突后同样返回 409。前端统一显示后端错误信息，因此即使列表数据已经过期也能得到明确提示。

重命名成功后，响应返回新名称，列表重新加载。删除、启停和后续编辑均使用新名称。

## 原始 reasoning_content 流

### 事件来源

圆点文本只来自模型 API 返回的 `reasoning_content` 增量，不使用“正在规划”“正在分析”等系统文案伪造思考内容。后端收到 reasoning delta 后立即发送 `thinking_delta`，不再等待完整句号或整段结束；前端按相同事件 ID 原样追加 token。

面向当前回答的推理节点，包括意图理解、Planner、分析任务、Skill 结果整理和最终合成，均在模型支持时开启 thinking 并接入公开流。工作流编译、步骤验收和工具参数 JSON 等内部控制调用不进入思考时间线，避免把控制协议当成用户可读推理。模型未返回 `reasoning_content` 时不生成替代文本。

### 工具事件

工具调用状态继续使用独立的 `progress/activity` 事件。它们不属于 `reasoning_content`，在前端渲染为搜索、浏览、市场数据或一般工具活动卡片。时间线按事件到达顺序交错显示：

```text
reasoning_content 增量
→ 工具开始/完成事件
→ 后续 reasoning_content 增量
→ 最终回答 token
```

工具结果本身仍作为 `tool` 角色消息进入后续模型上下文，不直接伪装成模型思考文本。

### 首屏反馈和结束状态

发送问题后立即创建 assistant 消息并显示无文案的流式光标。第一个 reasoning token 或工具活动到达后，光标进入对应时间线；最终回答 token 到达后逐步填充 Markdown。这样不会重新引入“正在规划”占位文案，也不会让页面在首个网络 token 前看起来没有响应。

每次模型调用使用独立 reasoning 事件 ID，避免不同节点的原始文本被错误拼接。工具事件保持既有 group ID 聚合规则。流结束、取消或失败时关闭动画，并保留已经收到的 reasoning 和活动记录。

## 数据与兼容性

`reasoning_content` 仅作为当前 SSE/AG-UI 流的展示数据，不写入最终 assistant 正文。现有历史消息仍按已保存的研究过程恢复；没有 reasoning 的旧消息无需迁移。

Skill 重命名不增加别名表。已经冻结工作流快照的运行继续使用 checkpoint；尚未加载定义且仍引用旧名称的历史运行可能无法继续，应按现有失败路径结束。新请求只使用新名称。

## 验证

- tooltip 宽度和 6 行截断样式通过管理端生产构建验证；
- 新增重名、重命名重名、名称不变、重命名成功和并发唯一键冲突有管理 API 测试；
- 前端预检阻止重复请求，并能显示 HTTP 409 提示；
- `reasoning_content` 单 token、重复 token、空白和跨节点事件按原样、按顺序累加；
- reasoning、工具开始、工具完成、后续 reasoning 和 answer delta 的交错顺序有协议及前端测试；
- 首个 reasoning token 不等待标点，发送后立即存在流式光标；
- 无 reasoning 的模型仍可依靠工具活动和最终回答正常完成；
- 运行主前端测试与构建、管理后端测试与管理前端构建、相关后端流协议测试。
