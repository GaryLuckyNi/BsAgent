# Planner 工具调用草案优化设计

用户已确认试行本优化。本次在 `codex/planner-tool-call` 实施，从 `dev` 建立分支后快进接续本会话的搜索迁移与权限恢复修复，不修改 `dev`，不创建 worktree。

## 目标与范围

对于参数已明确、无前序依赖的普通工具任务，Planner 可以在原有一次规划输出中附带调用草案，Tool Agent 校验通过后省去工具选择模型调用。没有草案或草案不适用时保持现有流程。独立任务可各自携带一个草案，不要求整个计划只有一个任务。

第一版仅向 Planner 提供目录标为 `low` 的工具输入契约，不调整工具风险配置。MCP 默认风险为 `medium` 的工具不会自动获得该优化，不能仅凭名称宣称其只读或降低风险。Skill、analysis、依赖任务和需要补充实体识别的任务保持原流程。该优化不等于补齐缺失参数或预测工具返回值。

## 契约与数据流

1. 提取现有 native tool schema 的输入投影函数，Planner 和执行模型共用，继续隐藏服务器注入字段与凭证字段。
2. `PlanningToolCard` 新增可选 `input_schema`。仅低风险工具且完整契约在单项 4000 字符、总量 12000 字符预算内时披露；不截断 schema，不提供输出 schema。摘要仍沿用原预算。脱敏会改变契约时不披露该契约。
3. `SubTaskModel` 新增可选 `proposed_tool_call`，结构为 `{"candidate_ref": "tool:名称@版本", "arguments": {}}`，不允许模型指定调用 ID、租户、凭证或审批状态。旧计划缺省为 null。
4. Planner 提示只有已披露完整输入契约、参数可由已知信息确定的无依赖普通任务才填写草案。字段可省略；工具候选仍不是授权。
5. Tool Agent 先复用既有候选解析，包括当前目录、权限、任务兼容性和运行可用性校验。仅当草案引用属于任务候选、对应本请求快照且当前解析结果仍包含该版本工具、完整输入契约确已披露、风险仍为 low 时尝试使用。
6. 草案经过现有日期规范化、完整参数校验、内联凭证与服务器字段拒绝后，转成与原路径相同的 NativeToolSelection，并复用可信调用 ID、来源快照、Gateway、预算、审批和回执代码。任何草案拒绝都发生在派发之前，退回原模型选择流程，不执行草案后再兜底。
7. 在既有 discovery 事件记录草案是否采用或回退及固定原因，不记录草案参数。旧计划签名在新字段为空时排除该字段；已有任务快照继续通过模型默认值做语义比较，不重写历史数据。仅修改草案不能改 ID 重放已失败任务。

## 验证

使用真实工具检索、Planner、Tool Agent、Gateway 和图，仅模型输出与远端工具边界受控。比较同一输入和相同调用参数：原路径执行层 bind 调用一次，优化路径零次；专业工具执行和工具检索次数不增加。另验证多个独立任务、依赖任务回退、非法参数回退、未知或不匹配候选、风险与权限变化、凭证和注入字段、旧快照及签名、来源恢复和持久回执。真实模型延迟和总 token 收益需要实际 trace 观测，本次不伪造线上收益数字。
