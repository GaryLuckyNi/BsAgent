# 复用目标与任务的研究过程展示

用户已确认删除专门生成的 public_summary，以已有 goal、tasks[].task_goal 和执行状态展示研究过程。Planner 原摘要与任务在同一次模型调用生成，优化减少输出字段和 token，不承诺减少一次模型调用或未经测量的耗时。

## 方案

- Planner 首次规划、修订、schema 与节点保存不再要求或输出 public_summary。PlanModel 仅在读取旧 payload 时忽略该字段，保持其他未知字段严格校验，旧检查点无需迁移。
- Intent Router 完成后发布 kind=goal，直接使用已解析 goal；Planner 完成后发布 kind=plan，由现有 task_goal 本地组成编号列表，不新增模型生成的标题或摘要字段。
- Analysis 与 Skill 不再从结果正文截取“研究发现”，仅发布目标与真实执行状态；实际分析结果仍完整保留给下游及最终合成，不减少必要的中间分析任务。
- 保留工具活动、来源确认、失败原因及真实结果数量。目标和任务展示继续清洗工具及协议标识；计划完成仅表示规划完成，不表示任务已执行。
- 前端使用现有研究过程布局显示 goal、plan、activity；历史 summary 事件仍可读取。服务端持久化和前端恢复同步接受新事件，计划列表的文本上限覆盖最多 12 项，避免刷新后丢失后半计划。
- 数据推演仍先确定待求量、公式、必要输入及核对值，把关系保留在 task_goal/completion_criteria，不为 UI 摘要另开思考任务。

## 验证

覆盖新旧 PlanModel、首次和修订输出协议、目标与计划事件、分析/Skill 内容不公开、执行失败状态、长计划持久化、前端实时和历史展示。运行受影响测试、后端全量及前端构建；用离线样本记录字段与字符减少，不将其冒充真实端到端提速。
