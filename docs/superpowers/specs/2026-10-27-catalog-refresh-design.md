# Run 级工具目录一致性与工具错误恢复

用户最终确认：一个 run 内固定同一份注册表和检索索引快照，不做节点级刷新。客户端周期感知配置变化并发布新快照，后续 run 使用新目录。保留既有授权、审批、来源限制和修订预算，不新增补偿、回滚或治理审批。

ToolCatalogRuntime 在 run 初始化时绑定配套快照，Interrupt 恢复仍取得同一份绑定，不能因全局目录更新而重新绑定。run 结束释放引用。提供显式刷新触发口，复用既有后台发现与原子发布；当前短连接 MCP 适配器不新增长连接通知订阅。

调用前在最新已感知目录检查对应工具是否仍可用、契约和执行绑定是否仍匹配；执行使用 run 已捕获的注册项。无关工具新增不使当前调用失效。工具移除返回 tool_not_found，目标工具契约或绑定改变返回 tool_catalog_changed，均标记 not_started，不发出远端调用。已经发出的调用不做事后目录比对，其结果按原绑定记录。

目录错误进入现有工具结果与任务结果，供模型选择后续行动。普通输入及审批恢复继续先验证身份和原确认载荷。若运行快照因进程重启等原因已不可取且当前目录不匹配，不静默换用新契约，向模型呈现未执行错误并收尾；不把目录变化作为 API Conflict 卡住会话。跨进程保留旧执行器不属于此次范围。

验收包括：同一 run 刷新前后快照不变、新 run 看到新目录；调用前移除或修改不派发、无关变更不误伤；调用途中刷新不丢结果；输入和审批恢复沿用原 run 快照；旧快照不可取时能形成模型可见失败并释放会话。所有节点继续共用建图时的固定快照。
