# Intent Router 保留目标依据与证据缺口设计

## 最新要求：goal 表达完整工作目标

用户进一步明确：goal 不是问句改写，应结合上下文交代必要取数、推导方向和交叉验证。下文最初方案中“不预先指定解法、数据字段”的约束由此更新：Router 可以说明完成请求必需的信息和处理要求，但仍不选工具、不输出任务图、不提前完成研判。

当前提示区分数值推演的必要输入、待求结果和直接核对值，并以不含公司、年份和数值的同比反推示范说明其关系。缺口仍嵌套于 available_information；范围限制优先，不给纯条件计算机械追加检索。最新有限验收见 `docs/acceptance/2026-10-27-contextual-goal.md`，以下保留早期方案及当时实验背景。

## 目标

按用户授权调整 intent router 提示，使 goal 保留所问声明、变化或版本实际采用的比较基础与口径；missing_input 表达尚未确认的直接依据，避免提前把研究目标改写成查询某个推定的历史字段。所有规则使用通用语义，不出现特定公司、年份、增长区间或工具。

## 依据

Planner 隔离实验中，三轮提示补充没有改变原案例；固定旧提示只改变 goal 后，三次均产生主要取证与历史核对任务。当前 Router `_FACT_GAP_ROUTING_PROMPT` 含“公司、期间、同比增速、净利润基数、核实金额”的个例示范，可能强化历史金额解法。该假设需 Router 到 Planner 的固定输入联合对照验证，不能直接视为已修复。

## 方案与边界

采用 prompt 修改，不新增顶层 schema。继续使用自由 JSON 的 available_information；允许其中 `missing_input` 作为明确标记的缺口元信息，禁止把未查到的值放到已有事实中。goal 与缺口必须一致。

1. goal 忠实保留目标对象、关系、主体、期间/版本与限制，不预先指定解法、数据字段或工具。
2. 追问具体声明或变化的实际参照、适用条件或计算依据时，将该对象实际采用的值、参照和关系作为必要缺口，不能由历史资料或类似对象自动替代。
3. 用户给出的声明可定位取证对象，不等于其未提供的参数与参照已有证明；只取回答本题所需内容，不全面审查声明真伪。
4. missing_input 与 goal 共同表达缺口，字段为自由 JSON 元信息，不承载已取得事实。历史资料仅在目标要求、口径不明或冲突需要时核对，不固定追加验证任务。
5. 明确的条件计算、仅问公式、限制外部取证或直接证据已充分时，维持原路由边界，避免过度核验。

只往 missing_input 增加内容而保留收窄的 goal 不足以满足目标，因此不采用；新增独立缺口分析模型会增加延迟，本次不采用。Planner、合成层和执行门禁均不改。

## 验证

使用原问题与合成的同类关系问题、基金基准、费率变化、条件计算、已充分材料、来源限制和范围外请求。调用生产 Router 与 Planner 入口，固定模型配置、候选和原始问题；不执行搜索、MCP 或业务 Run。原问题重复三次，同时检查 Router 缺口与最终计划，完整阅读响应，不以字段关键词出现代替取证覆盖。

通过相关 Router、规划、请求流程及图集成测试，运行 Ruff 和 diff 检查。保留此前未提交改动，不推送或部署；本次规划覆盖改善不等于最终合成误算已经解决。

## 用户补充与实验结论

用户指出原提示约束过于收窄。本次移除具体财务示例，保留通用目标、缺口与路由职责，候选变更未提交。真实实验对显式目标和已有历史实绩场景有改善，但原问题仍不稳定；主要取证和候选范围的端到端一致性未通过。详见 `docs/acceptance/2026-10-27-intent-evidence-gap.md`。
