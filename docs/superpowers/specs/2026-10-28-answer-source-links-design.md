# 回答中的文章引用跳转

## 目标与现状

用户要求 trace `e63644e40326c60cd3b2c2ab910d5ad8` 的回答中，内部 `source_` 引用可以点击跳转到 web_search 返回的文章。现有 `EvidenceProjection` 已按 URL 去重并提供稳定的 `source_id`、标题、URL 与摘要，前端 `MessageResponse` 已使用支持链接的 Streamdown；缺失的是从内部引用到公开链接的转换。

## 方案

采用来源表驱动的后端确定性转换。合成模型引用事实时输出 `source_1` 等已提供编号；输出阶段将编号转换成 Markdown 数字链接 `[1](<文章 URL>)`。同一来源复用同一编号，不把全部检索结果追加为参考文献。相比仅提示模型复制 URL，转换可以确保编号对应给定来源；相比新增引用元数据及面板，沿用 Markdown 能直接支持现有消息流、最终回答、复制及历史重载。

来源链接仅接受有效 HTTP/HTTPS 地址，转义 Markdown 目标中的特殊字符；未知编号或无效地址显示不可跳转的来源提示，不编造 URL。保留原有代码片段和已成型的 Markdown 链接，防止误替换其内部内容。内部编号只是出处关联，不代表事实已核实或证据充分。

## 流式与最终结果

复用现有段落流缓冲，在完整段落发送前转换引用，避免编号跨 token 时泄露或链接断裂。新决策协议与旧合成路径均使用相同转换；模型补证申请不转换、不公开。最终正文采用相同转换再进入现有 final_response 与消息持久化链路。链接在品牌文本过滤后生成，避免真实 URL 中的名称被替换。

前端使用 Streamdown 已有 URL 消毒与普通外链渲染，在新标签页打开并附带 noreferrer，不增加点击中转弹窗。

不新增模型调用、thinking、工具请求、引用面板或数据迁移。既有历史回答不回写；新回答保存可点击链接。不能仅凭引用编号判断资料足够回答目标。

## 验证

测试覆盖多来源与重复引用、转义下划线、未知编号、非法地址、带括号与参数的 URL、代码/已有链接保护，以及新旧路径的跨片段流式输出与最终正文一致性。使用原 trace 本地快照回放实际回答及来源映射，不重新调用模型或搜索。用真实前端 Markdown 组件验证链接目标及外部打开属性，并运行受影响的后端与前端回归。
