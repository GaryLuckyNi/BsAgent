# 通用 MCP 权限拒绝与回执结算修正

## 用户确认的行为

用户明确要求移除按接口名维护的只读白名单，并再次确认保留 interrupt，由用户选择后才执行联网搜索。当前修改是 dev 上的维护修复，不创建新 worktree。

## 分类规则

- 明确的 MCP 错误状态内的权限拒绝、结构化权限失败信封，以及未设置错误状态但独立返回的权限拒绝文本，统一为 `provider_permission_denied / denied`。
- 分类依据是返回结构与错误语义，不依赖服务器名、接口名、模型结论或只读接口名单。通用错误码及拒绝消息兼容规则集中在 `mcp_permission.py`。
- `denied` 表示本次调用被拒绝，沿用网关现有结算逻辑将回执存为 `settled`；不是将失败改为成功，也不是给上游账号授权。
- 普通业务对象、携带有效业务数据的响应不因出现权限文字而被误判。错误同时携带部分执行结果时仍视为执行不明，保留保护。
- 超时、未知异常、无法识别的无效响应仍不能冒充权限拒绝。所有原有工具风险等级保持不变。

## 交互与恢复

复用现有候选快照、scheduler 和 user_input_gate。只有失败调用当次实际候选包含 web_search，才提示是否使用联网搜索；全局注册或历史候选不能作为依据。

用户同意后只执行原候选中的搜索，不重新请求模型或重跑原 MCP；拒绝则使用已有资料并说明限制。恢复依旧校验当前权限、搜索绑定、预算与稳定 interaction/task/call 身份。搜索结果保留替代来源说明。

## 历史数据处理

用户在本次对话确认原 unknown 回执实际由 MCP 无权限导致。对该已完成运行的精确回执执行一次带行锁的人工结算，保留完整原失败摘要并追加 reconciliation 审计；不增加按工具名自动改写旧回执的运行时规则，不批量清除 unknown。

## 验证

- TDD 首轮复现 11 项失败，覆盖任意服务器/接口名和未标错误状态的拒绝。
- 实际 DynamicMcpHttpTool、执行网关及 durable 回执测试验证 rejected → denied → settled；未知写入、超时和无效输出测试仍保留 unknown。
- 实际 StateGraph/checkpoint 测试覆盖纯文本、JSON 和带错误状态的权限拒绝，确认之前不搜索、确认后搜索一次，原 MCP 与模型均不重复调用。
- 额外覆盖“部分执行结果＋权限错误”两项失败用例，确认仍不结算为前置拒绝。

本规格取代前版规格中按具体只读接口名单结算的约束，其余候选边界、人工选择、预算和权限约束继续生效。
