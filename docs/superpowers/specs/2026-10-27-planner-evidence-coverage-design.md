# Planner 目标直接证据覆盖设计

## 问题与范围

现有 Planner 强调最少任务、单次取证合并和复用入口信息，但未明确区分目标声明的直接证据与用于核对的相关资料。已观察计划只核实历史金额；它没有取得所问预告所采用的比较口径。历史数据真实不代表目标声明已经取得直接证据。

本次按用户要求尝试通用 prompt 优化。保留当前分支、任务协议、工具执行门禁与合成层代码，不增加模型调用阶段，不按公司、年份、财务公式或工具名写业务分支。

## 方案比较

1. 推荐：新增初次规划和反馈共用的证据覆盖规则。先检查回答目标所需的直接事实与关系，再按原颗粒度规则合并任务。改动范围小，可作固定输入对照。
2. 强制拆成“主要取证、交叉验证”两个任务：会造成无意义重复，且不符合单次调用能取得全部事实时应合并的约束，不采用。
3. 新增结构化证据角色和独立计划审核器：涉及协议和额外链路，本次不采用。

## 规划原则

- 结合用户原始请求理解 goal。入口已有信息与缺口是线索，不是已经核实的证明或穷尽的需求清单。
- 问题涉及某声明、版本或事件的具体结果、比较对象、适用口径时，取得能直接确认这些内容的材料；不能用背景资料或历史记录代替。
- 明确各输入在结论中的作用及对应的主体、时间、指标、版本、条件。核对资料仅验证对应事实，不能擅自改变被查对象。
- 用户明确给定假设并只要求计算或解释时，复用条件；现有材料足以回答时，不追加外部核验。交叉验证只在目标要求或关键冲突需要时安排。
- 把必要事实和关系写入任务目标及可核实的完成条件，再应用既有合并规则。允许一个调用覆盖主要证据和核对；只有不同来源、参数或真实依赖才拆任务。
- 候选仅支持核对资料时，仍保留主要取证目标，不能为了复用候选改写问题。只因取证先后偏好而无参数依赖时，不串行化。
- 反馈复用成果，仅修订仍阻断原目标的证据缺口；不创建独立的“检查计划完整性”任务。

## 验证与完成标准

使用生产 `LlmTaskPlanner.plan/review` 入口及同一配置模型做固定输入前后对照，不调用实际取证工具。原案例保留已有业务文本，缺少原候选全文时明确标注模拟卡片。其他场景使用合成材料，并保留旧颗粒度场景。

自动检查覆盖任务契约、直接取证目标、过度规划边界和负对照；完整计划需人工复核，不能仅靠关键词或任务数声称有效。原案例重复三次。还需验证条件分析、已取得直接证据、匹配 Skill、同调用多字段和不同对象查询等边界。

执行相关单元及图集成测试、Ruff 和 diff 检查。验收只支持规划行为改善，不证明工具必能查到所需材料，也不证明最终合成错误已经解决。

## 执行后的决策

本方案已实验，未通过原案例验收，未采用生产提示变更。输入层对照支持goal锚定影响，后续目标生成方案需独立设计与验证。
