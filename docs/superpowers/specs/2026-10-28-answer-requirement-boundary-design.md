# 回答要求与执行观察的边界

## 目标与依据

用户要求恢复耗时展示，并避免模型自拟验收条件导致答案反复列出无关数据缺口。采用现有调用与输出协议，不开启 thinking，不增加模型调用或新验收节点。

检查确认：普通 completion_criteria 由 planner 生成并交给模型理解，不是合成层代码逐字段硬验收。router 的 goal、planner 的任务条件与 unresolved_questions、内部 data_limitations 都可能传播模型额外扩展的要求。现有合成提示已有“只说明影响结论的限制”，但 planner 同时鼓励说明非关键缺口，REPLAN_PROMPT 又无条件以 goal 为判断目标。两个确定性兜底则直接公开全部限制清单。随后检查 trace df0dff78b8193725361d5ea122c8f8ba：搜索 query 包含北向资金，结果未覆盖该项；data_limitations 为空、三个任务均 success，原第六条缺口提示由模型生成，并非程序附加。不能将这一案例概括为所有回答的成因。

## 设计

- UI 保持“研究进展”标题，同时显示已有组件记录的秒数；没有真实 duration 的历史消息不编造时间。
- 根据实际问题、上下文与适用业务契约主动识别必要证据，不以用户逐项点名数据为前提。goal 是工作理解，普通取证的 completion_criteria 不自动成为固定业务契约。必要计算输入仍必须取得，不以缺少可选核对值否定已经成立的推导。
- 固定 Skill 的必需字段、冻结条件和 missing_policy 按业务契约执行；缺失按既有补证、失败或允许缺失后继续的策略处理，必要时澄清，不能擅自降低验收。没有新增通用自动澄清节点。
- 开放式研判在来源约束允许的范围内，以已有可靠信息形成与证据强度相符的倾向性或条件性结论。辅助指标未取得时可不采用，不逐项展示缺失；只有缺口真正阻断核心判断时才处理或说明。
- planner 的未解决问题只列仍影响用户请求的事项，不要求最终答案复述非关键缺口。合成与重规划使用相同边界，具体判断缺少的信息影响哪项用户所问结论；不得通过模糊表达掩盖核心目标未完成。
- 保留内部执行信息，不按关键词删除事实。自动生成的权限/预算文字描述执行路径，不宣告所有来源下的用户事实都缺失。
- 确定性兜底不能判断业务充分性，只呈现可核验的已有材料并明确尚未形成完整答复，不把内部任务清单直接列为业务数据缺口。
- 固定 Skill、授权、来源限制、真正关键缺口与数值校验继续生效。

## 验证

恢复耗时组件测试；模型输入保留原问、原材料与执行记录，提示来源边界一致；无模型/协议异常/数值异常兜底不复述内部可选任务且不声称完整完成；运行相关后端与前端测试。离线测试只验证实际数据流及确定性行为，不把 mock 响应当作模型理解效果。真实案例固定原始材料回放，并用必要输入缺失的计算问题作对照；固定 Skill 运行原有验收与缺失策略测试，不依赖模型口头声称遵守契约。
