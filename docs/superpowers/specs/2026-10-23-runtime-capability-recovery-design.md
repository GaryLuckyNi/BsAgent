# 运行时能力反馈与受控恢复架构设计

## 1. 确认记录与文档边界

- 日期：2026-10-23，Asia/Shanghai。
- 用户已确认采用“结果归一化＋运行时能力反馈＋确定性恢复”，保留现有 Agent 分工，不增加 Recovery Agent。
- 用户已单独确认：同一批并行任务的权限拒绝合并为一次 interrupt；授权只覆盖弹窗列出的任务，不自动扩展到后来新增或新失败的任务。
- 本文固化已确认的架构及首版边界，尚不是实现完成记录。本次不修改代码、接口权限、业务回执或运行状态，不重放外部工具。
- 首版只提供当前 Run 内的能力限制记录；跨请求、按账号隔离且可过期的记录属于后续增强，不混入首版。

本文替代此前权限方案中“仅依靠错误文案分类即可形成完整恢复机制”的设计假设；已有候选绑定、RBAC、用户确认和真实 unknown 保护继续保留。既有执行效率改动不在本次重写范围内。

## 2. 问题与目标

工具目录说明系统接入了哪些能力，不保证上游账号拥有所有接口权限。无法提前获知权限时，第一次真实业务请求可能被拒绝，这是正常运行结果，不应被包装成整个会话失控。

当前链路将部分权限拒绝归为普通远端执行失败；网关据风险等级写入 unknown，随后同会话其他 MCP 调用受阻，恢复节点又因没有权限错误码而不产生 interrupt。仅补某个接口名称或某句文案，不能解决职责耦合与复现困难。

本次目标：

1. 在保留分类依据的前提下区分明确拒绝、确定失败和执行不明。
2. 明确权限拒绝不产生错误的 unknown，不阻塞同批正常接口。
3. 利用本轮已经得到的限制反馈，避免重复尝试同一已知拒绝范围。
4. 用户确认后才执行已绑定的替代取证；恢复不重放原 MCP。
5. 保留研究目标和验收条件，不把搜索成功等同于证据充分。
6. 不因权限错误本身增加规划、恢复或验证模型调用。

不追求提前探测全部接口权限，也不承诺任意第三方纯文本错误都能被百分之百分类。

## 3. 方案取舍

| 方案 | 取舍 |
| --- | --- |
| 继续补错误文案 | 可用于补兼容性漏洞，但不能单独承担回执、能力记忆和授权恢复 |
| 结果归一化＋能力反馈＋确定性恢复 | 本次采用；复用执行网关和 Graph，不增加模型决策层 |
| 增加 Recovery Agent | 不采用；增加成本和不确定性，模型也不能证明副作用是否发生 |

## 4. 总体链路与职责

```text
Router → Planner（研究目标与验收条件）→ Tool Agent（选择工具）
                                            ↓
                                  Gateway / MCP Adapter
                                  归一化结果，先结算回执
                                            ↓
              ┌─────────────────────────────┼─────────────────────┐
              ↓                             ↓                     ↓
        明确权限拒绝                  成功或确定失败            执行不明
              ↓                             ↓                     ↓
        本轮能力限制记录                 任务观察              现有核实保护
              ↓
       RecoveryPolicy 生成待恢复事项
              ↓
       Scheduler 在本批收敛后封存确认批次
              ↓
       UserInputGate：一次 interrupt
              ↓ 用户确认
       替代执行器：仅执行已授权的 web_search
              ↓
       任务观察与缺口 → 已有 Planner 评审 → Synthesizer
```

| 模块 | 职责 | 不负责 |
| --- | --- | --- |
| 结果归一化 | 解释已收到的协议、错误及执行阶段，输出统一结果 | 决定研究结论或宣称未知副作用不存在 |
| 执行网关 | 权限、绑定、审批、预算、调用及回执落盘 | 因为需要兜底就回填成功 |
| 本轮能力记录 | 保存有范围的拒绝观察，供候选与执行前检查使用 | 变更账号权限或原始工具目录 |
| RecoveryPolicy | 依据契约产生等待确认、保留缺口等动作 | 调用模型猜测恢复方案 |
| Scheduler / UserInputGate | 合并确认事项、持久化等待并校验恢复身份 | 在恢复时重新执行原工具 |
| 证据评审 | 判断已有材料能回答什么、是否需要改变研究结构 | 将搜索声明当作独立事实验证 |

这些是职责边界，不要求新增等量 Graph 节点或独立服务。

## 5. 统一结果契约与回执

### 5.1 三种状态不能互相代替

- 调用与回执：一次请求是否派发、结果是否确定。
- 能力可用性：某个账号/连接在某个范围内被明确拒绝过。
- 证据覆盖：某个研究目标取得了哪些材料，仍缺什么。

`settled` 不等于调用成功；调用 `success` 不等于研究目标完整满足。能力记录也不等于新的授权。

### 5.2 最小契约

复用现有 `ToolCallResult` 和 `ToolCallRecord`，不再平行保存第二份完整结果。为结果增加明确的执行确定性信息：

| 字段 | 语义 |
| --- | --- |
| `status` | 沿用 success / failed / timeout / denied |
| `execution_state` | not_started / completed / uncertain；描述执行是否确定，不替代 status |
| `error.code` | 稳定的本地分类，不直接暴露远端异常正文 |
| `error.details` | 有界的分类依据：来源、规则 ID、上游错误码、阶段、是否存在部分结果、拒绝范围 |

`execution_state=completed` 表示请求执行情况已经明确，可能成功，也可能得到一个确定的失败或部分结果；不表示研究目标完成。`not_started` 只用于可以确认在业务执行前被拒绝/校验失败的情况。

新增字段须有兼容默认行为：缺失执行确定性的旧失败不能自动推断为未执行；中高风险未知结果沿用保守保护。不得按新契约批量重写旧回执。

### 5.3 分类顺序与安全边界

1. 校验 MCP 返回结构、协议错误与工具执行错误，识别是否包含正常或部分执行结果。
2. 优先使用适配器已知语义的结构化错误码及执行阶段。
3. 缺少结构化信息时，仅在明确错误上下文内进行受约束的文本兼容识别：没有正常/部分执行结果，拒绝语句是当前失败的主体而非引用说明，并且适配器能够确认该类返回代表执行前拒绝。不能扫描正常业务正文中的关键词来证明未执行；条件不足则保持不确定。
4. 混合结果、含糊消息、未知异常保持不确定；不让模型裁定副作用。

适配按数据源错误协议维护，不按每个 API 名称维护权限或只读白名单。未知错误码不能仅凭数值正负归为权限拒绝。鉴权失败、接口权限不足、限流、额度不足、参数错误分别保留分类；不是所有 denied 都能进入“账号无接口权限”流程。

已确认的事故证据是“权限路径未命中、远端错误被归为普通失败并形成新 unknown”；旧持久化摘要没有保留远端原文，不能把离线复现的某句文案当作该次调用的精确原文。实现验证应覆盖拒绝语义的不同包装和文案，并在取得授权的真实返回上核验，不以补一条猜测文案代替验收。

MCP `isError=true` 表示工具执行错误，不单独证明无权限或未执行；协议还允许结构化及非结构化结果。[MCP 工具规范](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)

### 5.4 回执结算

| 情况 | 回执及处理 |
| --- | --- |
| 已确认执行前权限拒绝 | settled，保留 denied 结果和依据，允许进入权限恢复 |
| 确定失败且无未决副作用 | settled，保留 failed 结果，按具体错误处理 |
| 成功/部分结果且执行情况明确 | settled，再评估证据覆盖 |
| 可能产生副作用且执行结果不明 | unknown，保留现有核实保护，不盲目重试 |

首版不修改工具风险配置，也不扩大现有低风险豁免。对中高风险工具，不能仅根据 status 名称结算；出现相互矛盾的执行信息时按不确定处理。超时不自动证明未执行，权限消息夹带部分执行结果也不自动证明整次调用被前置拒绝。

回执结果必须先持久化，再等待用户。派生能力记录写入失败不能把已确定的拒绝改成 unknown，更不能豁免原有安全检查；可从已落盘结果重建派生记录，不能因此重发外部调用。

## 6. 本轮能力限制记录

### 6.1 范围与依据

首版作用域为当前 `request_id`，随 checkpoint 保留，不跨请求复用。条目引用原始调用/回执，只保存匹配所需摘要，不复制整份结果。

匹配身份包括当前 Run、工具及版本、execution binding、账号/凭证修订（若可得）和拒绝范围。拿不到可靠的上游账号修订信息时，不声称能够安全跨请求缓存。

拒绝粒度规则：

- 默认仅匹配原工具及规范化参数指纹。
- 只有适配器明确取得工具级或权限范围级拒绝依据时，才能扩大匹配范围。
- 不按工具名猜测只读性或权限继承；一个工具受限不能推出整个服务器不可用。
- 不保存原始凭证，不把不同租户、连接或账号的结果混用。

### 6.2 使用位置

- 候选解析前读取限制，剔除匹配的已知不可用路径，同时保留跳过原因。
- 网关执行前再次检查，防止并行结果刚落盘而候选快照尚未更新。
- 未派发的跳过只记本地 `availability_skip` 事件，引用原观察；不伪造新的远端调用回执。
- 不修改 `ToolRegistry`、ToolSpec、目录摘要或已有审批参数快照。
- 固定 Skill 指定的工具不能因被过滤就换成其他工具。未声明替代能力的 Skill 保留失败/缺口，由用户或上层流程调整。

本记录不替代 RBAC、工具绑定和审批。并行任务在首次限制尚未落盘前仍可能同时请求；首版不引入分布式探测锁，也不承诺消除这种首次竞争。

## 7. 确定性恢复策略

RecoveryPolicy 读取统一结果、任务契约、原候选快照、能力记录及预算，输出动作，不调用模型。

可以进入权限替代确认，必须同时满足：

1. 属于已确认的上游权限拒绝，不是通用异常、限流或未决副作用。
2. 原调用回执已经完成安全结算。
3. 该任务尚未完成恢复，且真实候选快照包含 web_search。
4. 当前业务/Skill 契约允许替代来源。

不满足时保留明确原因，不从全局目录偷偷加入搜索。来源被用户或 Skill 明确限定时，不把搜索当作等价执行；需要改变约束属于新的授权或规划决策。

权限拒绝不原路自动重试。替代失败后不自动串联另一轮恢复；将材料和缺口交给已有评审。不能靠 Planner 换任务 ID 重置同一拒绝限制或本轮预算。

## 8. 批次确认与恢复协议

### 8.1 聚合与封存

并行 worker 只记录待恢复事项，不竞争写单值 `pending_user_input`。当前派发批次收敛后，由 scheduler 按稳定顺序生成不可变的确认批次。

批次保存：request/batch 身份与版本、列出的 task/call 引用、任务目标和验收条件快照、原候选及替代绑定、来源约束，以及这些内容的摘要指纹。首次封存后不向同一批次追加任务。

本轮新失败但不在已封存批次内的任务进入下一次确认；不得因为相似目标或相同数据源而复用授权。用户确认不允许自动修改已保存的任务或替代范围。

### 8.2 用户可见协议

保留两个选择：对列出的任务使用联网搜索，或仅使用已有资料并保留缺口。

每项显示有界的任务目标、原数据源、拒绝原因及替代来源限制。不展示凭证、工具参数或未经清理的远端错误。

现有 `UserInputRequest` 只有单个来源引用，question 上限500字符，不能用截断问题承载整批授权。首版需增加可选的结构化批次条目视图：

- 批次 interaction ID 对应服务端保存的完整快照；source 使用批次类型，不把某一个 task/call 冒充整个批次。
- 条目上限与当前最多12个活动任务保持一致；每项保留稳定引用和有界显示摘要。
- 前端必须展示全部被授权条目，不能隐去部分任务后仍授权全批。
- 非批次交互保持原协议；不支持批次显示的客户端不能静默使用不完整提示确认。

### 8.3 恢复校验

恢复校验租户、用户、request/checkpoint、interaction/batch版本及指纹、原调用与候选、替代工具版本/绑定、账号修订（若可得）、当前权限和预算。身份或绑定变化则不执行，要求重新确认或重新发起，不擅自放宽原有目录一致性保护。

等待节点只等待。用户确认后，只调度批次对应的替代调用，不再请求模型选择工具或生成原 MCP 参数。使用原任务目标、验收条件、标的/期间/时点构造有界搜索上下文，不透传原接口参数或错误正文。

LangGraph 恢复会重新运行 interrupt 所在节点，所以外部执行与等待必须分离，不能把“不重复调用”寄托在内存局部变量上。[LangGraph interrupt 文档](https://docs.langchain.com/oss/python/langgraph/interrupts)

### 8.4 重放与崩溃边界

- 每项替代调用使用服务端稳定身份，与原 call、确认批次和替代策略绑定。
- 已接受的相同确认只产生一次逻辑恢复动作；更改选择不能重开已消费授权。
- 已有持久化结果时复用，不仅检查 Graph State，也核对独立调用回执，覆盖“结果落盘但 checkpoint 尚未更新”的窗口。
- 对正在执行或结果未落盘的同身份调用，不自动再次发请求；暴露等待/核实状态，必要时明确重新授权。
- 不承诺外部服务没有幂等协议时的跨崩溃严格 exactly-once；本地防重不能证明外部未执行。

## 9. 证据覆盖与 Planner 边界

替代取证不改变原任务身份和验收条件。保留满足、部分满足、缺失或未知的覆盖信息，以及可引用材料和来源限制；原接口数据缺失的事实不能被搜索成功覆盖。

首版复用现有 completion_criteria、搜索 coverage 和 Planner 的 unresolved_questions，不建立新的研究本体或额外评审 Agent：

- 数据字段、日期、期间和完整性等可确定校验的条件用代码检查。
- 搜索模型的覆盖声明保留 basis，不当作独立事实证明。
- 自然语言材料是否足够，沿用批次证据评审；缺少真实数据时不能调度依赖该数据的确定性计算。
- TaskResult 的既有执行 status 不承担“全部验收通过”的含义；模型输入必须同时带有覆盖与来源限制，不只显示 success。
- 同一研究目标的来源切换由执行层恢复；只有研究目标、依赖、来源约束或预算需要改变时，Planner 才修订。

用户选择仅用已有资料后，任务结束等待，明确保留未取得项，不反复弹同一个问题。是否还能分析由已有材料决定，不能强迫所有工具任务成功后才允许回答。

## 10. 预算、审计与观测

### 10.1 预算

- 恢复分类、能力记录、批次确认及已确定替代参数的构造均为确定性处理，不新增模型调用。
- 每项已授权恢复最多执行一个逻辑搜索尝试；恢复自身不形成递归兜底链。
- 复用现有本轮搜索预算和原子预留，不因新批次、恢复或计划修订重新计数。
- 多个授权任务消耗各自实际调用名额；不擅自合并查询并宣称同时满足所有目标。
- 预算不足的条目标记未执行并保留缺口，不临时增加上限；有界处理部分条目时记录稳定执行顺序和结果。
- 搜索服务内部模型请求继续逐轮计量，不宣称替代取证没有模型成本。

### 10.2 单一事实来源

完整调用结果保留在 ToolCallRecord/回执对应的执行记录；能力条目、恢复事项和任务观察通过引用及最小摘要使用，不再多处嵌套 query、answer 和全部来源。回执为独立持久化保护，不能删除以节约提示词。

Langfuse 需要看清：分类依据、回执结算理由、能力命中/跳过范围、批次建立/确认/失效、恢复调用引用、预算消耗、覆盖缺口和是否真的触发修订。

分类依据优先记录结构化码、规则和阶段。有限长脱敏错误片段仅进入受控审计，不默认铺入各模型输入；无法安全脱敏则省略正文并保留安全标记，不回退为明文。

## 11. 首版映射与后续范围

首版沿用现有模块：

| 现有位置 | 设计要求 |
| --- | --- |
| `tools/mcp_http.py`、`tools/mcp_permission.py` | 在丢弃原文前完成结果归一化，保留安全依据 |
| `schemas/tools.py`、`tools/execution_gateway.py`、`conversations/execution.py` | 执行确定性与回执结算，持久化恢复防重依据 |
| `graph/state.py`、`tools/candidate_resolver.py` | 本轮限制记录及动态跳过，不修改目录 |
| `graph/nodes/permission_fallback.py` | 拆清纯策略、批次引用与替代执行，复用现有绑定检查 |

## 13. 验收矩阵

| 场景 | 必须成立 |
| --- | --- |
| 明确权限拒绝的文本/结构化/协议包装变体 | 归一化为可解释的拒绝，安全结算后进入确认 |
| 正常正文带权限词、限流、额度不足、参数错误 | 不冒充接口权限拒绝 |
| 权限错误夹带部分结果、执行后断连 | 不据关键词证明未执行，保留真实不确定性 |
| 两个不同接口并行，一个权限拒绝一个正常 | 拒绝不制造 unknown，正常接口不被误阻塞 |
| 同批多个可恢复拒绝 | 一次完整展示的 interrupt，不在确认前搜索 |
| 新任务在批次封存后失败 | 形成后续批次，不继承已有授权 |
| 用户拒绝、篡改或提交过期确认 | 不搜索，明确保留缺口或要求重新确认 |
| 重复确认、恢复重放、结果落盘但 checkpoint 未落盘 | 不重复原 MCP，已有替代结果不重发 |
| 同身份调用仍在执行、进程崩溃后结果缺失 | 不声称外部 exactly-once，不盲目重发 |
| 账号/连接/参数范围不同，或固定 Skill 禁止替代 | 不越界过滤、授权或替换工具 |
| 已确认限制被再次命中 | 无新远端调用，只记录引用原观察的跳过事件 |
| 搜索只得到相关文章而非所需序列 | 保留部分/缺失覆盖，不伪装量化任务完成 |
| 搜索预算耗尽、替代失败、能力记录写入失败 | 不递归恢复，不丢已确定回执，不扩大预算 |
| Langfuse 不可用或错误无法安全清理 | 业务隔离，省略不安全正文，无凭证泄露 |
| 回放与调用计数 | 权限处理不额外调用 Planner/恢复模型；保留正常证据评审 |

先用受控返回、真实网关/持久化与 Graph/checkpoint 证明上述条件，再在用户授权的真实数据源上验收；不能把替身测试当成真实账号权限验证。
