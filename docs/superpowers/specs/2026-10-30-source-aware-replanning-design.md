# 普通只读取证按数据源重规划

> 此方案已按用户后续要求停止，未作为最终方案交付。当前采用 Tool Agent 一次生成参数的多来源备用调用链，见 [当前设计](../specs/2026-10-30-multi-source-tool-plan-design.md)。


## 已确认行为

同一取证目标下，数据源 A 的工具失败后，不再换 A 的另一个工具尝试。必要信息仍缺失时，由合成层提出 `path_invalid`，Planner 优先选择其他已接入且适用的只读数据源；没有其他合适来源时才使用联网搜索。搜索参数由正常 Tool Agent 函数调用生成，不复制完整任务目标。

该策略不把单个指标的失败扩大为整个请求或会话的来源禁用，不改变主体、期间、指标与文档口径。不同取证目标仍可正常调用相同来源。

## 状态与身份

宿主在工具选择上下文保存当前请求、任务快照、调用指纹、受信副作用类型与来源身份。真实 MCP 以执行绑定的 `provider/server_id` 识别来源，避免把同服务器的不同工具当作不同来源；旧本地注册保留 MCP 命名空间兼容。

恢复范围从失败回执派生，不接受模型自报失败来源。新任务以 `retry_of_task_id` 关联当前失败任务，历史计划和原调用回执完整保留。沿该关系累计已失败来源，不能通过更换任务 ID 清空限制。

## 执行规则

1. 普通、已知只读 MCP 的权限、认证、额度、限流、服务或请求拒绝不再直接拼查询发起搜索，也不进入新的来源确认中断，先产出实际失败任务结果。
2. 参数错误允许原工具一次有依据的修正，提供原参数及脱敏错误详情，原样参数不再派发；再次失败后换来源。
3. Planner 的能力卡片与 Tool Agent 候选使用相同来源排除规则。失败来源在 BM25 截取前排除，避免候选全部被同源工具占满。参数修正仅披露原工具；来源切换仅披露适用的其他只读能力，没有适用候选时才披露搜索。
4. 规划校验要求重试保留原任务目标、验收条件和证据口径，并限制每个失败目标本次只有一个替代任务。下游未执行任务可重接替代任务的依赖。
5. 执行前再次核对恢复范围、来源与参数修正；其后继续通过原有 schema、权限、审批、预算、执行绑定及网关。
6. 来源恢复单独计数，每个请求最多 8 次修订，包含参数修正；普通结构性修订原有预算不扩大。没有新失败回执、来源耗尽、固定 Skill、在途执行、等待输入或预算耗尽不能无限循环。

## 兼容边界

固定 Skill 不进入普通来源重规划，继续使用冻结契约，包括既有明确搜索许可和参数重试规则。旧封存确认及业务写入恢复协议保留。写操作或未知副作用不进入来源自动切换；不核销既有未决回执。

## 验证

使用受控模型与数据源替身，运行真实 LangGraph、Planner、BM25、Tool Agent、Gateway 和独立数据库回执。验证来源 A 失败 → B 成功即停止，以及 A 失败 → B 失败 → 正常生成短查询搜索。覆盖错误码、缓存失效、参数修正、来源隔离、重试目标保持、预算、Skill 与持久化兼容；不以受控结果声称已取得真实财报。
