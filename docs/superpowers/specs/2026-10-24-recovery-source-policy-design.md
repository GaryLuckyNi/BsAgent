# 权限恢复来源约束的最小接入

日期：2026-10-24。分支：`codex/runtime-capability-recovery`。

2026-10-25 修订：依据用户确认，将“原始数据验收要求”与“用户禁止来源切换”分离；具体实现及真实验证见[修复验收](../../acceptance/2026-10-25-original-data-interrupt.md)。不增加自动搜索权限，不改变固定流程或未决执行保护。

## 决策与范围

用户已授权当前会话自主继续实施，要求不过度建设。沿用原恢复架构，不增加后台配置页面、数据库表、逐接口名单、Agent 或额外模型调用。修改工具 description 只改善选择，不取代执行控制。

选择一个服务端部署配置 `permission_recovery_source_policy`，取值 `unknown`（默认）或 `public_supplement_only`。后者表示业务允许**询问用户是否补充公开资料**，不是原接口等价替代或自动搜索授权。是否搜索仍由现有批次 interrupt 决定。

不选择仅改 description，因为当前代码硬校验来源政策，且提示词不能保证回执、防重或批次授权；不选择后台按业务场景配置，因为当前没有证据证明需要多套业务政策。

## 边界与数据流

1. 新 Run 从服务端设置冻结最小来源政策快照；旧 Run 缺少快照保持 unknown，不能因部署配置放宽自动取得恢复资格。
2. 既有 Intent Router 在同一次调用提取请求级 `source_constraint`：`unrestricted`、`original_only`、`unclear`。局部指定来源也保守视为整个请求受限，避免混合任务越界；不增加第二次分类。
3. 既有 Planner 在同一次调用标记每个任务的 `source_requirement`：`public_information`、`original_data`、`unclear`。需要完整序列、原始结构化数据或指定数据源时使用 original_data。不能为了恢复而降低验收要求。
4. 只有部署政策显式允许、Run 快照与当前配置一致、请求为 unrestricted/confirmation_required、任务需求为 public_information/original_data、且没有固定 Skill 时，无远端 I/O 的解析函数才能生成 allowed 及稳定规则依据。这里 allowed 只允许展示确认，不允许自动搜索；original_data 不等于用户 original_only。模型不能输出 allowed 或自行填充政策 basis。
5. 真实候选、已结算的执行前权限拒绝、当前 RBAC、批次确认、防重和预算继续独立校验。用户拒绝、不具备资格均成为业务缺口，不抛权限异常中断整条研究。
6. 形成选择快照时冻结来源依据；恢复前重新计算，与原快照严格比较。配置撤回、意图约束改变、任务约束改变均拒绝旧批次，搜索次数为零。已放宽的配置不能反向升级旧快照。

所有新语义字段缺失默认 unclear；未知不推断允许。新模式总开关仍默认关闭，不修改本地环境、不重启、不部署。

## 能保证与不能保证的内容

代码保证模型无法越过服务端政策，缺少结构化依据不能恢复，固定流程及用户明确禁止来源替代的任务不走搜索替代。原始数据任务可以经批次确认补充公开资料，但搜索成功不改变原任务验收条件，仍保留来源限制与原接口数据缺口。

自然语言限制的提取仍依赖既有模型，不能宣称任意自由文本都不会被误解。默认 unclear、请求级保守限制、任务级限制和用户可见确认是防线，不是通用金融数据真实性验证。若后续需要强制来源白名单，应由结构化请求契约扩展，不在本次建设后台。

## 验收

单元矩阵覆盖配置默认值、非法配置、缺快照、配置放宽/撤回、请求/任务限制、固定 Skill、缺失/非法语义字段、模型伪造 allowed。真实选择快照与 Graph 联合测试不再默认注入 allowed 替身；验证确认前零搜索、确认后仅列出任务搜索、限制任务返回缺口而健康任务完成、暂停后撤销不搜索。原权限分类、unknown、防重、共享预算、前端确认协议继续回归。

生产启用仍须通过原有专用 PostgreSQL 并发门槛；真实账号和付费请求不在本次授权内。
