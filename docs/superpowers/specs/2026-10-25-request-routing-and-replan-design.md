# 请求路由、上下文复用与主链路职责收敛设计

日期：2026-10-25

## 目标与已确认决策

本次工作有两个目标：

1. Router 向 Planner 传递 `available_information`，使规划能够复用与当前目标相关的已有信息，减少重复取数。
2. 按职责收敛主链路：Router 可基于充分上下文直接回答；需要整合证据时进入合成层；需要外部工作时先规划和执行；由合成层判断是否确实需要重新规划。

Router 与 Planner 保持独立。本文取代此前讨论的合并入口方案。本文是待书面审阅的设计，不表示代码已实现或真实请求已验证。

## 一、Router 的输入输出

Router 保留现有意图、业务分类、目标及来源约束提取职责，同时在同一次模型调用中输出：

- `available_information`：与当前目标有关的已有信息，顶层类型为对象，代码侧可表示为 `dict[str, Any]`，内部值必须可用 JSON 表达。
- `route`：严格枚举 `direct_answer`、`synthesize`、`plan`。
- `answer`：仅在 `direct_answer` 分支填写完整回答，其他分支为空。

业务信息对象内部不设必填字段，不强制领域 schema，不预设财务、行情、新闻字段清单。字符串、数值、布尔值、空值、数组及嵌套对象均可使用。字段命名和组织由 Router 围绕当前目标决定。

`available_information` 为空或旧 checkpoint 中缺少时按空对象处理。该对象不具有授权能力，不改变来源限制、审批或工具执行权限。

### 内容约束

Router 只整理输入中实际存在的信息，不将模型常识、推断或未执行的计划标记为已获取的数据。历史助手回答不自动等于核实过的外部证据。用户提供的信息可以作为分析前提，但不能自动获得外部核实属性。

对象优先携带简短信息和材料引用，不重复复制整份工具结果。时间、主体、来源、字段缺失、截断和不确定性等影响复用的信息应尽量保留。Router 标记已有信息，Planner 判断其是否满足当前目标；不能仅因为材料中出现过同一主题就禁止再次取证。

当前 Router 的历史投影排除了工具消息。实施时应复用现有上下文投影，为确实可访问的相关材料提供精简目录和稳定引用，不直接塞入全部原始工具记录，也不额外调用摘要模型。只有历史回答或摘要时应如实说明，不声明原始数据仍可读取。不得跨用户或跨会话读取材料来补齐引用。

内部业务字段自由，因此程序不能承诺通过遍历任意文本验证所有事实与引用。程序负责输入材料的身份和访问范围、对象的 JSON 合法性以及可识别引用的解析；模型负责语义整理。内容仍作为不可信数据处理。

### 路由规则

| 分支 | 条件 | 后续工作 |
| --- | --- | --- |
| `direct_answer` | 基于当前上下文即可直接解释或回答，不需要额外执行及证据整合 | 复用输出检查和最终响应，不进入 Planner 或合成层 |
| `synthesize` | 所需材料已有，需要整合证据、分析和形成最终研判 | 直接进入合成层，不为进入合成而先规划 |
| `plan` | 当前目标仍需要取数、工具动作或 Skill 执行 | Planner 生成最小必要计划，交给调度执行 |

复杂程度或是否属于解释性问题不单独决定路由；关键是尚需完成的工作。混合问题只要仍有必要的外部工作，就进入 `plan`，已有的解释和材料无需独立拆成重复任务。

回答与后续执行分支互斥。不能在选择 `plan` 或 `synthesize` 时先写完整结论，再执行取证。现有业务范围约束仍生效，范围外响应无需额外模型调用。不得把 Router 的原始 JSON 直接流式展示给用户。

## 二、上下文复用与规划

Planner 的初次规划和后续修订均接收 `available_information` 及必要的可访问材料。可复用信息同时进入真正需要它的执行和合成输入，避免只有规划阶段知道已有材料。

复用现有有界上下文与证据投影，不建立新的事实数据库或逐接口字段维护表。相同原始内容不同时复制到业务信息对象、材料正文和工具结果中；原始审计记录保持完整，模型输入使用有界投影。

Planner 通过 Prompt 控制任务颗粒度：

1. 优先复用满足当前主体、时间和来源要求的已有材料。
2. 适配已披露 Skill 的业务任务使用 Skill。
3. 需要精确权威数据的任务选择适合的数据能力；其他公开取证尽量通过少量综合搜索完成。
4. 不为最终解释、归纳或研判额外创建终端 Analysis 任务。
5. 保留确实作为后续步骤输入的中间分析，例如 Skill 中存在下游消费者的无工具步骤。

模型判断某任务适合原始数据，不等于用户明确禁止替代。任何替代仍须满足实际来源约束和确认要求，不能把搜索文章当作原始结构化数据用于精确计算。

## 三、执行、恢复与合成的职责

### Scheduler 与执行控制

Scheduler 根据任务状态和依赖派发工作，执行控制根据错误类型处理有限重试、参数修复、审批、来源切换确认、恢复及终止。新增成功结果本身不触发 Planner 评审。

同批权限失败按照已确认的恢复设计合并提示；确认只覆盖提示列出的任务。失败不能无声转为完成，也不能把整个请求的其他独立任务全部拦住。历史 unknown 回执的防重和核实保护继续生效，不通过清空回执、接口白名单或重新命名任务绕过。

有可推进任务、在途调用、待确认恢复或必要依赖等待时，先推进这些工作。某任务失败不等于全局请求必须结束，也不等于必须调用 Planner。

### 合成层

合成层承担最终分析、证据整合、局限说明和表达。它在原本就需要进行的同一次分析中判断应生成回答，还是提出重新规划请求，不新增一个每批结果必调的 Analysis 或研究评审 Agent。

只有在已有计划已执行到可以分析或明确无法继续推进的位置，才进入这次分析；不能每返回一个工具结果就调用合成层做例行评审。

合成层的控制输出采用互斥分支：

- `answer`：生成最终回答，保留影响结论的数据限制。
- `request_replan`：只输出结构化的修订需求，不同时生成可公开的完整答案。

`request_replan` 至少说明：受影响的原始目标或必要结论、暴露问题的证据引用、现有任务和恢复方式无法解决的原因、需要新增或修改或取消的工作。控制输出与 Router 的自由业务信息对象是不同契约；前者需要固定字段和严格校验。

合成层必须看到当前计划、必要的计划修订历史、相关已有材料、实际结果及错误和恢复摘要，才能区分“没有安排任务”和“任务已经安排但执行失败”。不得把内部错误摘要当作业务证据，也不需要接收所有重复审计字段。

## 四、重新规划边界：写入合成层 Prompt

### 总原则

完成原目标仍需要继续工作，但现有计划已经不能表达接下来必须做的工作，并且无法通过原任务内的重试、参数修复、来源替代或已有条件分支解决，才提出 replan。

缺口的重要性由它是否妨碍忠实完成原目标决定。材料更多、分析更丰富、信心更高或表述更漂亮，本身不是重新规划的理由。用户已经允许带限制回答时，应尊重该要求。

### 可以提出 replan 的场景

| 场景 | 投研示例 | 必须说明的计划变化 |
| --- | --- | --- |
| 原计划遗漏必要工作 | 判断估值却未安排必要的可比公司估值取证 | 原计划没有覆盖哪个必要目标，以及需新增什么任务 |
| 新证据揭示必要调查方向 | 利润增长主要来自一次性资产处置，需要核查公告和持续经营利润 | 为什么新方向是原问题的必要部分，而非可选扩题 |
| 关键证据冲突，需要额外核验 | 同期收入数字不一致，现有材料无法判断是否因口径或重述造成 | 为什么现有材料无法解释冲突，需增加什么核验 |
| 原执行路径不可行，替代需要改变任务结构 | 一个行业接口不可用，可行方案需要先查成分股、再分批取数汇总 | 为什么同一任务内换工具不足以解决，新增哪些依赖 |
| 关键前提被证据推翻，影响后续工作 | 公司重组改变主营业务，原同业比较对象失效 | 哪些未执行工作应调整或取消，哪些已有成果仍有效 |

### 不应直接触发 replan 的场景

| 情况 | 归属与处理 |
| --- | --- |
| 超时、限流、临时网络错误 | 原任务内按策略有限重试 |
| 参数错误或实体歧义 | 修复参数或询问用户 |
| MCP 权限不足 | 执行恢复和必要的来源切换确认 |
| 数据缺字段、结果覆盖不足 | 先按原任务的不完整结果及恢复策略处理 |
| 等待依赖、在途任务、已有条件分支被触发 | Scheduler 推进原计划 |
| 所有必要工作已完成，只剩分析和表达 | 合成层直接回答 |
| 无可行能力、用户拒绝必要替代、相关预算耗尽 | 在可用材料上回答并说明限制，或说明无法完成的部分 |
| 用户改变目标或新加要求 | 按新一轮请求处理，不冒充旧计划遗漏 |
| 对答案信心不足但说不清缺什么工作 | 保留不确定性，不以主观低信心反复规划 |

权限失败或不完整结果也可能最终暴露结构性问题，但错误本身不构成 replan 理由。例如一次替代搜索能够完成原任务时继续原任务；只有可行替代确实需要重构任务和依赖时，才按上表申请修订。重新规划不能授予替代来源权限。

### 模型判断与程序校验

合成层判断语义上的缺口和计划是否失效。程序不能靠错误码、关键词或结果数量完整代替这种判断。

程序只校验可确定事项：控制输出合法、请求绑定当前运行及计划版本、引用存在、相关工作没有仍在执行或等待有效恢复、没有重复提交相同未解决请求、预算允许、来源和权限约束未被绕过。是否在语义上仍服务于原目标由模型根据 Prompt 判断，不能伪装成确定性校验。不新增一个模型审查模型的调用。

Planner 收到请求后生成最小必要修订；继续验证 Skill 和工具能力可行性，不凭空生成不可执行任务。若已有工作能覆盖需求或没有可行修订，则返回明确的不修订原因，不能无变化地反复评审。

保留仍有效的已完成结果，调整受影响的未执行任务；不得重建全部计划、重跑全部工具，或仅通过改名重放失败操作。

### 循环与预算

第一版每轮用户请求最多接受一次实质性 replan，使用已有计划迭代预算统一计数，不另设可重复刷新的评审额度。格式修复不等于业务修订，但同样受模型请求的有限重试约束。

相同缺口不得反复申请。预算不足、修订没有实质变化或 Planner 无可行修订时，带明确原因进入最终回答，不再次申请相同工作；必要的最后一次合成输入应明确禁止再申请 replan。

产生有效修订时，执行补充任务后再做一次最终合成；未修订的拒绝路径必要时也需由合成层依据明确的结束原因生成答案，不能谎称已完成补证。正常路径在第一次合成调用中直接返回答案，不先生成一份分析再用另一次模型调用润色。控制分支确定前不向用户发布原始 JSON、内部评审内容或尚未采用的完整答案。

## 五、输出与兼容

Router 直答与合成答复复用相同的确定性输出检查、会话落库和最终响应通道。检查不通过时必须实际阻止原样输出；缺少固定声明等可确定问题本地修正，其他无法本地修正的违规内容使用受控回应，不为检查固定增加一次模型调用。现有 Verifier 的正则通过不等于事实核实通过，不能将其命名或观测为真实忠实度证明。

保留审批、interrupt、回执、防重复执行及固定 Skill 的工具绑定和必要验收。普通终端分析从主链路移除时，保留 Skill 中必要中间分析能力，不按节点名称盲目删除。

旧 checkpoint 中缺少新增字段时采用兼容默认：信息对象为空、业务范围内请求继续旧式进入规划，不从旧结果推测已获得新权限；实施需明确新旧运行恢复分界，避免在途确认失效或工具重复执行。

## 六、可观测性与验收

沿用 Langfuse，记录 Router 分支与已有信息、Planner 实际收到的投影、Scheduler 派发理由、合成输出动作及 replan 接受或拒绝原因、预算。模型请求记录为 Generation，确定性调度记录为 span，不按节点数冒充模型调用数。Trace 不额外保存未经现有脱敏规则处理的材料副本。

必须覆盖以下验收场景：

1. 已有上下文可直接回答：Router 后无 Planner、Analysis 或合成 Generation，仍完成输出检查及落库。
2. 证据已具备但需要整合：Router 后直接合成，无多余 Planner 或取数调用。
3. 混合问题：已有材料进入 `available_information` 并到达实际消费者，只规划必要的缺失工作。
4. 自由结构兼容：嵌套对象、数组、数字、空对象及旧字段缺省均可处理，不要求固定业务字段。
5. 时间或主体不匹配、只有助手自述或摘要：不会误将其当作足够的已核实原始数据。
6. 独立任务成功或依赖完成：直接推进后续任务，不出现仅因新结果触发的 Planner 评审。
7. 权限失败：先进入正确恢复路径和必要 interrupt；不能用 replan、任务改名或直答绕过确认。
8. 五类合理 replan 分别有证据与最小修订；相似但可在原任务内解决的案例不调用 Planner。
9. 重复缺口、预算耗尽、无变化修订、无可行能力：有限结束，保留有效成果，不循环。
10. Skill 必要中间分析、审批恢复、并行任务与旧 checkpoint 不因职责收敛丢失能力。
11. 输出检查不通过时，不再原样落地或通过流式内容提前泄露被拒绝的答案。

固定样本与链路回放应检查结构和实际调用；模型对语义边界的可靠性需用真实输入验证，不能靠模拟固定输出证明。真实请求仅报告实测调用、用量与耗时，不承诺固定延迟比例。普通模型直答目标为一次入口调用；附件分析、已有上下文压缩、提供方内部续轮和必要异常恢复应单独计入。

## 七、实施范围

实施涉及 Router 契约及 Prompt、上下文投影、Planner 初次与修订输入、调度路由、合成层控制协议及 Prompt、输出检查接线和对应测试、观测。

不新增 Recovery Agent、研究评审 Agent 或逐接口权限表，不把节点减少等同于模型调用减少，不在这次收敛中重做整个 Skill 编译或历史证据存储系统。
