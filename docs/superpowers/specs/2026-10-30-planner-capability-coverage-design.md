# Planner 按能力覆盖补召回

## 目标与边界

首次 Planner 依据用户目标、必要事实和少量已披露能力确定取证任务。已有候选不足时，允许一次明确的能力检索请求，再形成正式计划；不向模型注入全量工具目录，不执行业务工具，不占合成层的重规划预算。

一个任务内的候选必须相互替代，单个入选调用应能覆盖该任务；互补能力分成必要的独立任务。一次调用能返回多个必要事实时保持合并，不能按字段机械拆分。固定 Skill 覆盖目标时直接复用其既定流程。

## 协议与运行时

首次规划最多披露五张卡，为补召回保留至少三张卡位；即使配置 top_k=8 也预留名额。对普通多能力取证，第一回合优先确认必要能力并返回 `{"action":"discover_tools","queries":["缺少的业务能力短句"]}`；最多三个去重短句，每句不超过 512 字符。匹配 Skill、已有证据或单个已披露候选明确完整覆盖时允许直接返回计划。宿主在同一工具目录快照内执行 BM25，合并并控制披露至最多八张能力卡，再请求最终 tasks。最终响应不得再次申请检索。无搜索服务时不提供该分支。兼容旧模型直接输出 tasks。

保留当前请求、同一目录已有卡片，新增候选在剩余额度按检索问题轮流合并；总卡片正文不超过 8000 字符，完整输入契约不超过 12000 字符。检索同时应用目标和检索词中的市场/历史范围约束，避免目标未写市场时忽略能力检索词明确的 A 股范围。候选引用仍绑定当前 request_id 和目录快照；说明、权限与类型约束不变。工具层保留 Planner 已选定来源的候选，不用重新排序结果覆盖它们；其他来源仍可独立召回备用候选。

最终模型可输出内部 coverage，将必要事实绑定任务及候选；已有业务事实、可用取证能力与未知能力分开表达。模型声明 unknown 时，宿主也可根据对应任务的 tool_search_query 触发唯一一次补召回，不直接使用 task_goal 作为检索词。兼容明确包在 capability_search 字段内的检索申请，申请伴随的草案不会下发。coverage 不进入执行 State，不展示给用户；只校验结构和引用绑定，不以自然语言逐字匹配冒充业务覆盖证明。计算与解释不应作为外部取证缺口。

工具层只处理参数修正与执行失败切换，不判断业务完整性。调度节点不增加语义判断。合成层保留实际结果验收和兜底重规划。

## 降级与验证

检索无结果或暂不可用时保留已有候选，不能伪称能力完备。协议格式修复保持原有一次预算；修复可使用尚未消耗的补检索机会，但不能开启第二轮。JSON 数组、ID、候选引用与检索词先作结构校验，格式错误统一进入原有修复。补检索前后公开进度重置 JSON 缓冲，不发布虚假的计划失败事件。覆盖判断仍是模型语义判断，不宣称代码能证明整个目录的全局最优或业务完整性。

回归覆盖直接出计划零额外调用、按缺口补召回、禁止第二轮、非法检索协议不派发、候选预算、引用绑定、固定 Skill，以及工具层候选保留。使用真实工具目录和真实模型进行只规划验收，不执行财务取数。
