# Tool Agent 多来源备用调用链

## 用户已确认的方案

每个数据源独立检索最多三个适用候选，模型一次选择零个或多个来源、每个入选来源最多一个工具，并生成全部入选调用参数，按相关性排列。不同来源不要求全部入选。联网搜索为最后的备用调用，也在首次生成参数。执行串行；前一个成功后剪枝剩余候选，不进行重复取数。

参数错误先依据真实错误修正同一工具参数一次；修正失败或再次执行失败才切换后续候选。非参数错误直接执行下一个已生成参数的候选，不增加规划或参数生成模型调用。固定 Skill 和有副作用业务工具保留原有单调用路径。

## 组件边界

- 检索：在同一次 Run 的冻结目录中按数据源分组进行 BM25，各来源 Top-3，经权限与适用性筛选后交给模型。
- 选择：模型只绑定一个内部 `plan_source_calls` 计划函数。`choices` 为每个可信来源提供一个固定选择位，值为 null 或一个候选及其全部参数；`order` 排列全部非空选择位。Schema 披露每个候选的独立参数契约，宿主再次校验来源归属、唯一性、完整排序、搜索备用、凭证和服务端注入字段。计划函数不执行、不注入实际工具对话，只在轮到该来源时发布其单个真实请求。工具业务参数校验仍在执行当前来源前进行，局部参数错误只修正该工具，不否决其他备用来源。
- 执行：任务级持久化备用队列保存请求身份、目录与任务快照、当前位置、每源参数修正次数、实际尝试和剪枝状态。一次节点只执行当前工具，保存状态后再推进，因此断点恢复无需重新生成全部参数。
- 网关：每次实际尝试继续经过原参数、权限、审批、预算、目录和副作用门控。参数修正使用新的可信调用 ID，不重用旧参数的回执身份。
- 结果：只把实际执行的请求和结果写入工具对话及调用回执；失败明细完整保留。成功返回实际胜出来源，未执行候选标为剪枝；所有候选失败后才输出失败任务结果。
- 进度：复用任务活动 ID，显示“某数据源未取得数据，正在尝试另一数据源”或“正在修正查询条件”；保持进行中，完成后覆盖为成功。内部接口名、参数和错误正文不作为公共提示。

## 既有语义

工具成功沿用现有 `ToolCallResult.status`，不把合法的零值、false 或空集合擅自改成接口失败。是否满足用户问题继续由既有验收判断。固定 Skill 不自动扩展工具范围，写操作或未知副作用不进入多来源备用链；审批拒绝与未决执行不能作为切换来源的理由。搜索仍遵守共享调用预算。

本方案替代尚未交付的“按来源多次重规划”实现：不保留为来源切换新增的重试任务关系和独立重规划预算。原结构性重规划仍保留，不用于逐来源失败重试。

## 计划生成失败与重规划边界

`cee9079511ef1eeffad72ca8615493ff` 暴露了平铺候选 Function Calling 不能约束每源单选的问题：模型两次选中同一 Tushare 来源的现金流量表和财务指标工具，整份计划被拒绝，没有执行数据工具。旧实现只重发泛化提示，且最终失败未保存队列，合成层误将本地计划格式错误当成取证路径失效并触发重规划。

现在计划结构从单个函数返回；宿主拒绝同源多选、候选跨来源、重复或遗漏排序，不静默丢弃重复候选。首次结构错误仅在当前任务修正一次，反馈具体错误码和已披露的来源、候选身份，不复制未执行参数或任意异常正文。错误轨迹保存在队列 `generation_errors`。两次均失败则保存 failed 队列，结果为 `source_plan_invalid`，既有队列门控阻止重规划；没有模型配置时同样保存失败队列。不得把生成失败描述成远端来源失败。

嵌套候选参数 Schema 放入独立 `$defs` 并重定位本地引用，避免不同候选的定义重名或根引用偏移。服务端注入字段及凭证仍按原契约过滤与拒绝。固定 Skill、参数修正单调用以及执行网关不采用计划函数。
