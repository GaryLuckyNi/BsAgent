# InvestWise AI 研究工作区固定布局设计

## 背景

当前 AI 研究页已经将研究标题、对话内容和输入区拆分为独立组件，但页面高度仍依赖 `100vh` 和局部高度计算。输入区出现附件、错误提示或移动端浏览器地址栏高度变化时，可能出现整页滚动、底部输入区被挤出视口或多个滚动容器并存的问题。

本次调整只修改 AI 研究页的布局边界，不改变研究会话、附件上传、证据抽屉和消息流逻辑。

## 目标

- 删除研究历史侧栏底部的“行情数据待接入”卡片。
- InvestWise 顶部导航始终停留在视口顶部。
- 输入框、附件状态、错误提示和快捷问题组成完整输入区域，始终停留在研究区底部。
- 研究标题与底部输入区域之间的 AI 对话内容独立纵向滚动。
- 桌面端和移动端均不产生整页纵向滚动或横向滚动。

## 布局方案

采用视口级纵向布局，不使用 `position: fixed` 或依赖祖先滚动状态的 `position: sticky`。

1. `AppLayout` 对应的 `.app-shell` 使用 `height: 100dvh` 和纵向 Flex 布局，并隐藏整页溢出。
2. 顶部 `.topbar` 设置为不可压缩的固定高度区域，视觉效果等同吸顶。
3. 路由内容占据剩余可用高度；`.workspace` 使用 `height: 100%` 和 `min-height: 0`，不再通过 `calc(100vh - header)` 推算。
4. `.research-main` 保持三行 Grid：研究标题、可滚动对话、底部输入区域。
5. 只有 `.conversation` 设置 `overflow-y: auto`；其他主布局节点隐藏溢出或允许内部 Grid 正确收缩。
6. `.composer-wrap` 作为完整输入区域保留在 Grid 最后一行，并为移动端底部安全区预留空间。

## 组件调整

### `ResearchSidebar`

移除 `watch-card` 节点及其专属样式。研究历史列表可使用释放出的纵向空间，不新增替代占位内容。

### `AppLayout`

组件结构保持不变，只通过布局样式建立“顶部导航 + 路由页面”的全屏骨架，避免把页面业务逻辑移入布局组件。

### `ResearchWorkspace`

组件结构和数据流保持不变。桌面侧栏、移动端研究记录抽屉、证据抽屉继续独立工作；滚动边界由 CSS 控制。

### `ResearchComposer`

保持当前 AI Elements 组件及业务回调。附件、错误、输入框、工具栏和快捷问题都属于底部区域，不拆分固定层。

## 响应式行为

- 桌面端：顶部导航固定；左侧研究历史占满工作区高度；右侧只有消息列表滚动。
- 移动端：顶部导航固定；研究记录按钮与侧栏抽屉保持现状；底部输入区域使用安全区内边距，避免被系统手势区域遮挡。
- 输入区因附件或错误信息增高时，对话区自动缩小，不推动整个页面滚动。

## 可访问性与交互

- 保留原有键盘焦点样式和所有控件的语义标签。
- 消息滚动不影响顶部导航、研究标题和输入区的键盘可达性。
- 快捷问题与发送按钮继续保持原有交互，不添加依赖悬停的功能。
- 尊重现有 `prefers-reduced-motion` 规则。

## 测试与验收

### 自动化验证

- 运行现有 Vitest 测试，确保研究会话、证据抽屉和路由行为不回归。
- 运行 TypeScript 与 Vite 生产构建。

### 浏览器验收

- 桌面视口验证顶部导航和底部输入区域保持可见，滚动 AI 内容时二者位置不变。
- 验证页面根节点不滚动，`.conversation` 的 `scrollHeight` 大于 `clientHeight` 时可独立滚动。
- 验证“行情数据待接入”卡片不再出现。
- 在 390 × 844 移动视口验证无横向滚动、输入区域未被遮挡、研究记录抽屉可正常打开。
- 检查浏览器控制台无错误。

## 非目标

- 不调整顶部导航的视觉风格或菜单内容。
- 不修改输入框的功能、尺寸层级和快捷问题内容。
- 不接入 Tushare 或其他行情接口。
- 不改变证据来源抽屉、研究历史和消息生成逻辑。
