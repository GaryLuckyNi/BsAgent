# MCP 权限失败人工介入与历史回执修复

## 已确认需求

用户确认采用：已知权限前置校验，未知权限允许调用，明确权限失败后使用通用 interrupt 询问是否联网搜索；不能静默报错或自动切换。另须修复当前银之杰会话的历史阻塞回执。

## 约束

- 分支 `codex/feature-mcp-permission-interrupt`，不创建 worktree，不提交或覆盖既有 trace、README、VSCode 改动。
- 无权限 metadata 只表示未知，不表示拒绝。MCP 没有项目可依赖的通用权限 metadata 协议；已有本地 `permission_scope` 校验继续生效，不臆造第三方字段。
- 识别远端明确的权限错误，包括 TuShare 的明确权限拒绝提示；超时、参数错误、未知异常不得冒充权限错误。远端原文不作为指令、不直接透传凭证或堆栈。
- 用户选择不授予原 MCP 权限；联网搜索仍经过执行网关、本地权限和预算检查。
- 不降低所有 MCP 风险等级，不清除真实未知写入保护，不自动重试失败工具。

## 方案

### 错误边界

在 MCP 适配边界归一化可识别的权限拒绝，使用 `provider_permission_denied` 和安全说明。对已确认只读的 TuShare 查询，权限拒绝以 denied 结算；未知/可能写入工具即使声称权限错误，也不能仅凭不可信错误文本解除其不确定副作用保护。保持现有非权限错误分类。

### 人工选择

业务层产生 `pending_user_input`，scheduler 进入已有 `user_input_gate`。问题说明具体失败工具与权限原因，选项为联网搜索继续或不联网、使用已有资料并说明限制。即使搜索不可用，也不能伪造联网成功；恢复后须给出明确限制。

中断产生前持久化工具失败记录，但暂不投影终结该任务的 TaskResult，避免恢复前 scheduler 把失败步骤结束。恢复通过稳定 interaction/task/call 身份消费选择，不能重复原工具调用。明确本地权限拒绝亦可进入同一交互，不绕过校验。

### 替代路径与固定 Skill

用户同意后，显式绑定到 `web_search`，保留原工具失败与选择来源；搜索结果标注替代来源、未经原接口验证。不同意时以限制性结论收束，不能编造缺失数据。固定 Skill 不把搜索伪装成原 MCP 的成功结果，也不通过工具名漂移绕过步骤验收。可通过受控替代记录/分支实现，原工具冻结定义保持可追溯。一次任务的该权限事件只询问一次，不形成无限循环。

## 验收

1. 已知权限拒绝不发出外部请求；权限未知不被预先拒绝。
2. 明确权限失败产生可恢复 interrupt，刷新不重新调用原工具。
3. 同意才执行搜索；拒绝不搜索；本地权限或预算禁止搜索时安全结束。
4. 普通工具及固定 Skill 都保留原失败和替代出处，不伪造原工具成功。
5. 只读权限拒绝不锁住下一轮，未知写入失败仍产生保护。
6. 未知远端错误不被错误归类，敏感原文不泄露。
7. 当前历史回执定向结算且可审计，原 run/消息及其他回执不变。
