# InvestWise 金融投资应用 UI 设计

日期：2026-08-29  
状态：已确认  
范围：将 BsAgent 现有工程型前端重设计为面向真实投资者的 InvestWise 金融投资应用。本文定义产品结构、视觉语言、关键页面、AI 交互、证据引用与分阶段路线，不包含具体实施代码。

## 1. 产品定位

产品名称为 **InvestWise**，副标题为“智能投资研究平台”。

InvestWise 面向普通投资者，同时保留专业投研所需的数据深度和证据可追溯性。产品不以“聊天机器人”为首屏，而以行情、自选、资讯和持仓为主界面，AI 作为跨页面的研究能力进入。

产品目标：

- 让用户在一个界面内完成“发现机会—研究标的—追踪变化—形成决策”。
- 将 AI 结论与行情、财务、公告、新闻等证据直接关联。
- 在后续版本中延伸至因子研究、策略回测、模拟交易和受控自动交易。

## 2. 用户与核心场景

核心用户是关注 A 股的个人投资者，兼顾有较强研究需求的高频用户。

优先场景：

1. 查看大盘、行业、概念和自选股当日表现。
2. 进入个股页，联合查看行情、财务、公告、资讯与 AI 研究结论。
3. 针对财报、异动、风险事件或投资逻辑发起深度分析。
4. 从 AI 回答中快速核验引用证据和原始资料。
5. 对自选股、持仓和策略设置价格、事件或风险提醒。

## 3. 信息架构

桌面端使用固定左侧主导航，手机端收敛为底部主导航与二级页面顶部操作。

主信息架构：

- 市场：指数、行业、概念、涨跌分布、资金和市场要闻。
- 自选：分组自选列表、实时涨跌、异动和快速研究入口。
- 资讯：市场、行业、公司和公告信息流。
- 持仓：持仓收益、风险暴露、归因和相关事件。
- 策略与提醒：条件监控、策略规则、触发记录与后续量化入口。
- AI 研究：独立研究工作区，承载长对话、研究任务、历史会话和证据核验。
- 我的：账户、数据源、通知、交易连接与安全设置。

AI 提供两种入口：

- 全局 AI 抽屉：从市场、自选、个股、持仓等页面带当前上下文发起快速分析。
- AI 研究工作区：用于需要多轮追问、完整证据链和结构化输出的深度任务。

## 4. 视觉设计系统

整体风格为机构级浅色金融终端，避免游戏化行情大屏和通用 AI 聊天模板感。

### 4.1 颜色

- 品牌主色：深海军蓝，用于主导航、主按钮和重要标识。
- 品牌辅色：低饱和金，用于 AI、精选信息和弱调用，不作大面积背景。
- 基础色：白色、冷灰、深蓝灰，构建清晰的数据层级。
- A 股涨跌语义：红涨、绿跌，仅在价格及相关趋势中使用。
- 警告与风险：琥珀色与深红分级使用，不与涨跌色混用。

### 4.2 排版与密度

- 中文优先使用系统无衬线字体，数字、价格和百分比使用等宽数字特性。
- 桌面端采用中高信息密度，通过字重、留白和分隔线建立层级，少用厚重阴影。
- 卡片圆角保持克制；行情表格与长列表以扫读效率优先。
- 所有可交互控件具有 hover、focus-visible、active 和 disabled 状态。

## 5. 关键页面

### 5.1 市场首页

首页是市场终端，而非聊天首页。桌面端建议分为三层：

1. 顶部市场快照：上证、深证、创业板、科创 50 等指数与全局搜索。
2. 主分析区：指数走势、市场宽度、行业/概念热度和资金变化。
3. 关注区：自选行情、异动、市场要闻和 AI 每日摘要。

默认展示有决策价值的指标，避免为填满页面堆叠图表。

### 5.2 个股详情

个股页将数据和研究联系在同一上下文：

- 顶部：股票名称、代码、实时价格、涨跌、成交与自选操作。
- 主区：K 线和分时，支持周期、复权和关键事件标记。
- 数据页签：概况、财务、估值、公告、资讯和股东信息。
- AI 入口：右侧抽屉可带入当前股票、时间范围和当前页签上下文。

### 5.3 AI 研究工作区

桌面端为两栏主布局：

- 左栏：新建研究、会话历史、已保存主题和标的筛选。
- 主区：用户问题、AI 分析过程概览、结构化答案、内联证据索引和追问输入。

底层 Trace、Tenant、Session、Artifact 和原始思维链不向普通用户暴露。长任务只显示可理解的阶段进度，例如“识别标的”、“获取行情”、“检索公告”、“校验结论”。

聊天不提供导出功能。用户会话默认自动保存，允许重命名、收藏和删除。

## 6. AI 回答与证据引用

### 6.1 回答结构

答案优先按“结论摘要—核心依据—风险与反例—后续关注”组织，根据问题类型动态调整。关键事实和推断必须尽量就近绑定证据。

界面不在每条答案底部重复显示“不构成投资建议”，避免削弱产品的建议价值。后续自动交易的风险告知、用户授权和执行审批在交易功能的独立流程中处理。

### 6.2 内联证据索引

回答文本后使用中性灰色的数字圆点作为引用标记，例如 `2`、`7`、`15`。

索引语义：

- 数字表示该证据在当前回答完整证据列表中的序号，不表示证据数量。
- 同一结论由多条证据支持时，并列显示多个索引。
- 同一 `evidence_id` 在同一回答内始终使用相同序号。
- 编号与后端返回的稳定 `evidence_id` 映射，不依赖文本渲染临时位置。

### 6.3 证据抽屉

点击回答中的数字索引时：

1. 当前对话页不跳转。
2. 右侧打开“证据来源”抽屉。
3. 抽屉展示当前回答的完整证据列表，自动滚动至被引用条目并高亮。
4. 用户关闭抽屉后，回答的滚动位置和选中状态保留。

每条证据显示：序号、来源名称、日期、资料标题、命中摘要和原文入口。点击资料标题或“打开资料”时，使用浏览器新窗口/新标签页打开原始资料，而不是将证据列表本身做成独立页面。

### 6.4 证据前端数据形态

建议前端使用如下形态：

```ts
type EvidenceItem = {
  evidenceId: string;
  index: number;
  sourceName: string;
  publishedAt?: string;
  title: string;
  excerpt: string;
  sourceUrl?: string;
  sourceType: "market_data" | "filing" | "announcement" | "news" | "research";
};

type AnswerCitation = {
  evidenceId: string;
  index: number;
};
```

`sourceUrl` 缺失时不显示外链操作；不应伪造可访问原文的状态。外部链接需使用 `noopener`/`noreferrer` 防止新窗口回控原页。

## 7. 数据与现有能力衔接

前端保留现有能力，但重新包装为用户可理解的产品交互：

- OIDC 登录作为账户与权限基础。
- SSE 流式输出用于答案打字机效果、阶段进度和可中断任务。
- 图像上传、OCR 和 Vision 用于解读截图、图表和公告片段。
- 会话历史继续作为 AI 研究工作区的数据基础。
- Trace 保留给运维和内部调试，不作为普通用户主界面。
- Tushare 将作为真实行情与结构化金融数据的优先接入源，通过统一 provider 层向前端暴露稳定数据合约。

加载、空状态和失败状态必须是正式设计的一部分：行情超时显示数据时间和重试；部分证据失败时标识缺失项；AI 断流时保留已生成内容并允许续传。

## 8. 响应式与可访问性

- 桌面端优先，主要断点为宽桌面、窄桌面/平板和手机。
- 手机端证据抽屉转为接近全屏的右侧面板，仍保留关闭后的原回答位置。
- 图表不能只靠颜色传达涨跌，同时使用正负号、数值和图形差异。
- 证据圆点、图标按钮和表格行在键盘操作下必须可聚焦，并提供明确的 `aria-label`。
- 文本与背景对比度满足 WCAG AA，主要点按区不小于 44×44 CSS px。

## 9. 量化与自动交易路线

交易自动化是产品的后续目标，但与投研问答分层建设。

### 阶段一：市场与 AI 研究

完成市场首页、自选、个股页、资讯、AI 研究工作区与证据抽屉。

### 阶段二：持仓与智能提醒

接入用户持仓、收益归因、风险暴露、价格/事件提醒和持仓相关 AI 摘要。

### 阶段三：量化实验室

提供因子研究、策略构建、历史回测、交易成本模型、组合分析和模拟交易。策略结果必须展示样本期间、基准、最大回撤、交易频率和费用假设。

### 阶段四：受控自动交易

在模拟验证之后接入券商/交易通道。实盘执行必须具备：

- 账户与策略双重授权。
- 单笔、单日、单标的和组合级限额。
- 价格偏离、仓位、流动性、频率和亏损风控。
- 下单前预览或按风险等级审批。
- 实时状态、异常降级、可追溯审计日志和全局紧急停止。

AI 建议、策略信号和真实订单是三个不同对象，不得因一次对话直接跨越授权边界。

## 10. 验收标准

- 首屏在无教程情况下可被识别为投资市场产品，而非内部 Agent 调试工具。
- 用户可从市场或个股页在两步内发起带上下文的 AI 研究。
- 回答中的证据编号可键盘访问，点击后在当前页打开抽屉并正确定位该编号。
- 抽屉中有效原文链接使用新窗口打开，无链接证据不显示伪外链。
- 聊天界面无导出操作，不暴露内部 Trace 和原始思维链。
- 桌面与手机主要流程均可用，不出现横向溢出，重要状态不只依赖颜色。

## 11. 非本设计范围

- Tushare token、频控、数据权限和后端 adapter 的具体实现。
- 券商接入与实盘交易 API 选型。
- 因子库、回测引擎和交易执行引擎的技术架构。
- 具体的合规条款、风险问卷和地区性交易限制文案。
