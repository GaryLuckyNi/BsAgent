# 图片资产、后台身份与 OCR/Vision 内容边界实施计划

目标：推进既有 SEC-03/05/07/10 和 RT-05/14/23；修复图片 API 对同租户其他用户的默认资源访问、后台任务身份不绑定，以及图片文本结果/缓存未统一保护的问题。沿用已经确认的“通用凭证底线、业务规则暂空”设计，不推断业务数据分类。

架构：独立 asset_authorization 适配管理资源归属及后台当前权限；image_content 适配复用共享内容内核。API/资产服务和 Vision 公共边界接入，不要求业务 Agent 添加检查。原始像素只按已有资产清洗及租户外部 Vision 政策处理，文本凭证检查不构成图片内容外发前认证。

技术：现有 FastAPI、SQLAlchemy、Pydantic、httpx、pytest；无新依赖或迁移。当前 dev 的维护修复，不创建 worktree，不提交或部署。

- [x] 先写并观察失败测试：同租户他人详情/删除/分析、显式 read:any/delete:any 对照、队列 owner/analysis/session 替换、撤权和目录故障、过期资产、正常任务。
- [x] 资产服务在读取/删除/副作用前强制 owner 或明确操作范围；后台以持久化绑定为准，在对象读取和 provider 调用前刷新资产与当前权限，拒绝/故障不得调用外部服务。
- [x] 先复现 OCR/Vision 凭证结果、解析/HTTP 异常链、持久化/对象 artifact、旧缓存复制、直接 API/上下文读取和截断旁路。
- [x] 新增统一图片文本安全副本；在客户端返回、协调器截断、持久化/缓存复制、API/上下文输出前接入；不改原记录与执行身份。
