# 外部 RAG 实际契约核对与 HTTP 错误边界

范围：继续只修改 BsAgent 调用方，不更改外部 RAG，不假定新的认证协议。

- [x] 读取本地配置的 RAG 地址来源，不输出其他凭证。默认 localhost:8001 未运行，用户明确实际为 localhost:8011。
- [x] 仅 GET 实际服务健康与 OpenAPI，记录检索请求 schema、认证声明和身份字段；不检索真实知识文档。
- [ ] 先用合成错误正文及真实本地回执复现：404 原始错误泄入回执；网络异常/第三方错误含敏感文本；非200成功与重定向不能当证据。
- [ ] 在 RAG HTTP 适配器把错误正文换为固定安全文案，异常链不公开传输层详情；保持已有错误码与原HTTP请求，成功证据内容不在此处过滤。
- [ ] 将本地 RAG 地址显式配置为用户给出的8011，修正文档中把相邻源码等同实际部署的陈述，不重启服务。
- [ ] 回归并独立复核；保留服务认证/文档 ACL 的未完成状态，记录真实接入所需契约。

下游 OpenAPI 未声明认证不等于证明实际运行完全无鉴权。本轮未发检索请求、未读取文档，不能给匿名文档访问或 ACL 结论。Bearer/API Key、用户委派和私有文档授权需服务方明确其真实协议后接入；不自行强加签名头。

后续用户明确应采用统一工具内容策略，而非按 RAG 特例堆脱敏规则。此计划不再作为统一脱敏/防注入的实现方案，现有 RAG 局部修复和专项测试仅作局部证据；统一方案以 docs/security/tool-content-policy-design.md 为准。
