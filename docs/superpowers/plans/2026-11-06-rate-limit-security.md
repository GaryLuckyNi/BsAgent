# 入口预算失败策略与审批恢复限流修复计划

目标：验收并修复已有Redis入口限额，处理生产fail-open、必需服务缺失、运行配置未应用及审批恢复绕过；同时完成当前调用路径/预算盘点，不把本批限流等同于全任务预算完成。属于已有控制维护，在dev修改，不迁移、部署或修改外部服务。

设计：生产配置必须fail-closed，factory也强制该策略；配置启用限流时服务缺失返回固定503。RateLimitPolicy可声明受信runtime配置字段，API统一使用共享agent调用策略、图片使用其独立策略；自定义静态policy不被运行配置偷偷改写。审批decision HTTP入口与已有messages/protocol/AG-UI使用同一actor/tenant桶，内部函数调用不重复扣除AG-UI已消耗的限额。

Limiter故障或畸形结果返回固定错误，在except外抛出，不保留原Redis异常链；429保留有界Retry-After。正常请求、显式关闭的本地模式和允许的非生产fail-open保持对照。来源、状态、审批指纹和执行回执不因限额拒绝改写。
