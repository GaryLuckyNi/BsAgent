# 按数据源切换的失败重规划实施计划

> 此方案已按用户后续要求停止，未作为最终方案交付。当前采用 Tool Agent 一次生成参数的多来源备用调用链，见 [当前设计](../specs/2026-10-30-multi-source-tool-plan-design.md)。


**目标：** 普通只读取证失败后，由重规划选择其他数据源，同一取证目标不再遍历已失败来源的其他工具；其他来源不可用时才披露联网搜索，搜索参数走正常函数调用生成。

**架构：** 从本次请求的真实调用回执与宿主保存的选择上下文计算失败来源。重试任务通过 `retry_of_task_id` 关联历史任务，保持原目标和验收条件。来源切换有独立、有上限的修订预算，原有结构性修订预算不扩大。固定 Skill、写操作、未知副作用、审批及搜索预算继续按原边界处理。

**技术：** Python、Pydantic、LangGraph、现有 BM25 候选检索与统一工具网关。

- [ ] 添加失败回执、重试任务谱系、来源排除与来源优先级测试，先确认失败。
- [ ] 增加可信来源标识、回执派生恢复上下文；按目标传递历史失败来源，不做全局封禁。
- [ ] 撤回普通任务的硬编码自动搜索；只读失败保留原回执，交回合成与重规划。参数错误允许原工具一次修正。
- [ ] 规划和执行使用相同来源排除规则；候选缓存随失败观察变化，排除来源发生在 BM25 截取之前。
- [ ] 允许来源恢复多次修订并限制总次数；保留普通结构修订、依赖、在途、固定 Skill 门控。
- [ ] 使用受控模型和真实图、检索、网关验证 A 来源失败 → B 来源失败 → 搜索正常生成短 query；验证成功后终止、独立任务不受污染、固定 Skill 不越界。
- [ ] 运行相关单元及集成回归、静态检查，修订之前误写的“普通任务直接自动搜索”文档。
