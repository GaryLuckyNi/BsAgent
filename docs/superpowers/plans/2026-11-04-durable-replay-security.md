# 持久化协议重放内容安全修复计划

目标：关闭 `subscribe_events` 原样重放旧 JSON、按单帧检查无法发现跨帧凭证，以及 `get_active_run` 返回未封口部分正文的旁路。复用已获用户确认的“完整检查后展示”，在 dev 维护修复，不提交、部署、迁移或修改外部 RAG。

方案：独立 `security/protocol_replay.py` 适配负责正文重建与展示副本。按 `run_started` 阶段拼接所有正文，不能用不同消息 ID 拆开恢复客户端实际会拼接的文本；完整检查后按原片段长度分配安全文本。即使订阅 cursor 在中间，也从前文重建检查上下文。检查器故障、格式错误或预算超限扣留正文；原始行不改写。单次预检最多 20,000 事件、2,000,000 正文字符，数据库按 200 条读取，不一次装载全部历史。

运行仍开放时不发正文。遇到待检查正文后，后续进度/来源可作为不带 SSE id 的预览发送；恢复游标停留在正文之前。封口后重新按持久化序号发送完整检查后的事件，保证重连不会因较新的进度游标跳过正文。预览按已有业务 progress id 更新；正文与最终状态只在正式有序通道发送。当前运行状态接口在生产者未退出时返回空正文，退出后完整检查。

非正文事件生成共享凭证安全副本，来源 URL 使用现有 public_sources；消息角色/ID、run id、调用/审批指纹和真实状态不因展示检查改写。终结状态仍来自数据库，检查器故障不能改写副作用结果或触发图重新执行。新历史正文、旧历史正文都在订阅出口重查。

验收中补齐同源旁路：`public_message_snapshots` 同一 SQL 读取正文/消息状态/运行状态/封口，不采用 ORM 已缓存的旧部分正文；历史列表复用同一快照，搜索和会话匹配在 SQL 中排除未封口 assistant。会话 title/preview 完整读取，在公共 DTO 检查后再截至160/320字符，不能先截出低于凭证长度门槛的片段。

- [x] 实现独立重放适配和订阅/活跃正文公共接入；补检查器故障、超预算、不同消息/阶段隔离、取消/失败部分正文及关闭连接回归。
- [x] 执行协议重放、durable API、停止/恢复、模型/公开输出关联测试；独立只读复核，保存日志/JUnit/复跑清单。
- [x] 更新安全设计、红队案例、验收报告和 TODO；只关闭本计划已证明的范围，整体安全目标保持逐项验收。

边界：原数据库历史清理、所有未知业务秘密/编码、数据库响应字节上限、整体执行预算、现存 HTTP 订阅期间持续权限撤销及真实部署继续保留专项。此修复不将模型部分正文提前放行，不改变已执行工具的结果。
