## 设计与依据

采用确定性修复：查询只使用脱敏后的冻结任务目标；完整目标、验收条件与截止时点继续走可信上下文。在封存恢复条目前按当前搜索工具 schema 校验，无法构造合法输入时返回明确原因，不发布必定失败的确认项。执行时仍由 Gateway 二次校验，预算和防重继续使用既有持久回执。

工具节点因待确认而暂时没有 TaskResult 时，进度须参考同一任务的真实工具回执，不能将节点返回等同于取得证据。失败后的合成材料明确区分原接口权限不足、搜索参数问题和上游搜索失败，使用固定中文消息，不透传原始诊断。

涉及生产代码限定为恢复查询公共模块、恢复执行器、资格校验、执行节点的失败内容、公共进度和合成材料六处；均属于已确认的查询构造、预检与错误展示链路。行情/研报拆分、原始权限账号开通、Fetch、历史 Run 重放均不在本次范围。
