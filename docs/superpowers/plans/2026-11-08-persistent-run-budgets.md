## 设计与范围

新增独立 `security/run_budget.py`、预算表与0019迁移。首次已验证请求在begin_turn同一事务创建预算，冻结身份、策略版本/限额及绝对期限；普通请求字段、Graph State、checkpoint和恢复payload不提供预算权威。首次执行、同步/异步工具、HTTP/SSE、审批和worker恢复共用相同run记录，旧无预算任务不能靠恢复自动补发。

本批同时配置512次HTTP请求、128MiB原始响应实体和128MiB解压后响应信用额；请求次数包含零正文请求，避免GET重连不计费。模型计真实物理HTTP请求，工具计实际executor派发，搜索/回执结果复用不派发则不扣工具次数；失败/未知派发不退款。每次请求累计实际缓存正文长度，未知流式请求正文在预算run内拒绝，不先无界读完再测量。响应按64KiB不可退款信用额批量预留，账本原子比较更新，避免每token查库；记录的是已授予信用额而非精确网络账单。现有单响应8MiB/行预算继续独立约束。

新的ContextVar仅由API/harness可信资源绑定，生成器每次推进时设置并复位，不跨HTTP yield泄漏；HTTP读计量器捕获可信绑定，不能靠后续State字段替换run。预算错误固定、无原始连接异常链；耗尽/过期/服务故障都不派发新操作，终止错误不参与重试/替代流程。已开始的工具继续保存真实结果/未知副作用，预算不能阻断回执与cleanup。

账本使用独立短事务。条件UPDATE同时验证身份/冻结策略、期限和所有计数，不靠进程内Lock保证配额；并发/恢复不能重置。入口创建必须在执行前commit；不在持有execution写锁的事务内另开预算写事务。历史无账本任务需重发，生产迁移不自动回填或切换。
