# 统一工具内容策略实施计划

目标：不改业务 Agent 节点，为全部工具成功/失败/异常建立公共内容策略，并保留执行真实性。

架构：security/tool_content.py 提供受信业务规则、凭证底线、出口视图、来源/信任标记和可配置注入风险处置。ToolExecutionGateway 在原始返回校验后生成对全部出口规则取保守限制的工作流视图，再投影回执/观测视图；native_calls 处理正文和artifact。配置来自受信 Settings，不接受工具/模型返回修改。原始失败 payload 不作为 raw_result 旁路保存。

第一批明确限制：model/user/memory/receipt/trace/log 仍复用当前工作流结果，规则取保守交集，不通过低权限视图恢复原值；引擎可按出口投影，但独立用户展示视图、全应用日志、OCR/输入及后续数据外发用途策略仍待逐项接入。无业务规则时明确标记未配置，不能宣布业务脱敏完成。

- [x] 测试先行：任意工具成功/失败/异常的凭证泄露、schema敏感字段、业务掩码、回执旁路、正文/artifact不同步、来源伪造、策略异常及写入结果保存。
- [x] 纯策略内核：严格规则schema（字段路径支持*，redact/mask/drop，按工具/tenant/scopes/出口匹配）、有限处理预算、不修改原始值、最小审计和策略版本。
- [x] 统一网关：保留原始校验及执行状态，配置错误在派发前拒绝；派发后策略失败扣留内容并保留真实状态，原始摘要改为无正文诊断。
- [x] 回执/恢复与观测：每次重用按当前策略重新投影，策略视图与执行完整性指纹不混为一谈；敏感原始对象不进入待补写内存队列。
- [x] 模型工具消息：正文/JSON/artifact统一清理，ToolMessage角色不变，宿主覆盖外部自报信任元数据。注入标记是辅助，不声称检测万能。
- [x] 回归与独立审查，记录不同工具正常对照和恶意样本，更新中文文档及未覆盖TODO。

业务规则默认空；本地/测试合成手机号规则只作为测试，不作为生产业务定义。默认注入处置flag，可受信配置为withhold；withhold不伪造工具未执行，也不允许重复执行已经成功的同一写调用。

2026-11-09按用户要求收敛并补齐常见提示注入防护：公共工具运行配置默认值由上述首批的`flag`调整为`withhold`，OCR和记忆/摘要入口同样扣留命中内容，并补工具描述绑定检查与宿主来源隔离规则。纯策略构造器仍可供受信调用方显式选择处置；普通请求或外部工具不能修改配置。当前行为及证据见 [必要防护验收记录](../../security/reports/2026-11-09-prompt-injection-implementation.md)。

本批实施完成；877 项关联测试通过，其中专项 64 项，独立复核未发现剩余 P1/P2。证据和后续范围见 [验收记录](../../security/reports/2026-11-02-tool-content-implementation.md)。本计划完成不代表总体安全 TODO 已完成。
