# 长连接持续授权修复计划

目标：用户停用、成员撤销、权限回收、JWT到期或会话删除后，不继续通过已建立的 SSE 输出资料。沿用主应用现有 OIDC/JWT、权限目录与资源归属；不重跑或回滚已执行工具，不把读取拒绝伪装成运行失败。

公共模块 `security/stream_authorization.py` 保存已验证请求的不可变主体、必需权限与资源绑定。每次推进输出前、正文/进度/心跳实际发送前，重新检查目录当前授权、初始权限上限、JWT到期与数据库资源归属；检查器或数据库故障拒绝读取。固定流错误不包含原始异常、不带恢复游标、不生成 run_status。新连接仍走现有401/403/404依赖，已发出的字节无法撤回。

验收中额外修复慢授权查询跨过期限：所有目录/资源查询结束后再次检查本地deadline。首次POST的真实SDK丢弃code，故固定错误增加SDK保留的name，配合受信fetch的HTTP拒绝分类，以及onError/onFinish/恢复入口的停止标志；身份刷新或显式新请求再重新授权。

JWT验签主体新增可序列化的 `expires_at` 时间戳，目录认证映射保留该值；它来自验签后的 exp，不接受业务字段。后台持久化任务继续用自己的权限委派，不因用户订阅token到期而冒充任务未执行。POST protocol首次/恢复/幂等订阅保留原请求主体，不能用initialize_run返回的后台主体替代；GET events要求agent:read，POST输出要求agent:invoke。

覆盖当前3个 StreamingResponse入口：持久化 GET/POST、普通会话 SSE、AG-UI 新任务/审批恢复。AG-UI审批恢复保留已授权 approver 的既有跨用户审批语义，但绑定已核验的原run和租户/session，持续要求agent:invoke及approval:decide；不能从模型或resume payload自报资源授权。

前端识别固定授权终止错误并停止自动重连，保留最后安全内容/恢复游标，不把后台任务标记成完成或失败。其它临时网络错误仍按已有策略重试。

持续授权层不直接写运行状态。durable订阅关闭不停止独立生产者；旧同步生成器关闭仍遵循既有断线收尾契约，不将尚未完成turn的结束描述成已完成工具未执行。真实部署的IdP同步、独立审计及预算仍按总体TODO验收。
