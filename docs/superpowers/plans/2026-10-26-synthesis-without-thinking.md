# 合成层关闭推理与渐进输出实施计划

> 执行方式：在当前功能分支内按 executing-plans 顺序实施；不创建 worktree。

**目标：** 合成层所有模型调用关闭 thinking，根据 goal 决定回答规模，并在可校验的路径逐段展示正文。

**架构：** 保留一次模型调用同时判断完成情况和回答。回答采用单行 JSON 决策头加 Markdown 正文；重规划保留完整结构化申请。适配器将新协议转换成现有 SynthesisDecision，兼容已有完整 JSON 响应。首个决策头严格验证后才可能发布正文；数值底稿要求全文检查的路径仍缓冲。

**技术栈：** Python、Pydantic、现有 LlmStreamDelta 和 answer_delta 事件、pytest。

## 1. 关闭 thinking 与调整篇幅

- [x] 修改 `backend/app/graph/nodes/synthesizer.py`：首次和修复调用均为 `thinking=False`，删除仅对 thinking 生效的空响应降级配置。
- [x] 删除交接路径 800–1200 字要求；按用户问题覆盖必要信息，详细请求与偏好仍生效，不设统一短字数截断。
- [x] 更新 `test_request_flow.py`、`test_task_synthesis.py`、`test_dynamic_task_graph.py` 的实际请求断言，验证新流程、旧流程、显式交接均关闭。

## 2. 决策头与正文协议

- [x] `synthesis_decision.py` 接受 `{"action":"answer"}\n正文`，仅严格无额外字段的头有效；空正文失败。继续接受原完整 JSON，重规划引用与预算校验保持原有入口。
- [x] 调整 required_schema 与协议提示。格式修复仍最多一次且关闭 thinking。
- [x] 新增协议测试：拆分任意字符的响应、旧 JSON、重规划、未知 action、额外字段、空正文、非法 JSON 头。

## 3. 受控分段发布

- [x] 新增 `backend/app/graph/planning/synthesis_stream.py`：收集决策头，完整验证后仅转发回答正文；旧协议和重规划只缓冲，不公开控制字段。
- [x] 分段边界采用空行；不逐 token 绕开输出检查。共享既有投资建议禁止模式，在段发布前检查；模型品牌文本沿用现有替换逻辑。
- [x] 数值底稿存在时不开启正文流；最终仍运行原数值与 verifier 校验。异常或非法响应不把残余缓冲作为正文发布。
- [x] 验证首次段落可在模型调用结束前收到，失败、重规划、内部 JSON、数值不通过时不泄漏原始输出；最终正文不丢字、不重复。

## 完成条件

所有合成调用关闭 thinking；没有默认最低篇幅；原来的 goal、来源约束、重规划预算仍有效。普通回答的第一完整段可在模型结束前展示；需要全文数值检查的路径不提前发布。若原 trace 在关闭 thinking 后再现语义错误，修复其输入理解并重新验收，不能恢复 thinking 或用宽松断言掩盖。
