日期：2026-10-26。分支：`codex/deepseek-search-api`。

## 故障证据

Langfuse Trace：`5a3c8d3c89b610eecbafc0d37df91c96`。

用户问题为查询寒武纪最新股价、最近研报目标价并计算上行空间。只读检查原始观测、PostgreSQL 协议事件、执行回执及最终 checkpoint 后确认：

- TuShare `research_report` 返回 40203，被归一化为 `provider_permission_denied / not_started`。
- 来源切换确认正常发布，用户已选择 `web_search`，决定已持久化。
- 恢复查询拼接任务目标与验收条件，合计 192 字符，超过直连搜索的 128 字符限制。
- 搜索在 Gateway 本地返回 `tool_argument_validation_failed / not_started`，耗时约 1 ms，没有实际搜索回执。
- 任务目标本身为 101 字符，符合接口要求。
- 原工具节点因等待确认没有 TaskResult，进度将节点返回误报为“已取得研究证据”；合成只获得宽泛目标限制，没有说明替代搜索参数失败。

本次未修改原 Run、原始确认、checkpoint 或回执，也没有为验证重放原请求。

## 修改内容

1. 批次恢复查询仅使用脱敏后的冻结任务目标；完整目标、验收条件和截止时点继续通过可信研究上下文提供。调用身份继续由原批次和原调用确定，不截断查询或验收条件。
2. 恢复条目生成时，共用实际执行的查询构造函数，按当前搜索工具 schema 进行无 I/O 预检。查询超长、其它参数不合法或脱敏失败时返回明确原因，不生成可确认条目；执行时保留 Gateway 校验。
3. 权限失败尚无 TaskResult 时，公共进度依据同一任务的真实工具结果判断状态，存在恢复条目时提示等待选择来源；当前任务已有成功结果时，不再读取旧失败回执生成权限提示。
4. 查询预检失败和确认后的搜索失败使用固定中文说明。合成材料保留原权限失败及替代搜索失败的区别，不透传原始 HTTP 诊断。
5. 历史工具未核实导致本地阻塞的恢复，继续标记历史执行未核实，不误报为数据源账号权限不足。恢复材料保留原冻结来源约束以便正确归因；历史材料缺少该字段时，使用中性“原接口数据未获取”。

## 测试先行与受控回放

先调整查询预期并新增展示测试，观察 `7 failed, 8 passed`，分别复现查询拼接、待确认误报成功及合成丢失原因。

随后使用真实 `WebSearchTool` 输入契约、LangGraph、Gateway 和独立持久回执的受控集成测试回放原任务，观察 `3 failed, 1 passed`：确认搜索因超长未派发，以及两种输入长度契约都在预检缺失时错误发布弹窗；拒绝搜索的用例已通过。

实现后验证：

- 原样保留 101 字符任务目标与全部验收条件；确认前零搜索、确认后一次搜索。
- 客户端收到的 `query` 为任务目标，研究上下文保留全部验收条件和封存的 `as_of`。
- 同一调用通过持久回执复用时不再请求客户端，原 MCP 只调用一次。
- 拒绝联网时零搜索；实际 schema 为 128 或更严格的 64 字符时均正确预检，无确认项、无搜索。
- 权限拒绝但没有 TaskResult 时，typed/dict 两种回执表示都不会显示已取得证据。
- 恢复参数失败、搜索超时、预检超长和历史执行未核实的说明可区分，内部内容和用户可见材料保持一致。
