# 普通研究优先使用可用来源（早期实现记录）

> 本文的“原任务内自动搜索”实现已按用户后续澄清撤回。当前由 Tool Agent 一次生成跨来源备用参数，串行执行，成功剪枝，搜索最后兜底；不直接将 `task_goal` 用作查询词。见[当前设计](../superpowers/specs/2026-10-30-multi-source-tool-plan-design.md)。下文 313 项测试和受控重放仅记录当时实现，不作为当前行为的验收依据。

## 用户确认的策略

普通研究不需要指定数据获取来源，有可用来源就先取数据。保留所求主体、期间、指标及文档口径，来源切换不自动降低证据要求。固定 Skill 仍遵守已有冻结工具与显式搜索许可；工具权限、审批、搜索预算、执行绑定和已知写入保护保留。

## Trace 根因

`5ae77efacaf33d3cb1d93e1928cf677e`，北京时间 2026-10-30 09:20:57 开始：

1. 用户要求从立昂微 2024 年年报提取三项金额并计算比率，Router 输出 `source_constraint=original_only`。
2. 普通任务调用财务指标 VIP 接口，提供方返回 `40203`；系统按错误码保留为 `provider_request_rejected`、`not_started`，没有返回业务结果。该码不能仅凭数值精确断言权限原因，但既有只读自动搜索策略已覆盖此类请求拒绝。
3. 自动搜索被 `source_constraint != unrestricted` 的前置判断跳过。当时仍有六次搜索预算，且实际候选含 `web_search`。
4. 合成层没有原任务恢复失败的实际记录，却以 `path_invalid` 声称必须改变取证结构，消耗了一次重规划。
5. Planner 更换任务文字后，执行层选回普通财务指标接口；调用成功但缺少用户要求的三项金额，最终无法计算。执行成功不等于完成用户目标。

此次修改首先去掉来源标签对正常取数和自动兜底的阻拦，不将单个拒绝等同于任务结构无效。

## 修改

- Router 不再要求模型生成 `source_constraint`；模型响应解析保留旧字段兼容，但不再序列化到新状态。
- Planner 不再传播该字段或将来源标签作为规划限制；文档与指标口径仍属于业务要求。
- 普通 `web_search` 不再被旧来源标签阻拦。
- 已知只读 MCP 权限／请求拒绝在原任务内自动搜索，不因标签为 `original_only`、`confirmation_required`、`unclear` 或缺失而停止。
- 修正搜索工具描述中“权限失败不自动兜底”的过期提示。
- 合成层明确：单次数据源拒绝不证明结构失效；没有实际恢复记录不能声称原任务内恢复无法解决。重规划的请求绑定、预算和已有门控不变。

旧封存恢复协议及其审计字段保留兼容，不据本次策略修改历史回执，也不自动重放旧业务写入。

## 验证

先更新预期并观察到 **18 项失败、102 项通过**，失败覆盖来源标签阻断兜底、阻断普通搜索以及新意图／Planner 继续发布来源门控。

最终相关单元与集成回归 **313 项通过**，覆盖：

- 两种实际提供方错误码 `2002`／`40203`、五种旧标签／缺失状态、两种任务证据标签的真实 Graph + Gateway + 独立持久回执组合；均在原任务内自动搜索，不产生确认中断，原计划保持不变。
- 原失败回执与搜索回执分别结算，独立健康任务继续；不重放原调用。
- 共享搜索预算、缺少 `web:search` 权限的拦截、固定 Skill 搜索许可与参数重试限制继续有效。
- 新 Router／Planner 保持各一次模型调用，不发布或传播来源门控。
- 合成、重规划预算与原有生命周期回归。

另用原 trace 的失败结果、原请求参数和原任务目标重放失败后的恢复分支。即使旧状态仍为 `original_only`，也进入 `web_search`；搜索词 112 字符，包含立昂微、2024 年及三项金额指标，通过真实搜索入参 schema 校验。搜索使用受控替身，未重放原 MCP；该验证不表示已取得立昂微真实年报数据。结果见同目录 JSON。
