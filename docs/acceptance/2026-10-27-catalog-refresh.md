# Run 级工具目录一致性验收

## 行为

一个 run 固定使用同一份工具注册表与搜索索引，普通输入中断、审批中断恢复也沿用原快照。客户端刷新只发布新快照，不在节点之间切换目录；后续新 run 使用已发布的新目录。

Gateway 派发前检查最新已感知目录中的目标工具。工具移除返回 `tool_not_found`，契约或执行绑定变化返回 `tool_catalog_changed`，均为 `not_started`。无关目录新增不影响当前调用。执行使用 run 捕获的原条目，已经发出的调用保留结果，不因刷新丢弃或重放。

原执行器快照在进程重启后不可恢复且目录不匹配时，不换用新契约执行。待执行任务变成模型可见的工具错误，保留此前结果与未决回执，由模型组织本轮回答并完成会话收尾。有效的中断仍保留快照，终态提交后释放；非法恢复选项、审批决定仍被拒绝。

## 回归证据

- 目录固定、调用前检查、在途结果保留、初始化失败清理及两类中断恢复等针对性测试：22 项通过。
- 后端全量测试：2095 项通过、53 项跳过，耗时 195.13 秒。跳过项不计入验证通过；另有既有 pytest 插件导入与测试用 HMAC 密钥长度两条警告。
- 前端会话恢复与终态清理测试：40 项通过。
- 本次后端改动的 Ruff 检查通过；`sessions.py` 沿用已有 FastAPI 默认参数写法，检查时忽略原有 `B008`。
- `git diff --check` 通过。
- 独立代码审查发现的非法恢复载荷校验与延迟终态快照释放问题均已修复，并补充回归测试。

## 范围与限制

客户端复用现有周期发现与后台刷新，并提供显式刷新入口；未新增 MCP 长连接通知订阅。run 执行器引用保存在本进程，未实现跨进程旧执行器恢复。快照固定的是客户端的工具契约与执行绑定，不能冻结外部服务本身。未新增补偿、回滚、治理审批或自动重放机制。
