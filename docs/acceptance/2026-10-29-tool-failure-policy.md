# 工具失败的自动兜底与固定 Skill 边界

## 行为

- 普通、已知只读的 MCP 数据源权限拒绝或请求被拒，在来源允许时直接于原任务内调用 `web_search`，不为权限兜底额外申请重规划或弹出确认。原接口失败回执与搜索回执同时保留，搜索结果明确标记替代来源。
- `40203` 仍保留为提供方请求被拒，不通过错误文案正则推断权限，也不据此永久禁用接口。只读数据源可在本轮尝试公开来源。
- 用户限定原始来源时不自动搜索；显式来源确认约束继续按原确认路径处理。工具权限、审批、目录与共享搜索预算继续生效。
- 固定 Skill 明确绑定的工具默认不能替换。参数错误允许原步骤、原工具修正后重试一次，重试输入包含原参数与实际错误；未改变参数不重发。新调用使用独立身份并重新经过原执行与审批门禁。
- 只有 Skill summary 显式允许该步骤使用 `web_search`，且编译快照保存了逐字原文依据，才允许失败后在该步骤内搜索兜底。旧快照默认无搜索许可、未重试。
- 搜索成功不代表 Skill 自动完成：步骤验收核对绑定的原失败调用与实际搜索成功回执，继续检查原必需字段及完成条件。搜索失败或验收未通过，按 Skill 未完成处理。
- 固定 Skill 任务失败后禁止申请重规划，不能换名重建普通任务以绕开契约。独立就绪任务仍先正常执行。

## 验证范围

新增回归覆盖普通自动兜底、两种提供方拒绝码、来源/权限/预算门禁、与普通搜索共用预算、固定 Skill 禁止兜底和重规划、参数错误上下文及单次修复、显式搜索许可、恢复后的搜索回执复用、必需字段验收以及编译原文校验。

集成回归使用真实 Graph、Gateway、checkpoint 与独立数据库回执，验证已知只读数据源在不限来源时自动搜索、不产生恢复 interrupt，同时保持原拒绝回执结算；显式来源确认场景保留原确认流程。

独立评审发现并修复了重试提示遗漏原错误及兜底使用不同预算桶两项问题，两者均补充了先失败、修复后通过的回归用例。相关十四个单元/集成测试文件回归及 Ruff、差异空白检查用于验收。
