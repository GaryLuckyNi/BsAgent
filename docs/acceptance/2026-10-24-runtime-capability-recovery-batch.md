# 权限恢复批次与确认协议：第二检查点

日期：2026-10-24。分支：`codex/runtime-capability-recovery`。本记录只说明受控测试，不代表生产启用或真实账号权限验收。

## 已实现边界

1. 派发前固定任务成员及计划/观察摘要，worker 按稳定引用合并结果；Scheduler 等全部成员已有结果或恢复事项后封存，不扫描部分失败提前确认。
2. 同批拒绝合并为一个不可变授权批次，最多12项，完整显示目标、原工具、拒绝原因和来源限制。后来任务形成新批次，不继承旧确认。
3. 新协议为 `permission-recovery-batch-v1`。客户端必须回传 `presentation_version` 与 `batch_digest`；未知版本、残缺清单和重复条目不能按普通选择提交。刷新后的事件重放保留清单与摘要。
4. Session API 在 Graph 恢复前验证服务端会话归属、当前 Interrupt、完整展示视图、目录摘要及当前权限；调用之后仍保留归属一致性检查。空 scopes 表示撤权，不回退旧快照。
5. Gate 仅校验并持久化决定，不执行外部工具。独立 `permission_recovery` 节点复查任务、原回执、候选/版本/binding、来源约束与决定后，通过原 Gateway 搜索。没有生产 ExecutionControl 时拒绝，不静默采用内存授权。
6. 搜索请求身份绑定批次、原调用与策略，不调用模型重新选工具或生成查询，不重放原 MCP。研究时点使用初始快照；原参数与远端错误正文不进入搜索。
7. 新模式的普通搜索及恢复搜索均接入独立回执预留，共享每 Run 六次的预算。稳定顺序消费剩余名额；一项失败、预算不足或已有未决搜索，不阻止其他已批准事项，也不递归弹窗。
8. 同批中风险调用被本地 running 保护拦住时，仅对没有远端回执、原参数仍一致的本地等待做一次继续派发。拒绝回执先结算；真实 running/unknown 仍阻止执行，不整体关闭副作用保护。

原任务身份和验收条件保持不变。结果观察保留来源限制、原/替代调用引用、覆盖信息；完整答案位于 canonical ToolCallRecord，不额外生成带完整结果的恢复 artifact。超长 JSON 转义导致观察超过8000字符时，改用授权契约摘要引用，不截断授权快照。

## 受控验证范围

联合测试使用真实 StateGraph/InMemorySaver、Gateway、SQLite 独立回执和明确的来源契约替身；模型和工具都是本地替身。

| 场景 | 受控断言 |
| --- | --- |
| 两项拒绝＋健康分支 | 一个 interrupt、完整两项，确认前搜索0次；确认后原 MCP/选择模型计数不变，健康结果保留 |
| 同批中风险本地等待 | 拒绝结算后健康调用继续，均 settled；没有伪造 unknown，没有关闭 running/unknown 检查 |
| 已有真实 unknown | 原回执状态及正文不变，远端调用0次，明确保留缺口 |
| 结果落盘后节点失败 | 通过 Graph 重试消费独立回执，原 MCP/搜索都不重发 |
| 选择重复/反选 | 相同决定幂等，反选409，不能重开授权 |
| 任务/清单/候选/账号/来源/binding摘要变化、撤权 | 外部搜索0次，明确409 |
| 前五次搜索已占预算 | 批次按稳定顺序只派发剩余一次，另一项保留预算缺口 |
| 一个搜索仍 running 或返回失败 | 不重发未决调用，继续剩余事项，不递归确认 |
| 后续新任务 | 新 interaction/batch，旧确认不能提前触发新搜索 |
| 初始研究时点与恢复日期不同 | 搜索上下文仍使用原 as_of 和原验收条件 |
| 来源约束不明/禁止、固定 Skill | 不因目录或候选有搜索就推导来源等价 |
| 普通实体选择 | 沿用原协议，无新增必填展示字段 |
