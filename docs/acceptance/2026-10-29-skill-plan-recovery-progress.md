# Skill 计划展示与重规划进展覆盖

## 展示边界

首次 Planner 和反馈重规划共用 Skill 任务展示约束：`task_goal` 只说明“使用某 Skill 完成某业务目标”，保留必要主体与期间。不复制 Skill 正文，不展开内部工具调用、参数字段、清洗规则和输出模板。实际执行仍以 Skill 自身契约为准，业务验收条件不因展示简化而删除。不增加摘要模型调用，也不截断任务文字。

## 失败与补偿状态

此前节点执行完且任务失败时，公开事件立即设为 `failed`。重规划生成不同任务 ID，前端只追加新活动，旧失败条目和感叹号一直保留。

本次使用以下公开活动状态：

- `pending`：Skill 或 Tool 当前路径失败，后续处理尚未确定；显示“正在评估后续方案”和中性等待图标。
- `superseded`：Planner 已接受新计划，旧失败任务被新计划替代。使用旧活动 ID 原位更新为“已调整研究流程，按新研究计划继续”，图标改为流程图标，不声称原任务执行成功。
- `failed`：合成层已产生最终答复且没有待处理重规划时，当前计划仍未完成的任务才显示告警。补偿后的新任务若再次失败，也会正常显示最终告警。

单次 Planner 或合成节点异常仍可能由 LangGraph 外层重试，因此不能据该节点的 `failed` 事件提前结清活动。整次图执行最终抛错时，流式 API 才统一把尚未处理的 `pending` 活动结为 `failed`，补发同 ID 事件，并与助手失败状态同事务保存研究过程；`superseded` 不改回失败。可重试的用户输入恢复异常保留原中断状态，同时保存已更新的研究过程。

被替代 Skill 内的失败工具步骤同步更新，避免旧子步骤一直停在等待状态。新计划无效、未接受或最终停止补偿时，不会伪造 `superseded`。成功活动保持不变，原任务的执行结果和失败审计保持不变。

这次只更新公开状态投影，未扩大重试次数或重规划预算。新状态随 SSE、持久化研究过程和历史恢复链路保留，更新沿用原顺序。已经保存且没有这些新事件的旧会话不会据文案猜测补偿结果。
