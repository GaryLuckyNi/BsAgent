# 数据推演变量角色规划验收

## 当前结论

按用户建议实现了通用的“待求量、公式、必要输入、输入补证、直接结果核对”规则，作为候选保留在工作区；真实模型仍未稳定遵守，不能宣称原问题修复完成。原问题最终三次中一条路径符合要求，两条失败。没有提交、推送或部署。

## 候选改动

- Router 保留用户要求的计算、反推与核验，不把它改成查询或求另一个量。区分给定条件、推演输入与直接核对结果，后两者不能作为可互换的替代条件。
- Planner 在候选选择之前按定义确定待求量、公式或关系、必要自变量和适用条件，复用已知量，只为缺失输入取证。
- 首次规划与反馈共用规则。通过既有 `public_summary` 简述公式与取数方向；既有 `task_goal/completion_criteria` 说明所取数据是输入还是核对值，不新增 schema 字段。
- 对允许真实数据取证的推演问题，取得或复用直接披露的待求值作核对；不拿它反算缺失输入后再冒充原方向推演。同源一致只能支持口径/算术核对，不能称作独立来源证实。
- 复用既有颗粒度、Skill、依赖和简单计算交接规则：同调用能取得的输入和核对值合并，不固定两个任务或两次工具调用；用户限定只查某项、纯假设计算、资料已充分时不额外核验。

所有规则不含特定公司、年份、增长区间或某个财务公式。模型、thinking 和调用预算不变，没有新增审核模型。本阶段 Planner 文件包含新候选变更，早期证据覆盖报告中“Planner 未改动”仅描述当时阶段。

## 对照结果

修改前，原问题三次都把历史待求值当作主要取证；其中一条把获取本期绝对金额降为历史值缺失时的替代路径，未形成完整推演输入取证。

随后分别测试：系统提示加入变量角色规则；在验收条件提示中要求输出公式与用途；在既有摘要中先简述公式与方向再生成任务。中间失败响应均保留，没有通过改写原始问题或放宽判定获得通过。

最终完整复核为 8 项满足本次有限检查、3 项失败：

| 场景 | 结果 | 依据 |
|---|---|---|
| 原问题第1次 | 失败 | 公式和角色正确，但同一任务要求本期预告与历史数据，仅绑定历史候选，能力不足以覆盖任务 |
| 原问题第2次 | 失败 | 写出反推公式后仍将待求量当作输入、必要输入当作核对值，方向矛盾 |
| 原问题第3次 | 有限通过 | 本期预告金额用于反推，历史金额仅核对；历史候选不用于预告取证 |
| 年化净值反推 | 失败 | 角色分开，但未检查收益率和单位净值的分红/复权口径是否一致，公式适用条件不足 |
| 市盈率正向、股价反推 | 有限通过 | 输入与直接核对值分开，公式方向正确 |
| 纯条件、可解性、复用输入、充分材料、普通查询 | 有限通过 | 未因新规则追加无关取数或额外推演任务 |

自动粗筛的关键词命中不能识别公式变量倒置、候选仅覆盖部分目标或公式适用条件不足，因此最终以完整响应复核为准。
