# TuShare 只读调用与失败回执修复

## 问题与边界

此前副作用门禁用 `risk_level=medium/high` 近似判断可能写入。历史 TuShare 查询返回无效响应后留下 `unknown` 回执，随后同一会话的查询也会被 `tool_side_effects_unresolved` 拦截。

本次将受信读写语义独立为 `ToolSpec.effect_type`（`read_only` / `write` / `unknown`）。Admin 的 TuShare 数据查询连接声明 `read_only`，保留原有风险等级。声明来自宿主连接配置，不读取模型参数、接口名称或远端返回；策略进入冻结工具契约和执行绑定摘要。

按用户进一步明确的边界，`tool_side_effects_unresolved` **只用于宿主明确声明 `effect_type=write` 的已知业务接口**，且只读取同样具有可信写入声明的历史回执。`unknown` 工具和旧回执不能仅因 `medium/high` 风险等级被推定为业务写入。

## 行为

- 受信只读调用不被历史未决副作用回执阻塞。权限拒绝、超时、异常、无效返回、取消及死亡生产者恢复均不产生新的写入阻塞。
- 回执保留失败结果；`settled` 表示无需核对写入副作用，不代表查询成功。超时查询仍可保留 `execution_state=uncertain`，不伪造返回数据。
- 回执中的 `_effect_type` 只由调用预留时写入，工具返回不能覆盖。历史未知回执不删除、不批量改为成功；其中明确属于业务写入的未决回执继续保护业务写操作。
- 明确写工具仍受未决副作用门禁约束，即使风险等级为 `low`。未知工具的失败可记录结果不确定性，但不能据此拦截后续工具调用。

## 错误码

移除按权限、限流、额度和参数错误中文文案匹配的正则。适配器读取 `code`、`errorcode`、`error_code` 及 MCP 结构化错误；兼容现有 TuShare MCP 固定错误前缀时只提取数值码，不分析后面的文案。

[TuShare 官方 HTTP 文档](https://tushare.pro/document/1?doc_id=130) 明确 `2002` 表示权限问题。受信 TuShare 协议据此返回 `provider_permission_denied`、`execution_state=not_started`，回执结清。

项目保存的实际回包中，`40203` 同时用于无权限和频率超限。因此它归为 `provider_request_rejected`，保留 `provider_code=40203`，不猜测具体子类，也不写入永久无权限判断。未知或无错误码文案不再被自动解释成权限拒绝；部分结果不据此推断未执行。

## 幂等机制的实际覆盖

会话入口 `Idempotency-Key` 去重同一轮请求；成功工具调用回执可阻止同一可信 `call_id` 被再次执行；搜索另有持久化调用预留和结果复用。

任意外部 MCP 执行当前会生成新的适配器调用 ID，没有统一把业务幂等键传到远端，也没有远端去重及结果查询保证。这些本地机制不能证明响应丢失时远端没有写入。对已知业务写接口可保留 `tool_side_effects_unresolved`；不会因此把该门禁扩大到 TuShare 或其他未声明业务写入的工具。若某个写接口具有端到端幂等保证，后续可按该接口契约设计安全重试；本次不增加该能力。
