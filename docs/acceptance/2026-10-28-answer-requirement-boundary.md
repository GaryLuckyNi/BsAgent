# 回答要求边界与耗时展示验收

## 实际修复

研究进展标题重新使用既有 Reasoning.duration 显示秒数，不开启 thinking；历史没有 duration 的消息不编造时间。

根据用户进一步明确的边界，agent 根据问题和业务契约主动识别所需证据，不要求用户列出字段。固定 Skill 按既有冻结条件与 missing_policy 执行；开放式研判允许综合已有可靠信息，未采用的辅助指标不必逐项报告缺失。必要计算输入继续获取，来源限制仍生效。planner 不再要求说明每个非关键缺口，unresolved_questions 只记录仍影响核心结论或业务契约的事项。

合成和重规划共用同一要求来源：用户原问及真实上下文。保留 goal、计划、任务条件、材料、执行观察供判断；普通 completion_criteria 没有新增确定性硬验收或词语过滤。所有合成流程均提供 user_message，兼容旧流程工作目标比原问更宽的情况。关键缺口须具体影响核心判断或使业务契约无法满足，不以用户是否明确点名某项数据为前提。

替代路径结束和通用停止文案不再直接宣告用户事实缺失。无模型、空响应、协议修复失败和数值冲突的既有兜底不再把内部限制清单逐项列成业务缺口，只展示已有可核验材料，并明确尚未形成完整答复；数值校验继续拒绝冲突数字，未声称部分材料已完成请求。

## 真实 trace

用户提供 df0dff78b8193725361d5ea122c8f8ba，原问为“今天创业板指涨了3个多点，你认为这次是反转还是反弹”。router 将北向资金纳入参考维度，planner 要求未取得时标注；实际搜索 query 包含北向资金，但返回材料未提供该数值。合成输入包含 29 个来源，data_limitations 为空，三个任务状态均 success。原答案正文和第六条风险提示提及北向缺失，是模型自身的表达选择，不是程序附加的缺口清单。

北向资金可以是合理的研判维度；未搜到它不自动证明开放式研判无法进行。问题边界是证据能否支持判断、任务有无固定数据契约，不是用户是否逐项点名数据。

第一轮真实模型回放使用完全相同的 user_prompt，只替换合成提示，模型仍在正文和后续建议中提到北向未取得，未将其计为修复通过。原结果保存在忽略目录的 replay-first.json。后续根据用户明确的任务契约边界重新验证。回放脚本曾漏带来源引用提示，相关结果不作为最终验收；现已修正投影输入并断言引用提示存在，最终系统提示保存并校验 SHA-256。

## 最终回放与定向回归

- 开放式原问题：user_prompt 与原 trace 字节一致，保留 29 个来源、扩展 goal 和原计划，只替换合成提示。现用 deepseek-flash、thinking=false，9.362 秒返回有依据的倾向性判断，未再附加“北向数据缺失/待补”的说明。后续观察中仍提及北向，不把出现该词本身当失败。
- 必要输入对照：改问外资交易净贡献比例，模型指出缺少分子，未用主力资金数据冒充外资净额，也未编造比例，4.131 秒。这个对照验证按任务所需信息判断，不要求用户逐项列明输入字段。
- 最后提示收口后，定向 191 项测试通过（6.59 秒），覆盖意图、规划、合成、请求级修订、固定 Skill 与动态图。固定 Skill 按原有冻结条件与 missing_policy 处理，没有增加每项缺失都向用户提问的逻辑。
- 摘要记录在 2026-10-28-answer-requirement-replay.json；原始 trace 和模型答复保留在忽略的 investigations 目录，不复制到正式文档。

## 效果边界

mock 测试验证原问/材料进入模型、调用次数及 thinking 设置，不能证明模型必然理解正确。回放固定既有材料，不重新检索，不验证原材料中的市场事实真伪，不将单例输出改善等同于所有场景稳定改善。固定 Skill 验收代码与交互策略未被放宽；本次没有新增通用自动澄清能力。
