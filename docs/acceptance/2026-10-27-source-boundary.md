# 工具执行与证据验收分工验收

## 原因

Trace `84a94795ae293d938653ce8f91f1ee7f` 中，调度器实际派发四个独立任务，执行模型均选中 web_search。三个任务被 Planner 标为 original_data，普通执行门禁因此返回 source_switch_not_authorized；仅 public_information 新闻任务真正搜索。不是调度器漏发任务。

## 改动

- 删除普通搜索对任务数据标签的限制，以及对同一 run 历史 MCP 失败的扫描。原失败和未决回执保持原样，不重放原调用。
- 普通搜索只保留请求中 original_only、confirmation_required 的明确来源要求；工具可用性、参数、权限、预算、副作用和审批仍走现有执行链路。
- 恢复询问不再要求某种 source_requirement。部署契约、固定 Skill、原候选、封存批次、回执和确认校验继续保留；来源 basis 审计字段保持原格式，兼容既有有效中断。
- Planner 对 source_requirement 的说明收缩为证据需求描述。保留 Router 来源约束传递；合成层继续根据 goal、完整计划、实际结果和来源判断信息是否充分，不新增验收节点或模型调用。

## 证据

新增 Graph 回归使用真实调度器、Tool Agent、Gateway 与合成节点，仅在提供方边界替代模型输出和搜索响应。目录中只有 web_search，四任务含三个 original_data 和一个 public_information。旧实现只有一次调用，修复后四次调用成功；合成模型输入包含原计划、任务完成条件及四份实际结果。此测试验证执行路径，未重新提交用户原请求或声称已查得真实市场数据。

先运行新回归：10 项失败、52 项通过，失败涵盖原始数据标签、既往 MCP 拒绝/不确定结果误拦、unclear 标签恢复资格，以及明确确认要求未拦截的边界。最小修改后，针对测试 62 项通过。额外测试确认搜索仍需 web:search 权限，用户明确限制仍阻止普通搜索。

完整后端测试：2118 项通过、53 项跳过，耗时 194.90 秒。跳过项未计入通过；存在既有 pytest 插件导入和测试用 HMAC 短密钥两条警告。改动文件 Ruff 与 git diff --check 通过。独立只读审查复跑 62 项通过，未发现重要问题。

## 限制

工具调用成功仍只代表取得了实际返回内容，不能保证所有字段、期间或原始序列完整；证据是否足够回答 goal 继续由现有合成模型判断。来源要求的自然语言识别仍依赖 Router，本次没有增加新的来源授权系统。
