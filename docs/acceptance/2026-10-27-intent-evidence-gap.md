# Intent Router 目标与缺口通用化验收

## 当前结论

已移除会把问题引向特定财务查数解法的示例，将目标理解和缺口表达改为通用规则。变更作为候选保留在工作区，未提交、推送或部署。原始省略问法仍未稳定安排主要取证，修复质量验收未通过。

## 修改内容

- goal 保留用户要确认的结果、对象与关系，不提前决定算法、字段或取证路径；主体、时间或版本、所问关系和限制都应保留。
- 区分目标实际采用的依据与相关历史事实，避免用孤立的历史值替代目标声明的比较依据。
- 明确 `available_information.missing_input` 是待确认缺口元信息，与已有事实分开；继续使用自由 JSON，不新增顶层 schema。
- 缺口涉及目标实际采用的值、参照或条件时，goal 也应保留该待确认关系。不能只在缺口旁注中提及。
- 条件计算、仅问公式、材料充分和来源限制继续沿用原路由边界。Router 不选工具、不拆任务，也不提前完成研判。

没有增加公司、年份、数值、增长公式或具体工具分支；Planner、合成层和执行门禁均未因本次修改而改动。保留了既有角色标识，避免无关改变测试替身的分派。

## 固定输入对照

[完整输入与响应](2026-10-27-intent-evidence-gap.json) 包含旧提示、两轮中间版本和最终候选。12 个场景、每轮 14 个样本，原问题重复三次。使用生产 HybridIntentRouter 的结果驱动生产 LlmTaskPlanner，并通过 request_context 构建已有信息；原始问题、上下文和候选保持一致，运行时日期随调用时间更新。

taxonomy 与工具卡是明确标注的受控模拟。没有实际搜索、MCP、业务 Run 或合成调用，不能声称精确重放原 Trace 或修复完整业务链路。

旧提示下原问题三次均只安排历史金额查询；已有历史实绩的场景还出现了直接回答，虽然未取得目标预告。候选提示在后者改为 plan 并安排目标预告取证；显式询问预告比较基数、费率套餐、基金月报的目标关系和缺口表述也更完整。

最终候选完整复核：10 项满足本次有限检查，原问题三次失败，1 项因 Planner 超时未完成。

- 原问题前两次：missing_input 部分提及目标金额或公告，但 Planner 仍仅查历史金额。
- 原问题第三次：任务文字包含公告与历史核对，却只绑定不提供公告正文的历史财务工具，并给出历史查询草案。一次调用不能取得所需公告，所以仍失败。
- 不同公司期间场景的缺口使用“该预告”回指 goal 明确的目标年份，未重复年份；该项正则粗筛失败但语义复核通过。
- 已有历史实绩场景的 goal 没有公告关键词，但缺口与计划明确保留目标公告取证；同样不能仅按关键词判失败。
- 券商套餐的 Router 输出正确保留目标关系，Planner 调用约 61.5 秒后超时，按未完成记录，未算通过。现有记录器仅保存已返回调用的输入与输出，超时调用只有错误码。

纯给定条件、仅问公式/可解性、已有直接证据、给定每股收益复用、来源确认与范围外请求的本轮有限检查未退化。这里的通过只验证 Router 与计划，不验证实际资料可得、授权执行或答案正确性。

## 后续边界

不能宣称“missing_input 已经写到目标资料，Planner 就一定会执行”。本次仍观察到缺口被忽略和任务目标超出候选范围。也不能把这些未完成问题重新归为纯合成层故障。

根据用户指出的提示过度收窄问题，本次保留通用目标/缺口职责的候选改动供检查，但不继续叠加针对原句的规则。后续需要重新审视目标理解与计划覆盖如何保持一致，且应保留纯条件分析与已充分材料的边界。
