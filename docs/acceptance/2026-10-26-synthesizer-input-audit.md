# 合成层实际输入与完成判断

## 调用边界

`build_synthesizer_node` 从状态中选择本轮计划结果及允许复用的历史成功结果，`_render_answer` 再构造模型输入。合成模型不会直接读取整个 `AgentState`，也不会直接接收全部 `messages`、原始 `tool_calls` 或未筛选的 `task_results`。

此前没有逐字段判定 goal 完成的确定性规则。模型读取以下字段作语义判断；程序负责状态及输出协议验证、重规划预算与引用校验，以及少数既有数值契约检查。二者不能混称为同一个“校验”。

## 模型可接收的字段

| 字段 | 进入条件与来源 | 对完成判断的作用 |
| --- | --- | --- |
| `goal` | 总是提供；`intent.goal`，缺失时退回原始用户消息 | 本轮要回答的问题 |
| `research_materials` | 总是提供；筛选后的成功结果按任务目标组织，经过数值与搜索来源投影 | 读取实际正文、分析和引用，不用 success 代替充分性 |
| `data_limitations` | 总是提供；未解决问题、失败或未完成任务、部分停止原因 | 待结合当前证据判断的限制提示，不是完成与否的最终判决 |
| `user_message` | 新请求流程提供；分析交接时也可提供 | 用户原始范围、条件及限制 |
| `request_context` | 新请求流程提供 | `available_information` 是入口摘要；`materials` 是有界历史、压缩摘要和附件材料。区分用户条件、历史助手陈述和核实事实 |
| `current_plan` | 新请求流程提供；当前计划 | 理解任务意图、依赖及验收说明，不自行扩展最终目标 |
| `task_statuses` | 新请求流程提供；本次筛选结果的状态与错误码 | 执行状态，不等于内容已能回答问题 |
| `historical_execution_limits` | 新请求流程提供；未进入当前材料的历史失败任务 | 结合后续成功证据评估，不重复宣称已补齐的事实仍缺失 |
| `recovery` | 新请求流程提供；恢复结果摘要及待确认标记 | 恢复过程，不是业务事实 |
| `allow_replan` | 新请求流程提供；现有预算和在途执行门禁计算结果 | 是否允许提出重规划，不代表 goal 是否完成 |
| `replan_stop_reason` | 新请求流程提供；状态中的停止原因 | 动作限制，不可当成完成证明 |
| `required_schema` | 新请求流程提供；现有回答或重规划输出协议 | 输出格式，不判断业务事实 |
| `research_assessment` | 有 Planner 阶段判断时提供 | 阶段意见，不是新增证据 |
| `evidence` | 有证据条目时提供；正文、标题、来源 URI 和证据编号 | 可用于支持结论的证据内容 |
| `sources` | 来源投影生成了集中表时提供 | 按 `source_ids` 关联读取摘要、URL 等实际内容，不能只看研究材料中的引用编号 |
| `presentation_preferences` | 有可用语言或详略偏好时提供 | 表达要求，不是新的研究条件 |
| `user_materials` | 显式分析交接且有可访问材料时提供 | 补充用户历史或附件材料，不提升历史助手自述为核实事实 |
| `answer_requirements` | 显式分析交接时提供；该分析任务目标及 `completion_criteria` | 最终分析的交接说明，服务于顶层 goal |
| `format_repair` | 第一次模型输出不符合协议时追加到修复调用 | 原有一次格式修复，不是新的语义目标 |

## 原始 trace 的输入情况

`e83409879af22e552fe0a2f8c5ac6d56` 的续跑合成输入含 13 个顶层字段。事实金额在 `sources` 的公告摘要里，`research_materials.content.search_result` 保留的是 `source_ids`。同时，`request_context.available_information.missing_input` 仍描述入口时尚未取得的金额；结果正文还保留原接口缺失、来源恢复及 `coverage=unknown` 的说明。

因此，必须关联读取事实来源，并用后续材料重新判断入口缺口、阶段判断和历史执行提示是否仍影响 goal，不能由某个字段独立决定完成状态。

## 本轮修改范围

只在原有合成提示中说明实际字段用途，并让同一次模型调用综合可用信息判断能否回答 goal。保留来源限制、既有回答与重规划协议、预算门禁和格式修复。不新增目标协议、完成条件字段、独立审核节点或案例公式。

修改前只有显式分析交接开启 thinking，其他合成调用关闭。隔离对照后，生产参数调整为 `thinking=new_flow or handoff is not None`：新请求流程的首次合成调用开启推理；旧流程且没有显式分析交接时仍关闭。该设置沿用现有提供方能力，不新增独立审核调用。

既有推理空响应降级和一次格式修复仍可触发后续调用，不能承诺所有请求只调用一次；也不能把模型语义验证与程序回归混为一谈。推理可能增加 token 和延时，验收记录须如实记录已测结果及未测边界。
