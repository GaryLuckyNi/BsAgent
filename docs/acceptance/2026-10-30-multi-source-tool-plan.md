# 多来源备用调用链验收

## 最终行为

本次采用用户确认的一次生成全部参数方案。检索按各数据源独立 Top-3；模型从中选择并排序，每个来源至多一个工具，可以不选某个来源。联网搜索放在末尾。按计划串行执行，成功后剪枝剩余候选；非参数失败直接用下一工具的已有参数，参数错误先修正原工具一次，再次失败才切换。

普通来源切换不消耗重规划模型调用，不新增 `retry_of_task_id` 或来源重规划预算。上一版未交付的按来源重规划实现已撤回。固定 Skill 仍使用原单调用路径及冻结契约；写操作和未知副作用不进入只读备用链。

## 实现与审计

- 分源检索和函数调用分别校验候选范围及来源唯一性；Top-3 属于候选池，不属于执行队列。
- 备用计划保存于任务级 `source_attempt_queues`，绑定请求、任务快照与目录快照；实际执行才写入 AI 工具调用消息和 ToolMessage，不发布未执行的备用调用。
- 每次尝试保存原回执、错误码、错误详情及调用 ID；参数修正产生新的可信调用 ID。正常图检查点恢复复用已保存的队列和位置，不重新生成参数。
- 来源切换和参数修正复用同一活动 ID，显示进行中；成功后覆盖为完成。参数和内部接口名不写入公共提示。
- 审批等待不执行其他备用来源。搜索保留共享预算；本地参数校验失败未派发的搜索不计入额度，修正后的有效请求继续通过网关。
- 工具成功沿用既有返回契约，不把 0、false 或空集合擅自改为接口失败；是否能回答问题仍由原验收判断。

## 验证结果

相关单元及集成测试 **501 项通过（15.06 秒）**，相关代码 Ruff 检查与 `git diff --check` 通过。

新增验证覆盖：

1. 各来源分别召回三个候选，模型每源至多一个，允许遗漏某个来源，搜索末位。
2. 首个来源成功后其他来源和搜索零调用；权限失败后下一来源直接执行，无新增模型调用。
3. 参数错误仅绑定原工具修正一次；原样参数不重发；二次失败切换来源。
4. 专业来源全部失败后执行已生成的搜索参数；全部失败保留真实错误且不重规划重放。
5. 序列化状态恢复不重新生成备用参数，快照过期不执行；失败进度原位更新。
6. 审批等待及批准后恢复保持同一调用身份；本地超长搜索词修正不会被误耗预算阻断。
7. 真实 Graph、BM25、Gateway 与独立 SQLite 回执下，来源 A 失败 → B 成功即停止，以及 A、B 失败 → 搜索，均只有一次调用参数生成、零次重规划；同源另一工具零调用。

模型、远端数据源和搜索均使用受控替身，未重新发起线上研究或声称已取得真实财报；此处验证编排、门控、状态与协议行为，不等于真实模型在任意问题下的选择质量验收。
