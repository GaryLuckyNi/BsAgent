# Planner 任务颗粒度提示词修订

日期：2026-10-26。分支：`codex/planner-tool-call`，基线：`8d487cee`。

## 只读定位

Trace `16cb5fb14f11b1ce8a01e82b4e0f9a79` 的问题为“螺纹钢主力合约当前价格和近月基差是多少？”。Planner 生成主力行情、近月行情两个任务，均引用 `mcp.tushare.fut_daily_adj`。实际两次调用均使用 `RB.SHF`、`20261019—20261026`，只有第一份参数指定了返回字段；两次均收到提供方 40203 权限拒绝。第一任务使用 Planner 草案，第二任务重新进行模型选择。

已有 prompt 仅笼统要求少量任务、同次取证合并，并未充分区分“不同指标”“不同数据对象”“同一调用的多个返回字段”及“同一候选是否能覆盖整个任务”。用户明确要求按拆分颗粒度修正 prompt。本次只修改 `graph/planning/planner.py` 中初始规划与反馈共用的说明，不增加计划合并、工具名去重或执行门禁。

## 修订规则

- 普通 tool 任务以一次必要且可执行的外部取证为单位；同一返回中的多字段、多验收点合在一个任务。
- 不通过拼接多个目标制造一个仍需多轮工具链的任务；不能只以 task 数量下降判定成功。
- 不同实体、期间、来源、输入/返回范围及真实依赖允许必要拆分。同一个工具不要求在整份计划中唯一。
- 候选须覆盖整个任务，不能仅因主题相近复制给每个子任务。主力/连续/复权数据不能直接冒充具体交割月、现货或实时成交。
- 计算指标先明确所需事实口径，不把手头可取得的数据替换成不同指标的输入。
- 这些规则仅适用于未绑定 Skill 的普通工具取证任务；Skill 和中间 analysis 保持原约定。

期货范围与基差例子的依据：[TuShare 主力复权日线接口说明](https://tushare.pro/document/2?doc_id=492)、[上期所期现套利资料](https://www.shfe.com.cn/upload/20171227/1514362733410.pdf)。本次未查询实际行情或计算投资结论。

## 隔离验证

使用已配置的真实 DeepSeek 模型、相同的 trace 规划输入及两个合成对照，仅生成计划，不调用 MCP/Search，也不重放 Run。输入、模型返回与 usage 见同目录 JSON 记录。

- 旧 prompt 复现两个任务同时引用主力行情候选。
- 首次修订把任务压为一个，但出现疑似将多次调用拼进任务的问题，未作为通过结果。
- 补入调用边界后的一次尝试不再复制候选，后续一次仍出现复制，因此继续补强候选适用范围，并保留提示词具有波动性的判断。
- 最终对照中，原问题仍有两个任务：主力任务引用主力行情候选，近月及现货任务留空引用，交给其任务能力检索；计划中包含现货这一必要输入。
- 同一股票的代码、名称、上市与退市日期合为一个任务；两个股票、单对象接口保持两个任务，且主体参数不同。

## 边界与评审

本次验证支持“规划颗粒度与候选分配改善”，不证明后续近月与现货组合任务能由一次工具调用完成，也不证明实时价格、复权口径或最终基差答复正确。未运行完整业务请求，不能声称原问题的全链路已经修复。后续应根据实际工具目录和真实执行结果继续观察。
