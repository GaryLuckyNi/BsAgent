# Synthesizer 与 Verifier

## Synthesizer 职责

Synthesizer 是一次 Run 的最终回答合成层。它不再根据固定 A 股模板拼接字段，而是把本轮 `goal`、当前 DAG 的 `TaskResult` 和可用 `EvidencePackage` 交给 LLM，生成符合问题的中文 Markdown。

当前运行图停用独立 `analysis_agent`，保留其实现代码与历史契约。Planner 只安排必要的外部取证、外部计算或匹配 Skill；基于已有证据的解释、比较、推演、归因和最终判断由 Synthesizer 在最终回答中完成，不先生成分析草稿再改写，也不把纯分析改成额外工具任务。

旧计划中的未执行分析任务不再调度，且不自动计为数据缺失；未取得的工具证据及真实依赖仍按原规则处理，必要时由合成层申请补证。固定 Skill 如包含未执行的无工具分析步骤，会明确返回不支持并停止该工作流，不能伪造完成。

LLM 必须：

- 直接回答用户的投研目标，不逐字段机械复述工具结果。
- 根据问题自己决定章节，不无条件输出“趋势、财务质量”等固定维度。
- 可按需在少数小节标题前使用少量 emoji 作为阅读锚点，不要求每个回答或每个标题都使用，不为 emoji 强行分节或密集装饰正文。
- 只使用子任务结果和证据中存在的事实，清晰区分事实、推断和数据缺口。
- 不补造数字、来源、实时信息或未执行的工具结果。
- 不冒充模型厂商，不给出确定性收益承诺或直接买卖指令。

最终正文交付业务结果、分析依据和确实影响结论的必要限制。内部的工具选型、参数设置、数据源切换、重试及补证路线，不以总结、后续建议或操作指南的形式展示给用户；材料或历史回答中已有的执行建议也不应照搬。合成层应理解结果字段的业务含义再表达，正常保留数据出处、统计口径、计算和分析依据。用户明确询问公开资料获取方法时，可回答该方法，但不展开内部调用方案。

需要继续补证时，合成层沿用 `request_replan` 内部协议，`required_changes` 仅描述待取得的业务信息、待核实命题或覆盖范围；Planner 决定工具和参数。无法继续时按可靠材料回答并说明影响结果的业务限制，不将取数工作转交用户，也不掩盖必要缺口或把部分结果冒充完整结果。本边界不改变既有重规划门控、预算、固定 Skill 契约或流式输出协议，不增加模型调用。

Planner 与 Synthesizer 都可通过 LangGraph `Runtime.store` 按需读取长期偏好。Planner 只使用规划类偏好，Synthesizer 只使用展示类偏好，不把完整用户画像注入所有节点。

## 按需核验

普通数据查询和基于数据的计算不默认要求第二来源或独立披露值。已接入来源实际返回的数据，在主体、期间、指标含义、单位和适用口径明确、必要输入齐备且没有相反证据时，可直接用于回答与推导。意图识别与 Planner 同步使用该规则，不再在普通推演目标里自动追加交叉验证任务。

以下情形需要保留核验：用户明确要求、固定 Skill 契约要求、影响核心结论的实际证据冲突，或用户给出的关键现实前提尚无可靠依据而实际判断依赖其真实性。最后一种情形应内部补证，不能以模型自认为训练过或记得该数据代替证据；取证无法完成时，只能基于给定条件作有限结论。用户明确设定的假设、模拟或仅按给定数字计算不强制外查，已有可靠依据的前提直接复用。

上游自行追加的辅助核验失败，不自动成为用户交付限制；结果已经足以回答时，不在正文、口径说明或脚注中复述未做的核验。正常说明所用来源、公式和口径，不宣称执行过实际未执行的核验。口径不明、空结果、缺少必要输入或错误主体仍需处理，接入协议及执行成功本身不代表任意返回内容必然正确。

## 文章引用

联网搜索来源由 `EvidenceProjection` 按 URL 去重，汇总到 `sources`。合成模型在事实依据后引用表中的 `source_id`，如 `（source_1、source_2）`；`AnswerCitations` 将这些编号转换为 Markdown 数字链接，前端可在新标签页打开对应文章。

流式发布单元与最终保存正文使用同一引用转换，不增加模型调用或 thinking。正文在完整句子或行结束后即可发布，无需等待整段或全文；未闭合的链接、行内代码和代码围栏继续缓冲。未知来源编号或非法链接不生成跳转地址。已知数值底稿在每次发布前进行累计校验，发现矛盾则停止发布后续正文，最终仍保留全文校验与可信底稿降级。既有历史回答不回写，新回答的链接随正文保存，重新打开仍可点击。引用只表示出处关联，不代表已读取全文或证据足够完成目标。

模型调用在尚未发布正文时仍可按既有规则重试；已发布正文后发生调用错误，不再透明重放整个合成节点，避免把不同尝试的回答拼接。该规则也覆盖格式修复调用失败。

## 失败回答

- Intent 超出投研范围：返回简洁的产品边界说明。
- 子任务有终止性失败：返回可解释的错误和数据边界，不把部分结果当作完整结论。
- 没有配置 LLM：返回有界的确定性降级文本，不伪造投研分析。

## Verifier 职责

Verifier 是最终产品安全闸门，不重新做投研分析。它检查：

- 答案是否为空。
- 投研回答是否包含完整免责声明。
- 是否出现确定性收益承诺或直接买卖指令。
- 执行失败和超出范围回答是否使用正确响应类型。

本闸门只输出稳定验证结果，避免在终稿之后再引入一次不可控的自由生成。
