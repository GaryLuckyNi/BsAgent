# Skill 固定工作流

## 配置原则

`summary` 是 Skill 的唯一工作流维护入口。管理员需要在其中按顺序写明：

- 每一步的目标；
- 需要调用的工具名称，优先使用完整名称；
- 参数如何引用用户问题和前序步骤结果；
- 必需返回字段或自然语言完成条件；
- 数据缺失时停止还是允许继续；
- 最终输出格式和事实约束。

示例：

```text
第 1 步：调用工具 `mcp.local.stock.resolve_company`，根据用户问题填写公司名称。必须返回字段 symbol、name；缺失则停止并说明原因。
第 2 步：调用工具 `mcp.local.stock.market_snapshot`，使用第 1 步的 symbol。必须返回字段 price；缺失则停止并说明原因。
第 3 步：比较实际结果并列出限制。
最后用中文表格输出，只能使用上述步骤的实际结果，不得补造数据。
```

管理端不再保存 `allowed_tools` 和 `evidence_contract`。旧数据库升级时，会先把内置 Skill 的旧字段转换成明确的 `summary`；自定义 Skill 会保留原 summary，并追加其中尚未声明的旧工具和必需字段。完成回填后再删除这两列。

## 执行路径

命中 Skill 后，`skill_agent` 先把 `summary` 编译成有序步骤并保存到 checkpoint。编译器只能引用 `summary` 原文，不能补充工具、结果字段、完成条件或输出要求。明确写出的工具会按名称从本次工具注册表中加载完整 schema；缺失、短名称重名或权限不足都会在生成工具参数前终止。

每个步骤只绑定一个指定工具，`tool_agent` 只接收该工具的 schema 并生成参数，不再做语义选工具。步骤执行成功后，`skill_step_check` 验收必需字段和完成条件。只有验收通过，调度器才会进入下一步。全部步骤完成后，`skill_agent` 根据冻结的 `summary` 和步骤实际结果整理父任务结果，外层 Planner 只看到一次完整的 Skill 结果。

## 审批和恢复

高风险工具仍经过统一 `approval_gate`。审批前，工具名、版本、参数和调用 ID 已经冻结在 checkpoint 中；批准后恢复同一个调用，不会重新选工具或重新生成参数。后续步骤如果也属于高风险，会在该步骤再次暂停审批。

拒绝审批会把父 Skill 标记为失败，并阻止所有后续步骤。恢复、重试或重复读取已完成的 checkpoint 时，调度器会复用已保存的步骤结果，不会重复执行已经成功的工具调用。

## 失败规则

- 工具不存在、名称不唯一、版本变化或权限不足：执行前失败；
- 工具执行失败：当前步骤和父 Skill 失败；
- 必需字段缺失或完成条件未满足：默认停止；
- 只有 `summary` 明确写出“允许继续”时，才记录限制并进入下一步；
- 审批被拒绝：父 Skill 失败，后续步骤不执行；
- 编译结果遗漏编号步骤或 summary 中明确声明的工具：编译失败。
