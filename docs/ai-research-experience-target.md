# AI Research 近期体验目标

## 目标

近期交付目标是让投研问答达到主流深度研究产品的交互完成度：用户提交问题后立即获得持续反馈，系统自主理解目标、选择证据能力并形成自然的中文分析，最终答案以 Markdown Token 流持续输出。

这里追求的是产品体验和研究质量，不是复刻任何厂商的私有思维链。产品端只展示面向用户的研究思路与工具活动，内部 Prompt、JSON 契约、任务 ID、错误码和节点 Trace 仅用于调试与观测。

## 体验契约

1. 提交后 500ms 内出现首个可见状态，不允许页面无反馈等待。
2. 思考区使用自然中文连续展示研究方向，不出现控制指令、内部字段、节点名或阶段任务表。
3. 检索、市场数据查询等耗时操作以简短活动提示展示；同一活动不得重复刷屏。
4. 最终答案必须使用原生 Token 流输出，而不是图结束后再模拟打字。
5. 最终回答以用户问题为中心，执行失败、权限不足和数据缺口只能作为必要的局限说明，不能成为报告主体。
6. 部分证据可用时必须完成有边界的分析；只有不存在任何可用研究材料时，才返回简洁的失败说明。
7. 最终答案不得包含任务 ID、工具名、Provider 配置、内部错误码、成功率或链路修复建议。
8. Markdown 标题、列表、表格、引用和行内代码应稳定增量渲染，不重复、不闪回、不截断。

## 验收指标

- 首次可见事件延迟（TTFE）P95 不高于 1 秒。
- 最终答案首 Token 延迟（TTFT）按问题类型分别统计，不用伪造进度掩盖真实延迟。
- 10 条代表性投研问题全部进入正确链路，完成率不低于 90%。
- 产品事件中内部字段泄漏率、重复消息率、答案重复渲染率均为 0。
- 单一外部数据源失败时，只要存在有效公开证据，回答仍以 `research_answer` 完成。

## 回归问题集

回归至少覆盖：单公司综合分析、公司对比、行业与板块判断、市场异动归因、财务概念解释、技术面、估值、公告事件、时效性新闻以及数据源部分不可用场景。
